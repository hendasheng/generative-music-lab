### ★ 文档说的「基地」与实测不一致

`README.md` / `INTEGRATION.md` 写「**0.3 是颗粒合成器的基地**，改动先在 0.3 做再搬出去」。**现实是 0.3 已经落后 0.3.1 一整轮**（见下表）。名义基地 ≠ 实际基线，动手前先确认你要改的是哪一个。

| 偏离项 | 0.3 | 0.3.1 / 0.3.2 |
| --- | --- | --- |
| 默认 `reverb` / `volume` | `.3` / `0`（干声 RMS −15.5 dBFS） | `.65` / `+6 dB`（RMS −7.9 dBFS） |
| `gainForLevel()` 抽取 | 无（`inputGain` 内联） | 有，素材与实时共用同一目标 |
| `levels()` 电平读数 | 无 | 有（返回值成员，不是导出面成员） |
| `setAudioSession()` | 无 | 有（iOS 会话类别；**导出面成员**） |
| 实时输入补偿 | 写死 `1` | 按环形缓冲电平标定（每 250ms，最多 ×4） |
| `recorder.columns()` 按位置分列 | 无（录中波形是 43ms 时间窗） | 有（画面上「波形与 pad 起点/终点对不上」的修复） |

★ 反向同步（0.3.1 → 0.3）**不能只覆盖 `engine.js`**：0.3 的 `app.js` 里**一处 `setAudioSession` 调用都没有**（0.3.1/0.3.2 各有 2–3 处），光把引擎搬过去，iOS 那条修复不会被调用；`recorder.columns()` 也要 0.3 的 `app.js` 绘制端配合。这条是产品决策（0.3 要不要跟上），不要顺手做。

## 2. 0.3.2 当前状态

- 主体：摄像头窗（`.sample-strip` 波形浮层贴底）+ XY pad + 四个常驻旋钮。
- 菜单里：导入音频 / 内置音源 / 种子 / 6 个滑杆 / 混响 / 输出音量。

- ★ **去掉实时输入的理由是产品判断，不是版式取舍：它在 iOS 上目前处理不好**（响度偏小未解决 + 只能靠真机 A/B 分诊，见第 5 节第 1 条；完整依据与「别越界」的两条边界写在 `README.md` 的「为什么去掉实时输入」一节）。**「录制采样」保留**，录音期的 `setAudioSession` 也保留——那条与实时输入无关，是 iOS 录音后不被压低所必需。
- 引擎第四个参数 `liveSource` 在 `app.js` 里恒不传（= `null`），走素材路径。

文件：`engine.js`、`flow.js`、`recorder.js`、`camera.js`、`mobile.js`、`app.js`、`style.css`、`index.html`。**没有** `live.js` / `live-worklet.js`。

## 4. 本轮修掉的探针 bug（★ 以后别再喂给下一个人）

`tools/engine-sync-check.cjs` 是「同步引擎后证明声音没变」的**唯一**凭据，但它在本轮之前**已经跑不过了**，而且没人发现：

1. **导出面清单过期**：`API_KEYS` 里还写着 `levels`、缺 `setAudioSession`。0.3.1 同步时新增了 `setAudioSession`、把 `levels` 收进 `create()` 返回值，清单没跟着改 → 第 5 段 `导出面与预期` 必失败。
2. **音频桩缺 `createAnalyser()`**：0.3.1 的引擎在 compressor 与 destination 之间插了 AnalyserNode，桩没有这个方法 → `create()` 直接 `TypeError`。

为什么两条都没被发现：脚本的**默认调用**用的是 `tools/engine-0.3.1-before.js`（同步前的快照），这个文件**不在仓库里**（`git log --all` 无记录），于是默认调用在文件开头就 `exit 1` 退出了 —— 而「找不到快照」看起来像环境问题，不像断言失败。

已修：`API_KEYS` 改为当前 13 项导出面；桩补 `createAnalyser()`（与 `check.cjs` 同款）。

### 快照文件仍然缺（需要你决定）

`engine-sync-check.cjs` 的默认调用要求 `tools/engine-0.3.1-before.js`（同步前的 0.3.1 引擎）。它不在了，所以默认调用**现在仍然失败**（报「找不到同步前的引擎快照」）。两条路：

- 只想「以后每次同步都能证没变」：放一份当前引擎做基线即可 —— 例如 `Copy-Item 0.3.1\engine.js tools\engine-0.3.1-before.js`，此后默认调用就等于在检查「引擎没有再漂」。**注意这是「重新定基线」，不是恢复 2026-09-26 那次同步前的原件。**
- 想复现历史那次同步的真实比对：从提交 `bc21254`（`feat(06/0.3): wire live microphone input…`）取出当时的 `0.3/engine.js`，那才是「同步前」的 0.3.1 版本身。

本轮**没有**擅自建这份快照或改默认参数（会改变这条检查的含义）。

## 5. 已知未解决 / 未验证（按优先级）

★ **以下第 1 条不是 0.3.2 的遗留问题**：它只存在于 0.3.1 的实时输入路径，而 0.3.2 已把那条路整体去掉，并在桌面与 iOS 真机上都验收通过。列在这里是因为「将来要不要接回实时输入」取决于它。

1. **iOS Safari 实时输入响度偏小 —— 仍未解决，且卡在缺真机数据。** 这**正是 0.3.2 去掉实时输入的原因**（见 `README.md`「为什么去掉实时输入」），代码仍在 0.3.1。已排除项与下一步在 `0.3.1/README.md`「未解决」一节；结论是**不要先凭猜提高所有平台的增益**（会破坏已正常的桌面端），需 iOS 上 `window.__iosAB` 的 A/B `rmsDb`/`peakDb`。本机无头测不到（假麦克风峰值 0.0000）。要把它接回 0.3.2，起点是这一段，不是版式；★ 但先掂量代价——0.3.2 现在是**两个平台都验收过的版本**，加回一条只有桌面正常的链路会把它重新变成「一半可用」。
2. **iOS 每次 `play()` 新建 AudioContext**，而参考实现整页共用一个并在首个用户手势同一调用栈里 `prime()`。这是比会话类别更大的差异，未改。若真机出现「第一次播放没声音、要再点一次」，多半是这条。★ **截至 2026-09-28 的真机验收没有出现这个症状**，所以它在 0.3.2 上未被证实；改动面大（要把上下文抬到共享层、改 `deactivate` 的所有权语义）且只有真机能确认收益，没有新症状就不要动。
3. **0.3 落后 0.3.1 一整轮**（第 1 节表），且文档口径还写着「0.3 是基地」。要不要反向同步是产品决策。
4. **代理侧仍未实际试听**（真机验收是用户做的，见 `README.md` 的「真机验收」）；`live-check` 量到的 −8.3 dBFS RMS 只能证明「不哑也不削顶」，不能替代听感。引用这条时不要把它写成本版的未验收项——本版已验收，缺的只是**代理自己的**听感判断。

## 6. 动手时的硬规矩（这几条会直接咬人）

- 中间元素居中**只能**靠 grid 的 `1fr auto 1fr`；flex 两端对齐要求左右等宽，任何单边 padding 都会顶偏（0.3.2 的录制键被 `.main-actions` 上遗留的 `padding-right:10px` 顶偏过 5px）。断言要量**可见元素**到容器中心的偏移。
- 新建版本目录后**核对 `index.html` 引用的每个脚本都在**（0.3.2 建版漏拷 `camera.js`，`mobile.js` 整段 `ReferenceError` 失效，而静态检查与当时的 `live-check` 都是绿的），并跑一次 `camera-layout-check`（它真建一次 `CameraPreview`）。
- 探针判定只从**末尾一处**出去：`process.exit(ok ? 0 : 1)` 会**覆盖** `process.exitCode`，散在各段的 `if (!x) process.exitCode = 1` 全是死代码。
- 改引擎导出面 → 同步改 `engine-sync-check.cjs` 的 `API_KEYS`；改引擎用到的 Web Audio 节点 → 同步改该脚本的桩（桩要跟着被测代码走，否则它先藏 bug 再假崩）。
- 引擎的 `setAudioSession` 判据必须是「**当前是否在用麦克风**」，不能在 `play()` 里硬写 `playback`（0.3.2 无实时输入，硬写是安全的；将来接回实时输入时这条会立刻变成 bug）。
- 启动真机探针按 `AGENTS.md` 的清单：`--headless=new --autoplay-policy=no-user-gesture-required --mute-audio`；URL 带 cache-buster；别再起第二个服务器占端口。
