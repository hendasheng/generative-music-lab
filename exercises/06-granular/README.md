# 06 · Granular

**独立编写的粒子采样器**：把一段音源切成很短的小片段（粒子），按参数与随机流不断重叠播放，做成持续流动的质感。用原生 Web Audio 手写，不使用 Tone.js。

讨论参照 [Granula](https://granula.serezok.com/)、[ZYA granular](https://www.zya.cc/granular) 和 [waa-granular](https://github.com/arekdurlik/waa-granular) 的机制，不复制其界面、代码或音频资产。

- **现状（本文件）**：怎么跑、当前版本、现行参数与设计决策、怎么验证。
- **演进与实测**：[`历史记录.md`](历史记录.md) —— 逐轮为什么这么改、实测数字、被否掉的方案。想查「当时发生了什么」看它。
- **跨项目接入**：[`INTEGRATION.md`](INTEGRATION.md) —— 带哪些文件、接口、所有权与卸载责任。要把它搬进别的项目时先读它。

## 运行

直接打开 `0.3.2/index.html`，无需构建、无需联网、无 CDN 依赖。麦克风与摄像头需要安全上下文：`localhost` 或 HTTPS。手机真机验收用仓库自带隧道：

```powershell
pwsh tools/serve-public.ps1     # 仓库根执行；打印 https://<随机>.trycloudflare.com
# 手机打开 <公网地址>/exercises/06-granular/0.3.2/index.html
```

## 当前（0.3.2）的操作面

- **顶栏**：自由流动最左、**随机音源**（骰子图标，自由流动右边）、录制居中、播放最右；菜单按钮**仅桌面可见**（`@media(max-width:759px)` 隐藏），菜单内容一项没删（导入音频 / 内置音源 / 种子 / 六个滑杆 / 混响 / 输出音量）。★ 播放键的图标是 `mobile.js` 在运行时塞进去的尖三角，`index.html` 里那个圆角三角**不是**最终形态 —— 要动顶栏图标先看 `mobile.js`。（图标成套问题见 `历史记录.md` 的「随机音源的图标」。）
- **主体**：摄像头窗（左下角浮层是波形，可拖取样位置）→ XY pad（上轴标签「聚焦」、下轴标签「散开」，**纵轴顺带映射倒放概率的功能仍在，只是标签不再写出来**，见下面「XY 与手动接管」；**轴标签与坐标线在拖动时更实、不拖动时更淡**，状态就是 pad 的 `.pressing` 类，颜色走 `--axis-ink / --cross-ink` 两组变量；控制点是无描边的实心圆点，**按住会放大——手指 2.5 倍（13px → 32.5px）/ 鼠标、笔 1.5 倍**，因为手指肚会盖住小圆点；放大跟手（0.08s），**松手是 0.45s 的慢回落**，两档过渡分别写在「按下」与「基础」两个状态上；拖动时控制点后面拖一条**连续的带子**（pad 里那块 `.xy-trail` canvas：**填多边形**而不是分段描边，头宽跟着控制点当前直径走、尾端收到 0，Catmull-Rom 插值保证曲线光滑，650ms 内按时间过期缩回控制点；层序 拖尾 3 / 控制点 4，都在 `z-index:2` 的轴标签之上）；→ 四个常驻旋钮（粒子长度 / 密度 / 立体声散布 / 音高；上下拖（按住 Shift 精细）、**双击回默认值**——Max/MSP、Ableton Live 的惯例，回的是 `Granular.defaults` 里那一项；双击也不会闪灰块：旋钮上那个 52×52 的隐形 range 已经关掉 iOS 的 tap highlight，`user-select:none` 负责不选中文字）。
- **录制采样 · 30s**：点击后先停合成器与自由流动，再请求麦克风；可提前停止、可取消授权；30 秒自动结束。录完**自动解码载入并起播**（`load()` 内部会先 `stop()`，所以必须等它 resolve 再 `play()`）。录音 <0.25 秒或失败时保留旧素材。
- **摄像头**：只请求视频，默认后置、前置镜像；未打开时窗内图标常驻，打开后点窗口可收起/展开（相机图标是关闭摄像头的唯一入口，不能出现「关不掉」）。仅本地预览，不录像、不上传、不调制声音。
- 隐藏页面 / pagehide：停止声音、取消录音、关闭摄像头。
- 抽掉的东西：实时输入（LIVE）、`window.__iosAB` 诊断（两者都在 0.3.1）。

## 内置音源库

`Granular.demo(ctx, index = 0)` 一号一段素材，`Granular.demoNames` 是名字表（当前 4 段）：

| 号 | 名字 | 时长 | 做法 |
| --- | --- | --- | --- |
| 0 | 谐波片段 | 8.0s | 首版那段：四音序列 + 三泛音，2 秒一换、`sin²` 包络（**不可改动**） |
| 1 | 钟形泛音 | 6.0s | 非谐分音 `1 / 2.76 / 5.4 / 8.93` × 指数衰减，四次敲击互相叠尾 |
| 2 | 拨弦余韵 | 6.0s | Karplus-Strong 延迟线，五音依次拨响 |
| 3 | 人声共振 | 8.0s | 脉冲列过三个共振峰（加性合成），带颤音、逐句换音高 |

（曾经还有第 2 号「噪声气流」，用户听完要求删掉 —— 白噪底在颗粒化后只剩「嘶声」，跟另外三段不是一个层次。）

规则：

- **0 号冻结**：它是首版的内置素材，循环体必须逐字节保持原样（`0.1` / `0.2` 不升级，仍只生成 0 号）。`tools/check.cjs` 会拿首版公式复算并逐样本比对。
- 每段只用种子随机流 `random('demo-N')`：同一号在任何机器、任何时刻都是同一段素材（不受调用顺序影响）。索引取模回绕，负数与小数都安全。
- 新音源都在**段尾淡出 0.3 秒**：它们的自然衰减到素材末尾还没归零，硬切会在最后一个粒子里变成「啪」。
- 生成在主线程上，一次 100–250ms（含换素材后 `play()` 重建引擎的固定开销），所以按钮的点击处理是异步的，期间 `#status` 是「正在读取音源…」。

**顶栏的随机音源按钮**（仅 0.3.2 有 UI，骰子图标）：点一次随机换到**另一段**内置素材（不会连点两次听到同一段），换完更新菜单里的采样名与 `aria-label`；**换完直接出声**（用户要求，换素材必然要 `stop()`→重建引擎，所以载入完成后统一 `play()`；若这次载入已被下一次点击顶掉则不抢着播，由新的那次负责）。**触发状态**分两层：按下去同一帧挂 `aria-busy`（图标点亮成主色，**最少 400ms**，实测换素材 + 重建引擎只要 ~75ms，不留时长等于没反馈）；换完之后转成 `aria-pressed="true"` **亮着**，表示「现在这段是随机选的**并且在响**」，素材被别的路径换掉（导入文件 / 麦克风录音 / 菜单里重新载入内置音源）**或停止播放**都会熄灭，再按播放会重新亮（素材还是那一段随机选的）。它跟自由流动一样是**一盏灯（状态）**，灯的条件 = `materialBuiltin && sourceRandom && (engine || starting)`，`stop()` / `play()` / `load()` 三处都调 `syncSourceMark()`。导入的文件或录音素材不影响「上一段是第几号」，所以录完再点仍然从内置库里挑。屏幕上不显示当前是哪一段（用户要求界面只留摄像头 / 波形 / pad / 参数），要看名字就打开菜单。

★ **图标成套靠截图对比，不靠 path 数据**：同一条 `stroke-width="2"` 在粗壮的 ∞ / 尖三角上和在 5 条细斜线的 shuffle 上读出来的重量完全不同（墨水覆盖 70% / 50% vs 18%），第一版 shuffle 因此被用户一眼否掉。现在用 `dice-5`（53%）。判断方法、四个候选的对比结论与「播放键图标由 `mobile.js` 运行期替换」这条坑，都在 `历史记录.md`。

## 现行参数

| 键 | 范围 | 默认 | 语义 |
| --- | --- | --- | --- |
| `position` | 0–1 | 0.35 | 取样中心（相对整段素材） |
| `spray` | 0–0.5 | `defaultSpray(duration)` | 位置散布；加载素材时按时长重设（8 秒 → ±250ms） |
| `reverse` | 0–1 | 0 | 每颗粒子的倒放概率 |
| `size` | 15–1000 | 180 | 粒子输出时长（ms） |
| `density` | 2–60 | 24 | 每秒粒子数（平均，实际带 ±10% 扰动） |
| `pan` | 0–1 | 0.8 | 随机声像**范围** ±pan，不是固定左右平衡 |
| `pitch` | −24–24 | 0 | 半音；播放倍率 `2 ** (pitch/12)` |
| `reverb` | 0–1 | 0.65 | 并行混响发送量（干声保持） |
| `volume` | −24–6 | 6 | dB，相对 +6dB 母带的输出增益 |

参数范围来自页面约束，`create` / `plan` 不做全面校验：宿主须自己拒绝 NaN/Infinity、非正密度、空素材，并按表钳制。**不要直接改全局 `defaults`**，复制它。

## 现行设计决策

### 主色调（橙色族）

只有一处定义：`0.3.2/style.css` 顶部注释块下面那一行的三个变量 ——

```css
:root{--accent:#ed5b2a;--accent-reverse:#f37944;--accent-soft:#ffd9c6}
```

| 变量 | 出厂值 | 管什么 |
| --- | --- | --- |
| `--accent` | `#ed5b2a` | 焦点描边、按下态图标（自由流动 / 播放）、XY 圆点、旋钮指针、**录音波形柱**、波形上 `REC / LIVE INPUT` 文字 |
| `--accent-reverse` | `#f37944` | 倒放粒子（比主橙浅一档） |
| `--accent-soft` | `#ffd9c6` | 录制中那条播放头（浅橙，画布上按 0.67 透明度画） |

（表里是出厂值；作者已经自己把 `--accent` 调成过红色 —— 这正说明只有一个来源是有效的。探针也不写死颜色：`live-check` 读 XY 圆点的计算色当基准，所以换任何颜色都照样能验。）

★ **画布（Canvas 2D）读不了 CSS 变量**，所以 `app.js` 启动时用 `getComputedStyle(document.documentElement).getPropertyValue('--accent')` 读一次，存成 `ACCENT / ACCENT_REVERSE / ACCENT_SOFT`（在 `app.js` 顶部，带兜底值）。**改颜色只改 CSS，不用动 JS**；改完刷新页面即可（读的是启动时的值，运行时改变量不会回溯，没有做主题切换就不需要）。

验证方式（一次性探针）：把 `style.css` 当场改写成 `--accent:#0f0; --accent-soft:#f0f; --accent-reverse:#00f` 再加载，实测 XY 圆点变成 `rgb(0,255,0)`、录音画面里 1400 个纯绿像素（波形柱 + 文字）与 208 个品红像素（播放头）、播放时有 150 个纯蓝像素（倒放粒子）；换回默认 CSS 后三个通道都是 0，圆点是 `rgb(237,91,42)`。

### XY 与手动接管

`position = x`，`spray = y × 0.5`，`reverse = (2 × spray) ** 2.5` —— **顶端纯正放、中点约 18% 倒放、底端纯倒放**。`Granular.fromXY()` / `toXY()` 只做这层映射与钳制，**覆盖规则在 `app.js` 的 `setXY`**：新旧 spray 差值 < `1e-8` 时丢掉映射出来的 reverse，保留手动设定；有纵向变化才重算。Reverse 滑块不移动 XY；单独调 spray 会移动 XY 但保留当前 reverse；拖波形只改 position。

★ **pad 的上下标签不写这层语义**（用户要求只留「聚焦」「散开」）：纵向仍然是「往上收拢、正放为主；往下散开、倒放为主」，只是不在界面上用文字说明。这层关系现在只在三处可见：菜单里的「倒放概率」读数、pad 的 `aria-label`（`位置 X% · 散布 ±Y% · 倒放 Z%`，读屏与无视觉操作者仍拿得到）、以及波形里倒放粒子用 `--accent-reverse` 换色。**别因为标签没写就把 `reverse` 映射删掉。**

**手动操作（XY / 波形 / 任意滑块，含音高）一律关闭整个自由流动**，按钮同步关闭，松手不自动恢复；键盘调整同样。`flow.step()` 不能走这个入口，否则流动会自己关掉。

### 自由流动

从开启瞬间的当前值出发，各参数用独立随机流（`seed + ':flow:' + key`）、各自的距离与周期，五次平滑曲线连接。**pitch 不参与流动**。

| 参数 | 每段周期 | 距离基数 |
| --- | --- | --- |
| position | 6–13 s | 0.28 |
| spray | 9–18 s | 0.11 |
| size | 7–15 s | 220 ms |
| density | 5–11 s | 15 /s，且按 `(锚点长度/当前长度目标)^0.45` 反向关联 |
| pan | 11–21 s | 0.30 |

reverse 跟随 spray 映射曲线；开启前若手动设过，用 4 秒平滑衰减掉偏差（起点连续）。宿主维护**唯一** 25 ms 定时器，用 `performance.now()` 差值、单步 ≤0.1 秒，卡顿不追赶积压。停止播放 / 导入素材 / 切后台都关闭流动并清定时器。

★ **开启流动会顺带开始播放**（用户要求「点自由流动就直接出声」）：`void play()` 写在 `toggleFlow()` 里而不是按钮的 `click` 里 —— pad 上按空格也走同一条路，两个入口必须一致。**关掉流动不停声**（只是停止参数游走），所以只有「开启」这一侧调用 `play()`。`play()` 自带 `engine / starting / loading / recorder.active` 守卫，重复点击不会叠引擎。

### 单一来源

XY、滑块、波形、音频引擎读的是**同一份 `params` 对象**；引擎持有它的引用，改它只影响之后计划的粒子（最多约 120 ms 调度延迟，不追溯已排事件）。视觉**不消耗**音乐随机流。

### 音频引擎

- 每 25 ms 预排未来 120 ms。遇到主线程长暂停**跳过过期时刻，不补发积压粒子**。
- 每颗粒子：`BufferSource → Hann 包络(Gain) → StereoPanner → bus`；时长以**输出秒数**计，源读取长度乘播放速率，取样区间钳在素材边界内；倒放用预先算好的反向副本。
- 峰值 `≈ .38 / √(density × length)` 按预计重叠量补偿；最多 192 个（待播放 + 活动）声部，`onended` 清节点。
- 三层：主粒子（含 15% 干声 +12 半音，峰值 ×0.8）、湿声八度层（混响 > 0 时 45% 概率，×1.25 长度、×0.4 峰值，**只送混响**）。湿声八度从**原始**粒子派生，不从已升八度的主声部再升（避免意外 +24 半音）。
- 素材输入补偿（两条路径共用目标）：整段统计 RMS/峰值，目标 RMS 0.16、峰值预算 0.85、**最多 4 倍**；RMS < 0.001 不提升，已响的素材不衰减。源 buffer 不改。
- 链路：`粒子 → bus → 输入补偿 → 干声 / (shimmer 低通 → convolver → 180Hz 高通 → 4.5kHz 低通) → master 淡入淡出 → output 音量 → compressor → analyser → destination`。三处滤波 Q 均 0.707；compressor 是**峰值缓和器，不是严格限幅器**。
- 停止：先取消调度、35 ms 淡出、约 50 ms 后清声部与事件，再断开全部节点并 `close()` 上下文。**`end()` 之后要重播必须重新 `create()`** —— 不是暂停/继续。
- 异步启动与导入各自带代次检查：迟到的引擎必须 `deactivate()` 后丢弃，不能 `schedule()`。

### iOS 音频会话

`Granular.setAudioSession(type)` 写 `navigator.audioSession.type`（特性检测，旧 Safari 静默跳过）。默认 `auto` 有两个坑：输出跟着静音开关走；**采集麦克风期间系统会把整个页面输出压低**（[WebKit #236219](https://bugs.webkit.org/show_bug.cgi?id=236219)），而且**离开麦克风不切回就会一直留在被压低的那一档**。

| 时机 | 类型 |
| --- | --- |
| 录音 `requesting` / `recording` | `play-and-record` |
| 其余（`play()` / `stop()` / 空闲） | `playback` |

★ 判据必须是「**当前是否在用麦克风**」。0.3.1 有实时输入，若在 `play()` 里硬写 `playback`，会把实时输入刚声明的 `play-and-record` 顶掉。0.3.2 无实时输入、硬写是安全的，但将来接回 LIVE 时这条立刻变成 bug。

### 摄像头

`CameraPreview.create(video, onState)` → `start/stop/toggle/flip` + `active`；异步请求用**代次隔离**，取消后的迟到流立即释放。只请求 `video`，`audio:false`。切镜头用精确 `facingMode`，缺另一侧镜头时给出可重试的提示。**不要把摄像头流当录音流。**

### 录制与波形同轴

`SampleRecorder.create({onState,onResult,onError})` → `start/finish/cancel/waveform/columns` + `active`；`LIMIT = 30` 秒。格式优先 Opus WebM/Ogg，再 MP4，否则浏览器默认；显式关闭三项语音处理。模块自管定时器与 `MediaStreamTrack`，结束或取消都释放；分析用独立 AudioContext，**不接 destination**，结束即关闭。

★ **录制中的波形必须与解码后的采样波形同构**：按**位置**分 1000 列、随录制从左向右累积（`columns()` → `{mins, maxs, have}`，一列一个 25 ms 桶）。pad 的「起点 / 终点」指采样位置，而 analyser 的 43 ms 滚动窗是**时间轴** —— 早期版本画后者，所以播放头永远对不上。

### 引擎的单一来源（改引擎前必读）

**0.3 是颗粒合成器的基地**：引擎调整一律先在 0.3 做并测试，稳定后再搬到消费它的版本；不要反过来，也不要在别的版本里另写一套合成器逻辑。

★ 但**实测 0.3 目前落后 0.3.1 一整轮**（默认 reverb/volume、`setAudioSession`、`levels()`、实时输入补偿、`recorder.columns()`），所以「名义基地 ≠ 实际基线」。两版之间 `engine.js` / `flow.js` / `recorder.js` / `camera.js` 是**逐字节相同**的，可直接互换。

**内置音源库是三份共有的引擎能力**：`demo(ctx, index)` 的整段代码在 `0.3` / `0.3.1` / `0.3.2` 里逐字节相同（搬运时按锚点整段复制，别手抄），但**只有 0.3.2 有切换它的按钮** —— 0.3 与 0.3.1 仍只调用 `demo(ctx)`（= 0 号），行为与加音源库之前完全一致。

反向同步（0.3.1 → 0.3）**不能只覆盖 `engine.js`**：0.3 的 `app.js` 里一处 `setAudioSession` 调用都没有，光搬引擎那条 iOS 修复不会被调用；`recorder.columns()` 也要 0.3 的绘制端配合。要不要同步是产品决策，不要顺手做。

搬运后跑 `node tools/engine-sync-check.cjs <同步前的 engine.js> <同步后的 engine.js>` 证明「声音没变」，它会逐字节比对计划事件、八度派生、`inputGain`、`defaultSpray`、XY 映射、导出面与 `BufferSource.start` 序列。**若这次就是要改声音**，它会报差异——那是预期结果，此时改跑听感验收并记下新基线。

### 已知未解决 / 未验证

1. **iOS 上实时输入响度偏小（未解决）** —— 只属于 **0.3.1 的实时输入路径**，不是 0.3.2 的遗留问题（0.3.2 已去掉该路径并通过两平台验收）。卡在缺真机 A/B 数值：需在 iOS 上跑 `window.__iosAB`，记录 A（麦克风直通）与 B（经引擎）两次 `read()` 的 `rmsDb`/`peakDb`。**不要先凭猜提高所有平台的增益**（会破坏已正常的桌面端）。已排除项、分诊标准与诊断入口见 [`历史记录.md`](历史记录.md) 的「实时输入的响度」一节。
2. **代理侧未实际试听**，真机验收是用户做的。探针量到的电平只能证明「不哑也不削顶」，不能替代听感。
3. **iOS 每次 `play()` 新建 AudioContext**，参考实现是整页共用一个并在首个手势同一调用栈里 `prime()`。改动面大（要把上下文抬到共享层、改 `deactivate` 的所有权语义）且只有真机能确认收益。★ 2026-09-28 的真机验收**没有**出现「第一次播放没声音」的症状，所以这条未被证实——没有新症状不要动。
4. `engine-sync-check.cjs` 的**默认调用**仍会失败：它要 `tools/engine-0.3.1-before.js`（同步前的快照），该文件不在仓库里。要让它可跑，需放一份当前引擎当新基线（含义变成「引擎没再漂」），或从提交 `bc21254` 取历史原件复现那次真实比对。本轮没有擅自决定。
