# 02 · aisatsana 式极简钢琴（Markov 乐句重组）

第二份练习：复刻 Generative.fm 的 [piece-aisatsana](https://generative.fm/music/alex-bainter-aisatsana) 的生成机制——**记忆 + 重排**：音符素材固定，乐句顺序由马尔可夫链重组。

版本：[`0.1`](0.1/)（固定乐句 + 段落链）；[`0.2`](0.2/)（增加段落内音高马尔可夫链，节奏和宏观结构不变）；[`0.3`](0.3/)（当前版本：只改视觉，乐句之间从“切换”变成持续变形，音频路径未改动）。版本目录只保存实现文件，本 README 统一记录整个练习的设计与演进。

> **视觉规则已经抽成本目录里的 [`视觉规则.md`](视觉规则.md)。**
> 那份文档只讲规则（分层、时间基准、节点与连线的状态机、力学、参数表、禁区、验收清单），
> 不依赖本练习的实现细节 —— 想把这套观感用到别处时，直接读它即可；本 README 只记录本练习的演进与实测数据。

## 学习内容

- 谱面数据 → 八分音符网格量化 → 乐句切分（32 步一组）
- **段落化乐句库**：10 个乐句分 4 段（A 安静 → B 主题 → C 发展 → D 结尾），段落感知转移矩阵模拟原版衔接
- 马尔可夫链训练乐句转换概率，`walk()` 沿概率重组顺序
- 提前 1 秒触发 + ±25ms 人性化抖动
- 乐句素材的**律动设计**：节奏不均匀（切分/附点）、力度重音（0.4~0.8）、双音和弦块、音区对比——模仿人写的旋律而不是机械琶音
- **演奏版本系统**：同一乐句可被弹成完整、骨架、回声或迟到回应；留白来自“这次说多少”，不是插入空白段
- **0.2 实时视觉**：每个音高显示为状态节点，素材中学到的转移显示为有向边；静态乐句历史在底层依次排列，力导向网络在其上方游动，实际发声通过 `Tone.Draw` 同步高亮当前节点与刚走过的边；A/B/C/D 四个段落使用不同的当前状态色
- **0.2 背景 texture**：复用 03 的 Moodist 环境素材（包含 Jungle），以独立随机源、低增益和最多两层并发的方式淡入淡出，不改变钢琴的种子路径
- 与 01 的对照：**从零生成 vs 记忆 + 重排**（两种生成范式）

## 运行

运行当前版本请打开 [`0.3/index.html`](0.3/index.html)；历史版本入口是 [`0.2/index.html`](0.2/index.html) 与 [`0.1/index.html`](0.1/index.html)。页面通过 CDN 加载 Tone.js、钢琴采样与环境音，因此首次运行需要联网。

**钢琴采样**：`vsco2-piano-mf`（VSCO2 免费钢琴库，CC0）经 jsDelivr GitHub 镜像远程加载——首次约 50MB（之后走浏览器缓存），加载失败/超时自动回退 FM 合成钢琴，不会卡死。官方 CDN `samples.alexbainter.com` 对直连返回 403（有访问控制），故不走它。0.2 与 0.3 还会远程加载 Moodist 环境音效，单个音效失败或超时会静默跳过。也可在仓库根目录运行 `python -m http.server 8000` 后访问 `http://localhost:8000/exercises/02-aisatsana-markov/0.3/`。

## 0.3 视觉：乐句之间是“变成”，不是“切换”（只动视觉，音频未改）

0.2 给人的直接感受是“每一句的过渡很生硬”。原因在 `renderPhraseVisual()`：每个乐句开头都执行 `markovMapEl.replaceChildren()` 重建整张 SVG。

- 节点与边被删除再创建，CSS 过渡失去起始状态可补间 → 当前状态与活动边只能硬切；
- 节点环形坐标由视口与音高索引决定（确定性），重建等于抹掉力导向漂移 → 图每 9.6 秒（32 步 × 0.3s）弹回初始位置；
- `previousVisualNote = null` → 跨乐句的转移永不显示；`graphMotion.energy = 1` → 布局每句被重置；
- 重建时刻正是首音前 0.01 秒，所以“跳”永远砸在乐句重拍上。

0.3 把图改成**一个持续存在的对象**，乐句更替不再是一件事，而是一次重组：

- 节点 = 四个段落用过的音高并集（14 个），建一次、永不重建；环上的基准位置由视口与音高索引决定，每次换句再叠加一点相位 / 半径微扰（见下），**所以换句时所有点都会移动**；
- 边 = 所有段落出现过的转移（48 条），同样预建，DOM 之后不再增删；
- **连线的生长只由“有新点冒出来”触发**（用户明确要求的规则）：一端刚变成乐句点的转移，**朝那个新点生长过去** —— 新点在起点端时从终点端长过来（`stroke-dashoffset` 取负值反向揭示），新点在终点端时从起点端长出去；**两端本来就是乐句点的连线不做生长动画**，直接画满、只是跟着点移动；A、C 都有的连线完全不动（`setEdgePresence` 幂等）。收回：**反向生长**（不是消失、也不是透明度递减 —— 用户明确要求），揭示区间沿与生长相反的方向退回，**全程保持满透明度**，只有几何在缩。
- **生长/收回的时长与音符间隔挂钩，而且重组发生在首音那一刻**（先是用户指出固定时长会“一条还没长完、另一条已经开始”，后又指出旧的窗口让变换跑在无音的空白里、观感很干）：重组从**本句首音前 `MORPH_LEAD_S = 0.05` 秒**开始，时长基准是**本句内部第一个音程**（首音 → 第二个音，`clamp(M, MORPH_MIN_S = 0.32, MORPH_MAX_S = 1.6)`）；每条线再用**它自己那个点**的速度倍率细分。实测时长基准 0.3 / 0.6 / 0.9 / 2.4 秒 → `0.32 / 0.60 / 0.90 / 1.60` 秒，对应飞行 **600–798ms / 1004–1496ms / 2200ms**；而旧版（基准取"上一句尾音 → 本句首音"的空白、常驻上限 1.6 秒）飞行 2.2 秒中**约 73% 没有新音**。`EDGE_GROW_S = 0.7` / `EDGE_RETRACT_S = 0.6` 退化成“拿不到间隔时的兜底值”；**箭头只在画满之后才挂上**，否则线还没长到新点箭头就先出现了；画满后移除 dash（节点一直在呼吸漂移，留着就得每帧重算路径长度）；
- **不属于当前段落的音高收进下层（藏身层），精确贴在一个在场的宿主节点背后**（偏移 3px、半径收到 9px、**透明度压到 0**、音名隐藏）——宿主半径 17px，所以它是被真正挡住的；谁当宿主按“离自己环位最近的在场节点”分配；
- **变成本段落的音高时，它从宿主背后一次弹出**：搬到在场层（压在所有藏身点之上），沿 **easeOutBack**（`WAKE_BACK = 2.0`）落位 —— 起步速度约为平均的 5.7 倍（很猛），临到落点前**单次过冲约 13%** 再收回，收回之后不再有任何来回。
- **连线的明度 = 该转移在马尔可夫链里的概率**（用户提出：连线本来就是概率算出来的，能不能用灰度表达）：`walkNote` 是从当前音的后继数组里等概率挑一个（重复项就是权重），所以 **from→to 的概率 = 该转移出现次数 ÷ 该音后继总数**，明度按 `EDGE_OPACITY_MIN = 0.16 ~ EDGE_OPACITY_MAX = 0.72` **线性**映射。素材里既有大量 `p = 1` 的确定转移、也有 `p ≈ 0.07` 的偶然转移，所以线性映射能把灰度铺开（实测 A 段 0.272–0.72、跨度 0.448；C 段 0.20–0.72、跨度 0.52；若改用开方，低概率被抬到 0.39 附近，对比反而更弱）。**这两个常量里已经折算掉旧版写在 CSS 里的 `stroke-opacity: .8`**（旧元素值 0.2/0.9 × 0.8 = 屏幕上本来就是 0.16/0.72），所以线的观感和以前一模一样，但箭头的明度现在跟着线走（见下“线与箭头同明度”）。旧实现只有"出现次数 > 2"的两档提示，现已由概率灰度取代；
- **每句的点分布不同，但依据只能是这一句的音乐（2026-09，用户："不想让每一句的音符点分布在视觉上完全固定，每次要不一样，但整体逻辑还是要有的 —— 不要随机，完全的随机毫无意义"）**：旧做法是每次换句取一个 ±0.1 弧度 / 0.95–1.05 倍的**随机**微扰 —— 可复现但没有依据，而且幅度小到每句几乎一样，已删除。现在两条规则：**A 朝向 = 本句首音的槽位转到正上方**（但每句最多转半个槽位 `RING_ORIENT_STEP`）；**B 半径 = 本句该音发声次数的归一化值**（`RING_ACTIVITY_PULL = 0.22`，弹得最多的音比外圈靠内 22%），本段落在场但这句没弹到的音留在最外圈 —— 于是每句的点分布是一张不同的"密度云"：内圈是这句的骨干、外圈是没用上的可能。★ A 必须限速：实测本素材乐句首音是 A: C3/C3、B: C4/C5/C4、C: C3/C4/E4、D: C5/E4（槽位 1/5/7/11），C4↔C5 差 6 个槽位，一次摆过去最远那颗点要跑约 **720px**；限速后每句位移 **≤ 90.8px（实测最大 87.1–90.8、平均 67px）**，而首音在几句之内逐渐转到正上方（实测第 4 句 C3 正好落在 270° = 正上方）。★ 两条都是确定性的：**同一形状重算两次，所有环位偏差 0.000px**（视觉侧因此彻底不再需要随机流，`visualRng` 已删除）；★ 环位槽点自身只留 ±4% 的固定抖动（`RING_SLOT_JITTER`），不能再放大 —— 过去的 ±12% 会盖过"活跃度"这个真正的信号；
- **飞行有三类，按“点的角色变化”选缓动**：刚变成乐句点用 `mode: 'pop'` + `easeOutBack`（起步猛、单次过冲 13%，是“弹出来”）；本来就是乐句点用 `mode: 'glide'` + `easeInOutCubic`（平滑滑到新环位、不过冲，它们只是换位置而不是飞过来）；变回收起点用 `mode: 'retreat'` + `easeOutCubic`（滑到宿主背后，见下）。三者共用同一套按音高固定的速度倍率与时长公式；
- **飞行时长 = 音符间隔 × `WAKE_FLIGHT_SCALE = 2.0` × 该音高自己的速度倍率**，钳到 `WAKE_FLIGHT_MIN_S = 0.6` ~ `WAKE_FLIGHT_MAX_S = 2.2` 秒（用户两次反馈“太快”，从 0.32 固定 → 1.5 倍 → 现在 2.0 倍）；
- **视觉侧不再使用随机数**：环的朝向与半径都由本句的音乐算出（首音 + 发声次数），所以"同一段音乐必然画出同一张图"；也因此不需要再维护一条视觉随机流（原来的 `visualRng` 已删除）。⚠️ 若将来又要给视觉加随机，仍必须像 texture 那样**从种子派生一条独立流**，绝不能消耗钢琴的 rng（0.2 踩过这个坑）；
- **视口与响应式（2026-09 调整，用户反馈"窄屏下很好，宽屏下四周的空白太大"）**：原因是环的半径写了两条**绝对上限**（`min(380, W*0.36)` / `min(330, H*0.32)`），窗口一大就再也不长 —— 实测 2560×1440 的窗口里只有 **760×660** 一圈（横向 30%、纵向 46%）。改法不是把常量逐个乘系数（那会变成"环变大了、点和字还是 17px/12px"），而是把内部坐标定义成**设计单位**：`viewBox` = 窗口尺寸 ÷ `scale`，由浏览器把整张 SVG 等比放大，于是环、节点、音名、连线粗细、箭头尺寸、弹的幅度**全按同一比例**缩放。`scale = clamp(sqrt(窗口面积 ÷ 1100×700), 1, 2.5)`——**下限 1** 保证参考尺寸以内的窗口渲染结果与改造前逐像素一致（窄屏观感不变）。环半径改为纯比例 `0.36W / 0.32H`，实测各视口横向填充都是 **0.68**、纵向 **0.63**、节点屏幕半径 = `17 × scale`、间距/半径稳定在 **10.3–14.6**（1440×900 → scale 1.30 / 节点 22.1px；1920×1080 → 1.64 / 27.9px；2560×1440 → 2.19 / 37.2px；3440×1440 → 封顶 2.50 / 42.5px）。HUD 是 HTML 覆盖层、故意不缩放，保证文字始终可读；
- **`f` 键全屏 / 退出全屏**（2026-09 增加）：键盘事件算"用户手势"，所以不需要额外按钮；全屏的是整个文档（HUD 与控制还在），想只看画面再点一下画面隐藏界面 —— 两件事故意不合并。焦点在种子输入框里时不处理（否则打不出 f）；`requestFullscreen()` 的 Promise 会 `catch` 掉，避免控制台出现未捕获错误；`fullscreenchange` 后调用 `updateGraphViewBox(true)` 重算视口（浏览器不一定会派发 `resize`）；
- **退场的连线是"反向生长"，彩色层跟着线一起退（2026-09 修复）**：用户发现换句时"激活的连接线直接通过透明度消失"。查下来是两个原因叠加：① `applyPhraseVisual` 发现某条转移不再属于本段落时顺手把它的概率明度写成 0，而 `updateEdgePresence` 又把明度每帧写进 `opacity` —— **整段收回过程是看不见的**（实测收回途中 `presence` 0.653、`opacity` 已经是 **0**）；② 彩色行进层保持满长、`opacity` 1，直到下一条转移开始才用 1.2 秒退色，于是画面上只剩"停在原处、慢慢变淡"的彩线。现在：明度只在"它属于本段落"时更新（退场保留上一次的明度，`presence` 到 0 才压到 0），彩色层的可见区间裁成 **扫过区间 ∩ 灰线可见区间**，收回时跟着灰线逐帧反向生长、**全程满透明度**、收完即结束高亮（实测两者 `dashoffset` 逐帧相同：`89.81487141927084` vs `…83`，`opacity` 全程 1，箭头在收回途中为 `null`）。
- **高亮的"退场"也是反向生长，不是退色**（用户 2026-09 的规则："所有连接线的出现/消失都要生长/反生长的动态，而不是透明度控制"）：一条**留在本段落**的转移被下一条取代时，彩色层沿原路**退回去** —— 揭示区间从全长缩回 0（终点端先消失、起点端最后消失），时长与它走过来时相同（= 该音的 I，即 `pulse.duration`），**全程满透明度**，退场一开始就摘掉箭头。实测区间 `256 → 231.8 → 204.1 → 176.4 → 148.8 → 121.1 → 93.4 → 65.7 → 38 → 10.4`（0.576 秒内线性缩回 0，速率 ≈ L ÷ I）。旧的 1.2 秒 `opacity` 退色（常量 `EDGE_SWEEP_FADE_S`）已删除 —— 至此**连线的出现/消失（底边与高亮）全部由几何表达，没有一处用透明度**；`opacity` 只承担"概率明度"这个静态量；
- **箭头跟着"正在移动的头部"走（2026-09）**：用户指出"箭头一直在目的地等着曲线过来"，要求生长/反向生长时箭头跟随曲线头部，并且方向要按曲线算、不能固定或固定成结尾朝向。做法：每条边多一条 `.chain-head` 路径（描边不可见、`stroke-opacity: 0`，只承载 marker —— marker 的 fill 是 `context-stroke`，实测不受 `stroke-opacity` 影响，所以描边不显示、箭头照常显示），每帧把它的 `d` 重算成"头部前 12 个用户单位的一小段曲线"，于是 `orient="auto"` 给出的就是**该点切线**。**箭头底边取在头部那一点**（参考点是底边中点，所以折线末端就放在头部）—— 这一点很关键：线头（含 2.4 宽描边的圆头）全落在箭头较宽的身体里，不会露出来，而且颜色到位时这支箭头与"停在终点的那支"逐点重合。方向：行进时沿曲线正向（θ = 0），反向生长时**掉头指回起点端**（θ = π）—— 用户明确肯定过这个转向（"回退箭头转向回退的方向是对的"），但要求**慢慢转过去、不能一瞬间翻**。做法是显式算出方向 `u = 切线·cosθ + 法线·sinθ`（切线/法线取头部处局部值），θ 逐帧从 0 爬到 π：实测 8ms 一帧 `4 → 8 → … → 176 → 180`、**0.36 秒转完**（= 高亮时长 0.6s × `HEAD_ARROW_TURN_RATIO = 0.6`，钳制 0.22–0.5s），转向期间**底边中点始终钉在头部**，所以线的端点一直在箭头身体里（横向宽度实测：头部 8.5 → +1 时 7.5 → +2 时 6.5 → +4 时 4.5 → +8 时 0.5）。彩色层同时用**平头描边**（`stroke-linecap: butt`）：圆头会比算出来的端点再多伸 1.2，反向生长时那截会露在箭头外面。同时**一条边只显示一支箭头**：颜色还在走时终点那支不挂（否则就是"在目的地等着"），颜色到位后骑行箭头收起、改由停在终点的那支（明度与线一致），反向生长退完再把底边箭头挂回来。实测：行进 `dotWithTangent = +1`、反向生长 `−1`；箭头底边到彩色头部 0.00–0.01、尖端到头部 8.8（正好一个箭头长度）；两种运动期间 `path.marker-end` 与 `pulsePath.marker-end` 都是 `null`。★ 两个坑：①取样顺序必须"从后往前排到头部"，写反会让箭头掉头 180°（实测 −1）；②**不要把尖端放在头部上** —— 那会让线头露出、并在交接时"往前弹一下"（用户报的两个现象都出自这里：细步实测"箭头底边到静止位置的距离" 应当线性单调减到 0，`12.11 → 10.39 → 8.66 → 6.94 → 5.22 → 3.49 → 1.77 → 到位`，每帧恒 1.72）；
- **变回收起点时是“滑到宿主背后被挡住”，不是原地消失**（用户报的 bug：下一次音符变少时，有点突然不见了）：收起也是一个飞行（`mode: 'retreat'`），动效用 `easeOutCubic`（立刻起步、稳稳落进宿主背后），不透明度用 `1 − easeInCubic(t)` —— **前段几乎全亮**（所以看得出它在移动），**末段迅速淡掉**，而末段正好是它钻进宿主背后的时刻，于是观感是“被挡住了”。结束时它停在离宿主 3px 处、半径缩到 9px（宿主半径 17px），完全被遮挡；连线的反向生长用同一个时长，所以线是和它一起退进去的；
- **换句的弹是“通过连线传开的”，不是整体外扩**（用户明确否定过整体径向外扩的版本）：换句那一刻给在场节点一次**切向**冲量（方向按索引交替），位移再**沿连线传给邻居** —— 连线在这里是弹簧（“铰链”，`EDGE_COUPLING = 0.012`），静止长度取环上的原始距离，所以环的平衡位置不变、只是把运动传出去。阻尼 `NODE_DAMPING = 0.92`（阻尼太大扰动传不出去）；
- **行程（振幅）的调整记录**：用户反馈“速度够、范围不够，像是很短的弹簧，把弹簧放长一点”。离散模拟给出的结论是：本系统阻尼很重（0.92/帧），**单把弹簧变软只值 1.25× 行程**；放松阻尼虽然能加行程，却会把方向反转从 3 次推到 9 次、变成乱抖。所以采用“软一档 + 适度加冲量”：`NODE_HOME_SPRING` 0.012→**0.009**、`EDGE_COUPLING` 0.016→**0.012**，并把推挤 / 漂移按同比例降到 **900 / 0.038**（静态偏移 = 力/弹簧，必须一起调，否则环会变松），换句冲量 6→**8.5**。合计行程 **≈1.6×**，起步速度只涨约 40%；
- **弹的力度分两级**（用户明确要求，之前两级太接近以至于听着只有一种）：
  - **换句级**：`PHRASE_KICK = 8.5`（实测单点峰值 **27.3px**，84ms 到峰）、段落切换 `SECTION_KICK = 12.5`（**40.1px**）—— 整句的重音；
  - **音符级**：`NOTE_KICK = 1.7`，每个音发声只轻轻推一下（实测 **5.9px**）—— 两级之比 **4.6 : 1**，听得出来“换句”才是重音；
- **转移的激活是“行进”，不是整条变色**：彩色覆盖层与灰边同曲线，`stroke-dasharray` = 全长、`stroke-dashoffset` 从全长推到 0，于是颜色从**起点一路长到终点**，走完保持彩色，等下一条转移开始时再退色 1.2 秒。颜色到达终点的那一刻做两件事：给底边加 `.active`（**只换 `stroke` 颜色、绝不改 `stroke-width`** —— 箭头是 `markerUnits="strokeWidth"`，描边一变粗箭头就会跟着放大），**并且给行进层挂上第二支几何完全相同的箭头**（`userSpaceOnUse` 版本，尺寸不随 2.4 的粗描边变化）—— 因为线本来就是“底边 + 行进层”两层叠出来的，箭头只挂一层就会出现“线是实心的、箭头还半透明”（用户 2026-09 报的问题），两层都挂之后箭头与线的明度逐帧相同（颜色用 0.12 秒快速切换，让箭头“到点亮起”；退色时随底边一起回到 1.2 秒的灰）；
- **一个音程驱动三件事**（用户要求：音点的“亮 → 暗”不能每个音都一样）：上一个音到这个音的实际音程 `clamp(间隔, EDGE_SWEEP_MIN_S = 0.16, EDGE_SWEEP_MAX_S = 1.5)` 同时决定 ——
  1. **彩色行进**走多久（到点箭头亮起）；
  2. 该音点**从亮到暗**用多久（`flashDuration`，线性退回常态色）；
  3. 于是两者天然同步：音密处一闪即暗、留白处余韵长，而不会出现“行进还在走、点已经暗了”。
  时长由 `showVisualNote(phraseId, note, audioTime)` 传入的发声时刻与 `previousVisualTime` 相减得到；第一个音没有“上一个音”可参照，用 `FIRST_NOTE_INTERVAL_S = 0.5` 兜底（行进与点亮都用它，避免开场第一个音闪成 0.16 秒）；

- **HUD 增加 light / dark 主题按钮（2026-09，用户："准备调整配色，先在 HUD 里加 light/dark 按钮，用当前 icon 库的 icon"）**：按钮在控制面板右上角（控制面板改成 `flex` 行），图标沿用 `shared/exercise-controls.js` 那套（24×24、`fill:none`、`stroke` 继承 `currentColor`、`stroke-width: 2.4`），**图标表示"点了会变成什么"**（深色时显示太阳）；`title` / `aria-label` 用动词，`aria-pressed` 表示当前是不是浅色。配色**只有一处定义**（CSS 变量 `:root` 与 `html[data-theme="light"]`）：页面元素直接用变量，SVG 节点因为要逐帧做 RGB 插值，由 `applyTheme()` 从同一批变量读成数组（`NODE_IDLE_FILL` / `NODE_PRESENT_FILL` / `NODE_PRESENT_STROKE` 因此改成 `let`）—— 不能在 CSS 和 JS 里各写一份，否则会出现"面板变白了、环上的点还是黑的"。主题在 `<head>` 第一段脚本里、**首帧之前**应用（否则浅色用户每次打开先闪一帧深色），选择存 `localStorage['gml-theme']`（读写都包 `try`，`file://` 下会抛错），**默认深色、不跟随系统**。★ 浅色不是"把 zinc 色阶对调"：第一版按色阶镜像取值后整张图发虚，实测节点与底色只剩 **1.34:1**（深色 2.51:1）、连线墨色 2.33:1（深色 4.02:1）；现在改成**对齐对比度** —— 墨色（连线与节点描边 `#71717a`）两套主题共用，节点灰度按对比度反解（浅色收起/在场 = `#b3b3b8` / `#9a9a9e`），实测在场节点 **2.55:1**（深色 2.51）、收起节点 **1.90:1**（深色 1.86）、连线 100% **4.40:1**（深色 4.02）、最淡的概率线 **1.21:1**（深色 1.15）。音名颜色跟着节点走（深色白字、浅色 `#18181b`）。⚠️ 待办：日志正文用段落色当墨，浅色下绿色只剩 **1.97:1**、橙色 2.15:1，需要另配一套压暗的段落色或改用 `--fg`，等配色定夺；

**位置不用 CSS 过渡，也不用欠阻尼弹簧**：节点要在“藏身层 / 在场层”之间搬动，而 DOM 搬动会重启动 CSS 过渡，所以半径、透明度、颜色、音名可见性全部由 `paintNode()` 逐帧写入。

- **弹出/收起用一次性“飞行”**：`easeOutBack`（`WAKE_BACK = 2.0`，单次过冲约 13%），时长由音符间隔决定（见上）。欠阻尼弹簧（k=0.012 / 阻尼 0.94）会在到达后继续过冲并来回弹几下；而纯缓出（`easeOutQuart`）又完全不弹、看起来像平移 —— 用户把这两个极端都否掉了，**单次小过冲**才是要的手感；
- **静止时的呼吸仍用弹簧**（`NODE_HOME_SPRING = 0.009` / 阻尼 0.92；阻尼不能太大，否则扰动传不出去）；
- **连线既是视觉也是“铰链”**：作为弹簧参与动力学（`EDGE_COUPLING = 0.012`，静止长度 = 环上的原始距离，所以平衡位置仍是那个环），但**不作布局依据** —— 早期版本给边设了 170–280px 的绝对“理想长度”，结果把环整个撑开、平衡点偏移 30px 以上。区别就是静止长度取“环上的距离”还是“一个常数”；

**踩过的坑之二**：行进层一开始在 CSS 里写了 `opacity: 0`，而 JS 又用 `setAttribute('opacity', 1)` 去点亮它 —— SVG 呈现属性会被任何 CSS 规则覆盖，于是**属性写着 1、画面完全不显示**，用户看到的就是“彻底没有彩色连线”。现在：CSS 里不再声明透明度，全部由 JS 写**内联样式**（`style.opacity`），内联样式不会被样式表覆盖。教训是验证方式也得跟着改：只读 `getAttribute('opacity')` 会误判为通过，必须读 `getComputedStyle(...).opacity`。

**踩过的坑之三**：转移边一开始还参与布局（把两端拉到 170–280px 的理想长度），但环的间距只有约 130px，于是边一直在把环撑开，弹簧平衡点被推偏 30px 以上，节点弹出后会在 72%~117% 之间来回摆、停不下来。现在的结论是：**边只做视觉，不参与布局**；布局完全由环位弹簧决定。

    - **两端都是老点的新连线**（E4|G4）：`presence=100%`、`dasharray=null`、箭头已在、明度按概率写入 —— 不做生长动画，直接就在。

    - **端点收起 → 反向生长退回**（C→A，F3/D4/A4/B4/C5 收起）：起点端收起的连线 `C5|G4` 轨迹 `97% → 81% → 64% → 47% → 30% → 14% → 0%`，`revealFromEnd=true`（朝终点端退回），**收回过程中透明度全程 0.58 不变**（证明是几何收缩而不是淡出），收完 `presence=0 / 箭头=null`；终点端收起的 `C4|D4` 则是 `revealFromEnd=false`、朝起点端退回。
    - **时长与音符间隔挂钩**：传入时长基准 0.35 / 0.8 / 1.4 秒时，生长与反向生长的时长**分别等于 0.35 / 0.8 / 1.4 秒**；基准 0.35 秒时的生长进度 `29% → 57% → 86% → 100%`（每 0.1 秒采样）；时长基准映射 `0.3 → 0.32`、`0.6 → 0.60`、`0.9 → 0.90`、`2.4 → 1.60`（钳制）；
    - **重组与首音同刻（2026-09 调整）**：调度时刻 `首音 → 首音 − 0.05s`；旧版（窗口 = “上一句尾音 → 本句首音”的空白，常驻上限 1.6 秒）飞行 2.2 秒里**约 73% 没有新音**，新版基准 0.32 秒时飞行 **600–798ms 全程有音乐**；线与点仍然同步（20 条朝新点生长的连线，时长全部等于其对应节点，0 条不一致）。
  - 收起：见上「收起 = 滑到宿主背后被遮挡」那条（**旧的“原地淡出 + 不可见后瞬移”实现已被取代**，那版曾实测 opacity `0.60 → 0.36 → … → 0.00` 且位移仅 0.0–0.2px，正是用户报的“突然消失”观感）。
  - 转移行进（探针把 `performance.now()` 换成可控假时钟，才能逐帧验证）：给定 0.6 秒音程时行进时长正好 0.600 秒；揭示进度逐帧 10% → 25% → 39% → 53% → 68% → 83% → 97% → 100%（单调向前），`dasharray` 始终是“全长 全长”；走完后保持 `opacity=1`，下一条开始时旧的那条退到 `opacity=0.861 → 0.000（active=false）`；钳制正确（音程 5s → 1.50s，0.01s → 0.16s）。
  - 箭头时序与尺寸：灰箭头 `markerUnits="strokeWidth"`、`markerWidth=8`（**尺寸随引用它的 path 的描边宽度缩放**），行进层的箭头另建一支 `markerUnits="userSpaceOnUse"`、长度 `ARROW_LENGTH = 8.8` 的同款（直接引用灰箭头的话，2.4 的粗描边会把它放大 **2.18 倍** —— 那就是用户看到的“箭头过大”）。未激活时底边 `stroke=rgb(113,113,122)`、`strokeWidth=1.1px`、挂着 `url(#arrowhead)`；行进中底边仍是灰的（`active=false`）、行进层 `opacity=1` 且**不带 marker**（颜色还没到）；到达终点后底边 `active=true`、`stroke` 变成 `rgb(139,92,246)` 而 **`strokeWidth` 仍是 1.1px**（`getComputedStyle` 已核对，CSS 不再声明它），同时行进层挂上 `url(#arrowhead-pulse)`；下一条开始后底边退回灰、行进层归零并摘掉箭头。
  - **线与箭头同明度（2026-09 调整，用户报“线都长完了，箭头的三角还有点透明”）**：根因是**描边的不透明度传不到箭头上**。标定页实测（同一页 5 条路径）：`stroke-opacity=.8` + 元素 `opacity=1` → 线 **0.800**、箭头 **1.000**；元素 `opacity=.9` → 线 **0.719**、箭头 **0.900**（即 marker 的 fill 只吃元素的 `opacity`）。而线其实是**两层**元素叠出来的（灰底边 + 行进层，行进层一直亮到下一条转移开始才退色），箭头却只挂在底边上 —— 于是颜色到位后线已饱和、箭头还停在概率明度上（最暗那条转移：线 `(139,92,246)`、箭头 `(40,40,44)`）。改法两条：①行进层挂上**几何完全相同的**第二支箭头（标定实测两者 bbox / 尖端 / 末尾高度 / 像素面积一致，且不再随描边宽度变化），箭头与线的叠乘结果逐帧相同；②把旧版写在 CSS 里的 `stroke-opacity: .8` 折算进 `EDGE_OPACITY_MIN/MAX`，让**明度只有一个来源**（元素 `opacity`）—— 屏幕上线的明度和以前完全一样。改后实测：灰态暗转移 线 `(39,39,42)` vs 箭头 `(40,40,44)`；最暗转移正在走彩色时 **线 = 箭头 = `(139,92,246)`**（差 0）；退色一半时差 0.013。
  - **参考点取箭头底边中点（`refX = 0`，2026-09 调整）**：marker 的 `refX/refY` 就是“路径末端落在箭头坐标系里的哪个位置”，把它放在**底边中点**，线尾就正好停在箭头最宽的那条底边上 —— 既不可能再从收窄的锥面里露出来（用户报过“连接线超出了箭头”：旧版 `refX = 7` 时实测线尾处箭头宽度只有 **1.10**，恰等于线宽 1.1），也不需要上一版那套“线尾回缩 `ARROW_TAIL_INSET = 3.2` + 同步缩小 `refX` 补偿”。箭头位置与旧版实测一致：底边 **28.7px**、尖端 **≈20px**（都指离目标节点圆心的距离），线的起点端仍是 `R + 2 = 19px`。标定实测：`refX = 0` 时线上的点、线尾附近的点、箭头身体内部的点**同为 0.502**（单层、无叠加），三种声明方式（`userSpaceOnUse` / `strokeWidth` 单位 / 换描边宽度）结果完全一致。
  - ⚠️ **量箭头像素前先查旁边有没有别的连线**：48 条边都汇到少数几个节点，实测 `C4|G3`（明度也是 0.72）从采样点旁 **2.9px** 穿过，像素被叠乘成 `1−(1−0.72)² = 0.92` 而不是 0.72 —— 差点被误判成“箭头比线更实”。现在探针会把每条在场连线到采样点的最小距离一起打出来（对每条边采样 160 个点）。
  - **可见性一律用计算样式核对**（属性不算数）：行进中 `getComputedStyle(行进层).opacity = 1`（内联样式），在场节点 `0.995`、收起节点 `0.000`/音名 `0.000`；下一条开始后行进层计算样式回到 `0`。这一项正是补上“属性写了 1 但画面不显示”那个坑之后加的断言。
  - 切换段落后节点 DOM 未重建（`dataset` 标记仍在），三层子元素数守恒（藏身层 10 + 在场层 18 = 14 圆 + 14 音名）；发声染色走 `flash` 并在 30 帧后衰减到 0.64；`window.exercise.activate` 仍存在。
- **我这边看不到画面也听不到声音**，以下是现在真正可调的旋钮（都写在 `0.3/index.html` 顶部与视觉一节）：
  - 飞行快慢：`WAKE_FLIGHT_SCALE = 2.0`（相对音符间隔的倍数）、`WAKE_FLIGHT_MIN_S = 0.6`、`WAKE_FLIGHT_MAX_S = 2.2`；
  - 点与点的速度差：`WAKE_SPEED_MIN = 0.8` / `WAKE_SPEED_MAX = 1.25`（按音高用黄金比小数固定）；
  - 弹出的过冲：`WAKE_BACK = 2.0`（≈13%；想更含蓄 1.6 ≈ 9%）；
  - 连线的生长/收回：跟着 `morphSeconds`（= `clamp(间隔, MORPH_MIN_S = 0.32, MORPH_MAX_S = 1.6)`）与各自点的速度倍率；`EDGE_GROW_S = 0.7` / `EDGE_RETRACT_S = 0.6` 只是兜底；
  - 连线灰度：`EDGE_OPACITY_MIN = 0.16` / `EDGE_OPACITY_MAX = 0.72`（元素 `opacity`，也是箭头跟着走的那个值）；
  - 每句的朝向与形状：`RING_ORIENT_STEP = 2π/14 × 0.5`（每句最多转半个槽位，朝"首音在上方"）、`RING_ACTIVITY_PULL = 0.22`（活跃度对半径的拉伸）、`RING_SLOT_JITTER = 0.04`（槽点固定抖动）；
  - 换句的两级力度：`PHRASE_KICK = 8.5` / `SECTION_KICK = 12.5` / `NOTE_KICK = 1.7`；
  - 收起的透明度：`HIDDEN_NODE_OPACITY = 0`（想留一点暗示就调 0.05，但宿主遮挡会因此失效）；
  - 主题配色：**画面那部分**（`--stage-bg` / `--graph-edge` / `--graph-node-base` / 段落色 / 音名两个候选字色）全部集中在 `index.html` 里带 `★★` 的 `PALETTE` 块（两套主题各一份），由 `applyTheme()` 推成 `<html>` 的内联 CSS 变量；**HUD 那部分**（`--bg / --panel / --fg / --dim / --line / --hairline / --log-fg / --code-* / --control-*`）仍在 `<style>` 的 `:root` 与 `html[data-theme="light"]` 两块里；
  - **画面配色集中在 JS 的 `PALETTE` 里**（2026-09 用户要求"把非激活点 / 音符字 / 连线 / 背景色这些变量和段落色写到一块，我边看边调"）：`PALETTE.dark` / `PALETTE.light` 各有一份 `stageBg`（画面底）、`edge`（未激活连线）、`nodeBase`（点本来的颜色）、`labelInkLight` / `labelInkDark`（音名的两个候选字色）、`sections[4]`（段落色 = 被激活时的颜色）；`applyTheme()` 把它们推成 `<html>` 上的内联 CSS 变量（`--stage-bg` / `--graph-edge` / `--graph-node-base` / `--section-color`），CSS 规则照旧用 `var()` 取值，**CSS 里不再声明这几个变量**（内联样式优先级更高，写在那边改了也不生效）。非法色值会被跳过并在控制台点名，所以手调时打错不会把画面弄坏。页面 HUD 的配色（面板、正文、控件、`code`）不是画面的一部分，仍在 `<style>` 的两个变量块里；
  - **点的颜色是两个状态、两种来源**（用户 2026-09："乐句点有本来的颜色和被激活的颜色（跟随乐句颜色）"）：平时就是点**本来的颜色** `nodeBase`（不随段落变），刚发声时插值到**本段落色** `mix(nodeBase, 段落色, flash)`，flash 由该音的 I 决定衰减时长 —— 所以"被激活的颜色"是算出来的、不是配置项。旧结构里 `nodePresent`（在场点的灰）与 `nodeBase` 重复，`nodeIdle` 则完全看不见（休眠点透明度 0、靠宿主遮住，用户实测"两边 nodeIdle 都没有作用"），两个键都删掉了；`PALETTE` 现在 6 个键，每个都能在画面上指出来。★ 中途我曾把这条误读成"平时也该带一点段落色"并加了 `nodeTint` 混合，结果整圈都变成段落色，用户指出"现在全部都成乐句颜色了"，已回退 —— **平时的点必须是它自己的颜色**。★ **点不再画描边**（用户："音符点不要描边"）：`stroke` 固定 `none`，`--graph-node-stroke` 与图例上的描边一并删除。★ **音名的字色也在调色板里**（用户："音符点的字色也要在这里"）：`labelInkLight` / `labelInkDark` 是**两个候选**，`labelInkFor()` 按 `nodeBase` 挑对比度更高的那个，所以把 `nodeBase` 换成亮色也不会糊；想让字色固定就把两个候选写成同一个色值。实测深色 `#52525b` 挑白墨（7.73:1）、浅色 `#C2C2C2` 挑深墨（9.95:1），临时把浅色 `nodeBase` 改成亮黄 `#FFCD04` 后自动翻成深墨（11.80:1），渲染出来的 `fill` 与内部状态一致。实测八种组合（两套主题 × 四段）：平时恒为 `nodeBase`、刚响恒为本段段落色、`stroke` 恒为 `none`、flash=0.5 落在两者中点（深色 A 段 `#9342ad`）；
  - **踩到的顺序坑（本轮）**：把"音名墨色"接进 `applyTheme()` 之后整页视觉直接不建起来 —— `applyTheme()` 在脚本中段就被调用一次，而它间接用到的 `mixRgb` 声明在更后面，于是 `Cannot access 'mixRgb' before initialization`。修法是把 `mixRgb` / `rgbToHex` 提到颜色常量之前（与"edge.rest 在边创建之前算"那次是同一类问题）；探针里表现为 `ensurePhraseGraph is not defined`（脚本中断，后面的声明全没执行）；
  - 段落色：`PALETTE.dark.sections` / `PALETTE.light.sections` 各四个（A/B/C/D）；换一整组色时按**色相最近一一对应**，不要凭感觉指派；

## 0.2 背景 texture

环境层取自 Moodist，目前包含 Brown Noise、Wind in Trees、Jungle、Birds、Busy Street 与 Crowd。Jungle 使用官方 `public/sounds/nature/jungle.mp3`，作为较长的自然底层随机出现，而不是随每个乐句触发。

- texture 使用由演出种子派生的独立 RNG；增加、删除或加载失败都不会改变钢琴的 Markov 行走路径。
- 各层按照自己的出现周期、持续时间和概率调度，并以 5–9 秒淡入淡出；同一时刻最多保留两层，避免环境声掩盖钢琴。
- Jungle 当前周期为 75–145 秒、持续 28–58 秒、出现概率 0.62、目标增益 0.14；听感调整优先改这些参数，不改乐句与段落结构。
- 音效采用并行加载和单项 12 秒超时。某一素材失败时只跳过该层，不阻塞整首作品启动。
- `schedule()` 启动 texture 调度；`end()` 停止播放并清理 Transport 事件；`deactivate()` 释放 Player、Filter、Gain 与 Panner，避免再次播放时复用已停止资源。

## 0.2 视觉与交互

- 马尔可夫状态网络占满窗口并保持响应式居中；节点代表音高，箭头代表素材中存在的转移。
- 节点只有“当前”与“非当前”两个状态。刚弹过的节点逐渐退回非当前色，不额外保留第三种历史状态。
- 乐句历史是网络下方的静态 z 层；新乐句从视窗底部进入，将旧行平滑向上推。移动端历史位于上半屏。
- A/B/C/D 四类乐句分别使用紫、绿、橙、粉色，节点高亮、活动边和乐句文字保持同一主题色。
- 点击舞台可显示或隐藏 HUD；HUD 包含标题、播放控制、状态、图例和机制说明，不参与网络布局。
- 音频由 Transport 预排，视觉只在 `Tone.Draw.schedule(..., audioTime)` 到达实际发声时刻后更新，避免 lookAhead 造成提前高亮。

## 机制说明

```
乐句库（10 句，分 4 段：安静/主题/发展/结尾）
→ 段落感知马尔可夫链：段落层按转移矩阵选段（主循环 A→B→C→A），句层段内选句
→ 每 32 步选择一种演奏版本播放乐句（完整/骨架/回声/迟到回应）
```

- **音符 100% 来自素材**（记忆），**段落与乐句顺序被概率重组**（重排）——听感是"同一首曲子每次演奏段落顺序不同"
- **段落感来自素材结构**：原版 301 秒谱面含 intro→主题→发展→结尾的性格差异，马尔可夫链保留了段落衔接规律；本练习用 10 个带段落性格的乐句 + 段落转移矩阵模拟
- **留白来自演奏方式**：句尾会自然降密度，双音只在较满版本保留；C 发展段之后会短暂降低整体密度，让段落有回落
- 段落转移矩阵实时显示在页面上，可观察"当前段落 → 下一段落"的概率
- 换一版（新种子）改变行走路径；改 `SECTION_TRANSITIONS` 可调整段落性格（如让发展段更常回落安静）
