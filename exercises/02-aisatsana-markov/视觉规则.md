# 马尔可夫状态图 · 视觉规则（规范）

这份文档是 **02 Aisatsana Markov 状态图视觉系统的完整规则**，也是把它复用到其它练习时的说明书。
参考实现：同目录下的 `0.3/index.html`（单文件，视觉代码集中在「视觉」一节）。
⚠️ `0.4/` 目前是 0.3 的**逐行副本**（需求待定），所以 0.4 也遵循这份规则；
等 0.4 的改动落地后，这里要改成"参考实现 = 0.4"，并把与 0.3 的差异写进 §13 那种"最小改造清单"式的条目。
只读这份文档 + 参数表，就能在别处重新实现同一套观感；不需要读源码。

> 本文件属于**练习专有文档**，所以放在练习目录内（与 `README.md` 并列），不放在仓库根部的 `notes/`；
> `notes/` 只放跨练习的源码阅读与创作方法论。

> 设计目标一句话：**一场演出只有一张图，乐句更替不是"重画"，而是这张图自己变形。**

## 1. 心智模型

| 概念 | 含义 | 对应实现 |
| --- | --- | --- |
| 状态（节点） | 一个音高。节点集合 = **所有段落用过的音高并集**，建一次、永不重建 | `GRAPH_NOTES`、`ensurePhraseGraph()` |
| 转移（连线） | 素材里出现过的一次「当前音 → 下一音」。同样预建，之后不增删 DOM | `graphMotion.edges` |
| 当前段落 | 决定**哪些**音高与转移此刻在场 | `applyPhraseVisual(section, …)` |
| 当前音符 | 刚发声的那一个音（节点染色 + 走过的边行进） | `showVisualNote()` |

推论（都是硬性要求）：

- 换句时**不允许**清空或重建 SVG（`replaceChildren` 之类）；
- 段落只影响「存在度 / 明度 / 颜色」，不影响图的身份；
- 节点与连线是长期对象，跨乐句、跨段落、甚至跨"停止—再播放"都保留。

## 2. 分层与遮挡（z 序 = DOM 顺序）

```
defs（箭头 marker + 每条边的渐变）
藏身层   chain-hidden-layer   ← 非在场节点都在这里，永远画在最下面
灰边层   chain-edge-layer     ← 灰色转移线（明度=概率，方向=沿线渐变）
行进层   chain-pulse-layer    ← 彩色行进覆盖层
在场层   chain-node-layer     ← 在场节点；压在所有藏身点之上
涟漪层   burst-layer          ← 环境层 birds 出现时的那一发（0.4 新增；见 §14.6）——
                                不参与这张图的力学，只是画在最上面，元素随生命结束即移除
```

- 节点在**藏身层 / 在场层之间搬动**（`layer.appendChild`），所以"藏起来的点"必然被在场点遮住；
- **搬动会重启动 CSS 过渡**，因此节点的半径 / 透明度 / 颜色 / 音名可见性**一律由 JS 逐帧写入内联样式**，不依赖 CSS 过渡；
- 由此可见，节点相关的 CSS 只保留字体与 `stroke-width` 这类静态声明。
- 涟漪层**按需创建**（第一次起爆时才 `appendChild`，因此它天然排在最上），且永远不参与节点/连线的力学。

## 3. 时间基准：一切时长都来自音乐，不写死

这是整套规则里最关键的一条。四个时间量：

| 符号 | 定义 | 现值 / 钳制 | 用途 |
| --- | --- | --- | --- |
| **I**（音程） | 当前音的发声时刻 − 上一个音的发声时刻 | `clamp(I, 0.16, 1.5)` 秒 | 彩色行进时长、音点"亮→暗"时长、箭头亮起的时刻 |
| **M**（时长基准） | **本句内部第一个音程**（首音 → 第二个音） | `clamp(M, 0.32, 1.6)` 秒 | 换句整段结构变化的时长尺度（连线生长/收回、节点飞行） |
| **F(音高)** | 该音高本次飞行的时长 | `clamp(M × 2.0 × s, 0.6, 2.2)` 秒 | 节点弹出 / 滑位 / 收起 |
| **s**（速度倍率） | 按音高固定的个性化速度 | `0.8 ~ 1.25` | 让各点速度不同，不齐步走 |
| **提前量** | 重组相对首音的时刻 | `MORPH_LEAD_S = 0.05` 秒 | 避免视觉比听感晚一帧 |

- `s` 用**黄金比小数**打散：`s = 0.8 + 0.45 × frac(midi(音高) × 0.61803398875)`。
  ⚠️ 不要用哈希低位（`hashSeed(note) % 1000`）：音名相近时低位会撞在一起，实测 14 个音高只出 9 个不同倍率，速度差被压扁。
- **重组必须在"本句首音"那一刻开始，不能在它之前的空白里跑。**
  ⚠️ 这里踩过一次坑：早期版本把窗口定义成"上一个乐句最后一个音 → 本句首音"，而那段区间**按定义里面没有任何新音**（上一个音已经是最靠近首音的一次触键），而且句尾越稀这个窗口越会顶到上限 —— 实测变换总长 2.2 秒里有 **约 73% 的时间没有新音**，观感很"干"。改成"从首音开始、时长跟随本句内部第一个音程"之后，密句里 0.6–0.8 秒、常见间隔约 1.0–1.5 秒，**全程都有音乐**。
- 由此不再需要跨乐句保存"上一句最后一个音的时刻"这类状态：时长基准全部来自本句已排定的音符。
- **允许飞行延伸到首音之后**。不要加"点必须在首音之前到位"这类硬约束 —— 那会把速度逼得很快（且会重新把变换推回无音区间）。
- 第一个音没有"上一个音"可参照：用 `FIRST_NOTE_INTERVAL_S = 0.5` 秒兜底（行进与点亮都用它）。
- **M 直接从本句已排定的音符里算**（首音与第二个音的 `audioTime` 之差），不依赖任何跨乐句状态，也不要在视觉回调里读"上一个音"——播放时那些回调可能还没跑到。
  （历史：早期版本确实需要一个跨乐句的"上一句最后一个音的时刻"，用来算首音之前的空白有多长；改用"本句内部第一个音程"当基准后这个状态已经删掉了。）

## 4. 节点状态机

状态由"是否在场"和"本次角色变化"决定；`present` 与过渡是两件事。

| 状态 | 触发 | 位置 | 半径 | 透明度 | 颜色 | 音名 |
| --- | --- | --- | --- | --- | --- | --- |
| 休眠 | 不属于当前段落且过渡结束 | 紧贴宿主背后（偏移 3px） | 9 | **0** | `nodeBase` | 0 |
| 在场（乐句点，平时） | 属于当前段落，过渡结束 | 环位（`home`） | 17 | 1 | `nodeBase` —— **点本来的颜色** | 1 |
| 当前（刚发声） | 刚发声 | 同上 | 17 | 1 | `mix(nodeBase, 本段落色, flash)` —— flash=1 时就是**本段落色** | 1 |

**颜色是两个状态、两种来源**（用户 2026-09 的原话："乐句点有本来的颜色和被激活的颜色（跟随乐句颜色）"）：

- **本来的颜色** = `PALETTE[*].nodeBase`，一个键，不随段落变（深色 `#52525b` / 浅色 `#9a9a9e`）；
- **被激活的颜色** = **本段落色**，是算出来的、不是配出来的：`fill = mix(nodeBase, sectionColorRgb, flash)`，
  flash 由该音的 **I** 决定衰减时长（§3）。所以"激活色"跟着换段、跟着主题自动走，没有也不该有独立的配置项。
- 中间态就是这两者的线性插值（实测深色 A 段 flash=0.5 → `#9342ad`，介于 `#52525b` 与 `#d332ff` 之间）。

⚠️ 曾经把这条读成"平时也该带一点段落色"，于是加了 `nodeTint`（`mix(nodeBase, 段落色, tint)`）——
结果整圈都变成段落色、"本来的颜色"看不见了，用户直接指出"现在全部都成乐句颜色了"，已回退。
**不要再往这个方向改**：平时的点必须是它自己的颜色，段落色只属于"被激活"那一刻。
另一个已删掉的键是 `nodeIdle`：休眠点透明度是 0、靠宿主遮住，它只在过渡途中经过，
用户实测"两边 nodeIdle 都没有作用" —— 调色板里每个键都要能在画面上指出来，否则就是误导。

**点不画描边**（用户 2026-09："音符点不要描边"）：形状全靠填充色与底色/连线的关系分出来，
所以 `.chain-node` 的 `stroke` 固定是 `none`，也没有 `--graph-node-stroke` 这个变量；图例里那个点同样没有描边。

**音名的字色就是 `PALETTE[*].labelInk` 一个键**：压在**点本来的颜色**（`nodeBase`）上，
只有对比度低于 `LABEL_INK_MIN_CONTRAST = 3` 时才退回"白墨 / 深墨"里更清楚的那个并在控制台点名 ——
既不会糊，也不会静默地替用户做决定。
⚠️ 曾经做成"浅墨 / 深墨**两个候选** + 自动挑对比度高的那个"，结果用户把那两个键读成了
"浅色主题的字色 / 深色主题的字色"，两边各填了一组同明度的值，于是两套主题里音名都糊在点上
（实测深色 `#18181b` 压 `#414149` = 1.8:1、浅色 `#ffffff` 压 `#C2C2C2` = 1.6:1）。
**键名必须说清"它是什么"**：一个明确的值 + 一条报警，比两个需要猜的候选好用。

过渡（三种"飞行"，都占 `F(音高)` 时长）：

| 过渡 | 何时 | 缓动 | 说明 |
| --- | --- | --- | --- |
| `pop` | 休眠 → 在场（刚变成乐句点） | `easeOutBack`（`WAKE_BACK = 2.0`，单次过冲约 13%） | 起步速度约为平均的 5.7 倍；**过冲只发生一次**，到位后不再来回 |
| `glide` | 在场 → 在场（本来就是乐句点，只是环位被微扰） | `easeInOutCubic` | 平滑滑位、无过冲（它不是"飞过来"，只是换位置） |
| `retreat` | 在场 → 休眠 | `easeOutCubic` + 透明度 `1 − easeInCubic(t)` | **滑到宿主背后被挡住**：前段几乎全亮（看得出在移动），末段迅速淡掉，而末段正好是钻进宿主背后的时刻 |

补充规则：

- 染色（"当前"状态）：`flash = 1` 后**线性**衰减到 0，时长 = 该音的 **I**。所以音密处一闪即暗、留白处余韵长；
- 染色只改填充颜色（`nodeBase → 段落色` 之间多走完 `1 − nodeTint` 那一段），不改半径与位置，也不再改描边（没有描边了）；
- 休眠节点的宿主 = **离它环位最近的在场节点**；宿主若也转入休眠则重新指派；
- 不允许"原地淡出消失"：那会被看成 bug（用户实际报过"有点突然不见了"）。
- ⚠️ 收起缓动**不要用 `easeInOutCubic`**：它前段太慢，实测换句后 0.15 秒只走 0.4px，观感像"愣在原地"；`easeOutCubic` 同样时间走 24px。

## 5. 连线状态机

| 状态 | 表现 |
| --- | --- |
| 不存在 | 透明度 0 |
| 生长中 | 用 `stroke-dashoffset` 从一端揭示到另一端 |
| 就位 | 移除 dash 属性（实线）、明度 = 概率；**没有箭头**，方向靠沿线渐变读（见 §5 第 9 条） |
| 行进中（被走到） | 彩色覆盖层沿曲线扫过；**箭头骑在彩色头部**（或到点后停在终点） |
| 收回中 | 反向生长（几何逆放），**全程保持满透明度** |

关键规则：

1. **生长只由"有新点冒出来"触发**：一端刚变成乐句点的转移，**朝那个新点**生长过去。
   - 新点在**起点端** → 从终点端反向长过来（`stroke-dashoffset` 取**负值**）；
   - 新点在**终点端** → 从起点端长出去（正值）；
   - **两端本来就是乐句点** → 不做生长动画，直接画满（"连线只是跟着点移动"）；
   - 两段落都有的连线完全不动（幂等：`setEdgePresence` 对目标状态早退）。
2. **收回 = 反向生长**，不是消失、也不是透明度递减：起点端收起就朝终点端退，反之亦然。
   - ⚠️ **退场的线在几何收回完成之前，alpha 不能先变成 0**。02 踩过这个坑：`applyPhraseVisual`
     发现某条转移不再属于本段落时，顺手把它的概率明度写成 0，而 `updateEdgePresence` 又把明度
     每帧写进 `opacity` —— 于是**收回过程整个是看不见的**（几何在缩、画面上什么都没有），
     用户看到的是"激活的连线被透明度抹掉"（2026-09 反馈，实测：收回途中 presence 0.653、alpha 0）。
     正确做法：明度只在"它属于本段落"时才更新，退场时保留上一次的明度，等 presence 到 0 再由
     `updateEdgePresence` 统一压到 0（此时几何也是空的，不会看到突变）。
   - 收回途中没有箭头（常规连线本来就没有；彩色层跟着摘掉它自己的，见第 7 条）。
3. **时长与点同步**：连线的生长/收回直接用**它自己那个点**的 `F(音高)`；两端都是新点时取平均。这样"线长满"与"点到位"落在同一帧。
4. **常规（灰）连线不挂箭头**（用户 2026-09："去掉常规连线的箭头，显得很乱"）：`marker-end` 从头到尾都是空的；
   方向改由**渐变**表达（第 9 条）。旧版这里是"画满之后才挂上箭头"，那套连同 `syncEdgeArrow` / `edge.arrowOn` 一起删了。
5. **画满后把 dash 属性整个移除**：节点一直在呼吸漂移，留着 dash 就得每帧重算路径长度。
6. **明度 = 马尔可夫转移概率**：
   - `walkNote` 是从当前音的后继数组里**等概率**挑一个（重复项即权重），所以
     `p = 该转移出现次数 ÷ 该起点音的后继总数`；
   - `opacity = EDGE_OPACITY_MIN + (MAX − MIN) × p = 0.16 + 0.56 × p`（线性；本素材里 p 跨 0.07–1.0，线性比开方对比更强）；
   - 不属于当前段落的连线明度为 0。
   - ⚠️ **透明度只能有一个来源：元素的 `opacity`**。不能把明度写进 `stroke-opacity` ——
     实测（见 §11 的标定）：描边的不透明度**传不到箭头上**（描边 0.8 / 元素 1 时，线 0.800、箭头 1.000），
     而元素的 `opacity` 会作用到 marker 上（元素 0.9 → 线 0.719、箭头 0.900）。曾把 0.8 写在 CSS 的
     `stroke-opacity` 上，于是"线"和"箭头"各按一套规则变暗，永远对不齐；现已把 0.8 折算进上面两个常量
     （屏幕上线的明度和以前一模一样，箭头则跟着线走）。
7. **彩色行进的时长 = 该音的 I**（不是固定值）：颜色从起点走到终点。
   **箭头只属于"激活的连线"**（常规连线没有箭头，见第 4 条）：生长/反向生长时它骑在彩色头部上（第 7 条下面的细则），
   颜色到位后交给"停在终点的那支"，也就是**行进层自己的箭头**。要点：
   - 行进层描边 2.4，所以它**不能**直接复用 `markerUnits="strokeWidth"` 的那支箭头（会放大 **2.18 倍**，
     用户报过"箭头过大"）；因此另建一支 `markerUnits="userSpaceOnUse"`、长度写成绝对值的同款箭头
     （`#arrowhead-pulse`）—— 标定实测两者 bbox / 尖端位置 / 末尾高度 / 像素面积**完全一致**，且不再随描边宽度变化；
   - **箭头跟着"正在移动的头部"走，不是停在目的地等曲线过来**（用户 2026-09 的要求）：
     颜色还在行进或反向生长时，箭头骑在**彩色区间的正向端**上，**箭头底边正好压在那一点**；
     方向始终**沿曲线正向（= 过渡的方向）**，而且取的是**头部处的局部切线**
     （用一小段重算的折线承载 marker，靠 `orient="auto"` 得到）——
     曲线是带弯曲的，头部切线 ≠ 结尾处的朝向，这就是"方向算自曲线、不能固定成结尾朝向"的含义。
   - **反向生长时箭头要掉头指回起点端，但必须"绕头部慢慢转过去"**（用户 2026-09 的第二轮反馈；
     第一轮我曾把它整段删掉，被否了）：方向角 θ 从 0（沿曲线正向）爬到 π（掉头），
     `u = 切线·cosθ + 法线·sinθ`（切线/法线都取头部处的局部值）—— 于是箭头像罗盘指针一样绕头部扫过去，
     而**底边中点始终钉在头部**上，转向过程中线的端点一直落在箭头身体里。
     转速：转向时长 = 这次高亮的时长 `pulse.duration × HEAD_ARROW_TURN_RATIO(0.6)`，
     钳制在 `HEAD_ARROW_TURN_MIN_S(0.22) ~ HEAD_ARROW_TURN_MAX_S(0.5)` 秒 —— 跟音乐同长同短。
     ⚠️ **绝不能"一帧翻过去"**（旧版就是每帧直接按状态取正/反向，等于瞬间 180°，用户原话："不要一瞬间转回去"）。
     ⚠️ 也绝不能固定角度、或固定成结尾处的朝向。
     ⚠️ **一定是"箭头底边落在头部"，不是"尖端落在头部"**：参考点是底边中点，
       所以折线的末端就取在头部上；这样 ① 线头藏在箭头较宽的身体里（不会从旁边露出来）；
       ② 颜色到位时这支箭头与"停在终点的那支"逐点重合，交接不会"往前弹一下"
       （早期版本把尖端放在头部上，于是线头露一截、交接时位置差 8.8）。
     ⚠️ 彩色层要用**平头**描边（`stroke-linecap: butt`）：圆头会让彩色比算出来的端点再多伸 1.2，
       行进时那截正好藏在箭头身体里，但反向生长时箭头在头部**前面**，这 1.2 就会露出来。
     实现：每条边多一个 `.chain-head` 路径（描边不可见、`stroke-opacity: 0`，只用来承载 marker；
       marker 的 fill 是 `context-stroke`，实测**不受 stroke-opacity 影响**，所以描边不显示、箭头照常显示），
       每帧把 `d` 重算成"头部前 `HEAD_ARROW_BACK = 12` 个用户单位的一小段"。
     ⚠️ **取样顺序必须从后往前排到头部**：marker 的朝向取自**路径末端那一小段的方向**，
       顺序写反会让箭头正好掉头 180°（02 实测 `dotWithTangent = −1`，改回 +1）。
     ⚠️ **一条边同时只显示一支箭头**：颜色还在走时，终点那支先不挂（否则就是"在目的地等着"）；
       头部停下（颜色到位）后收起骑行箭头，改由停在终点的那支负责（明度与线一致）。
       ★ 自从常规连线不再有箭头（第 4 条），"底边箭头"这一半已经不存在了：
       现在只有"骑行箭头"和"行进层停在终点的那支"两种情况，两者都是**激活线**的箭头。
   - 箭头**方向与位置都算自曲线**：位置 = 彩色区间的正向端 `end`；方向 = 该点的切线。
     ⚠️ 不要用"路径末端"以外的固定参照物（比如节点的连线朝向）来定向 —— 曲线是带弯曲的二次曲线，
     端点朝向与头部朝向可以差很多。⚠️ 也不要提前把箭头挂在行进层上：marker 永远画在路径末端，
     dash 揭示不会挪动它（那是"颜色还没到箭头先亮"）。
   - **彩色层永远不能比灰线长**：它的可见区间 = 扫过区间 `[0, reveal·L)` ∩ 灰线的可见区间。
     灰线正在生长时（`presence < 1`）尤其重要，否则彩色会浮在"还没有线"的位置上。
     实现（两个区间求交后写成一个 dash）：
     ```
     灰线可见区间 = presence ≥ 1 ? [0, L)
                  : revealFromEnd ? [(1−presence)·L, L) : [0, presence·L)
     彩色区间     = [灰线起点, min(灰线终点, reveal·L))     // 交集为空就写 dasharray "0 L"
     dash 写法：起点为 0 时用旧形式 "L L" + offset = L − end（**与旧实现完全等价，视觉零变化**）；
                起点 > 0（灰线从终点端长出来）时用 "段长 L" + offset = −start 表示中间一段。
     ```
     ⚠️ 灰线**收回**时彩色层跟着一起反向生长，并且**全程保持满透明度**、不推进退场计时；
     收完（`presence = 0`）时高亮直接结束。旧版让彩色层保持满长、只靠 1.2 秒退色消失 ——
     换句时看起来就是"激活的连线被透明度抹掉"，而不是跟着线退回去（用户 2026-09 反馈）。
   - **被下一条转移取代时，高亮也走"反向生长"，不是退色**（用户 2026-09 的规则：
     "所有连接线的出现/消失都要生长/反生长的动态，而不是透明度控制"）：
     揭示区间从全长**缩回 0** —— 终点端先消失、起点端最后消失，即沿原路退回去；
     时长与它走过来时相同（`pulse.duration` = 该音的 I），全程满透明度。
     这条线本身还在场，只是不再是"当前转移"，所以这里退的是**高亮**而不是线：
     两者都必须由几何表达，不能一个几何一个淡出。
8. **参考点取箭头底边的中点（`refX = 0`），线尾就停在箭头最宽的那条底边上**（只作用于**激活线**的箭头）：
   marker 的 `refX/refY` 就是"路径末端落在箭头的哪个位置"，所以这一条规则同时解决两件事 ——
   - 线尾**不可能**从收窄的锥面里露出来（用户报过"连接线超出了箭头"；旧版 `refX = 7` 时实测线尾处箭头宽度
     只有 **1.10**，恰好等于线宽 1.1，线头是齐平的）；
   - 线尾也不会与箭头**重叠**（也就不需要在别处补偿 `refX`：那是上一版的 `ARROW_TAIL_INSET = 3.2` 做法，已删除）。
   `ARROW_TIP_GAP = 2.9`（尖端离节点边缘）、`ARROW_TAIL_OFFSET = 11.7`（路径末端离节点边缘）与旧版实测一致：
   **底边 28.7px、尖端约 20px（离目标节点圆心）**。⚠️ 常规连线虽然不挂箭头，路径末端**仍然**留出这 11.7 ——
   `edgeGeometry()` 只算一份几何给底边与行进层共用（两份几何会让彩色浮在灰线旁边），
   而留出的这段由渐变的暗端吃掉（第 9 条），所以看不出"线被截断"。
   - 标定实测：`refX = 0` 时线上的点、线尾附近的点、箭头身体内部的点**同为 0.502**（单层、无叠加）；
     缺了这条规则就要靠"把线尾藏进箭头身体里"，多一条补偿链就多一处会失准的地方。
   - ⚠️ 元素 `opacity` 会把**描边与 marker 合成一个透明组**：组内重叠（线尾压着箭头）不会叠乘变实，
     所以"箭头比线更实"这种担心在同一个 path 内不成立；真正会叠乘的是**别的元素**
     （比如另一条连线恰好也压在这个像素上，见 §11 第 8 条的提醒）。
9. **常规连线的"方向"由沿线灰度渐变表达**（用户 2026-09："能否用渐灰度代替箭头的方向"）：
   每条边在 `defs` 里有一条**自己的** `linearGradient`（`gradientUnits="userSpaceOnUse"`），
   轴 = 这条边的**弦**（起点端 → 终点端，每帧跟着点更新），两端用 `stop-opacity` 做浓度差：
   `edgeFadeFrom`（起点端，默认 1）→ `edgeFadeTo`（终点端，默认 0.3）。
   - **默认"起点亮、终点淡"**：这样终点端那 11.7 的"箭头位"正好被渐隐吃掉，不会显得线被截断；
     想反过来就把两个数对调（`0.3 / 1`）—— 两个方向都读得出方向，选哪个是手感问题。
   - 渐变只沿**弦**插值（SVG 的 `linearGradient` 不能沿曲线走）；线是弯的，但两端浓度差足够明显。
   - 这条路与"明度 = 概率"是**两个独立通道**：元素 `opacity` 管整体明度（概率），
     `stop-opacity` 管线内两端的差（方向），互不干扰。
   - ⚠️ **轴的起终点必须和路径用同一份几何**（`edgeGeometry()` 同时返回 `d` 与轴），分开算会让两者错开。
   - ⚠️ **自环（本素材有 1 条：`C3|C3`）必须特殊处理**：起终点同一个点会让 `x1,y1 == x2,y2`，
     按 SVG 规范**整条渐变不渲染** → 那条线直接消失。自环改用它那圈"上抛"的两端当轴。
   - ⚠️ `stop-color` **不能**写 `currentColor` / `context-stroke`（那只在 marker 里有效），
     所以墨色由 JS 从 `PALETTE.edge` 写进去；换主题时 `applyEdgeInk()` 遍历所有渐变更新颜色与两端浓度。

## 6. 力学：让"弹"沿连线传开

换句时的动感**不是整环缩放**（那看起来像充气），而是扰动沿连线传导：

- 换句瞬间给在场节点一次**切向**冲量（方向按索引交替），大小分两级：
  `PHRASE_KICK = 8.5`（约 26px 行程）、段落切换 `SECTION_KICK = 12.5`（约 38px）；
- 每次发声给该节点一次**很轻**的切向推力：`NOTE_KICK = 1.7`（约 5px）。
  两级必须差约 5:1，否则听不出"换句"这个重音；
- 连线同时是弹簧（"铰链"）：`EDGE_COUPLING = 0.012`，**静止长度 = 环上的原始距离**，
  所以环的平衡位置不变，边只负责把运动传给邻居；
- 阻尼 `NODE_DAMPING = 0.92`：太小扰动传不出去，太大变成乱抖；
- 环位弹簧 `NODE_HOME_SPRING = 0.009`、推挤 `NODE_REPULSION = 900`、漂移 `NODE_DRIFT = 0.038`。
  ⚠️ 这三个是**同比例**的：静态偏移 = 力 ÷ 弹簧，只调其中一个会让整张图变松。

**跨度与形状：每句的分布必须不一样，但依据只能是这一句的音乐 —— 不许用随机数。**
（用户 2026-09："不想让每一句的音符点分布在视觉上完全固定，每次要不一样，但整体逻辑还是要有的；
 不要随机，完全的随机毫无意义。" 旧做法是每次换句取一个 ±0.1 弧度 / 0.95–1.05 倍的随机微扰 ——
 可复现、但**没有依据**，而且幅度小到每句看起来几乎一样。）两条规则：

| | 依据 | 做法 | 效果 |
| --- | --- | --- | --- |
| **A 朝向** | 本句**首音** | 把首音的槽位转到**正上方**，但**每句最多转半个槽位**（`RING_ORIENT_STEP`） | "这一句从哪个音开始"一眼可见；首音会在几句之内逐渐转到正上方 |
| **B 半径** | 本句每个音的**发声次数** | 半径 × `1 − RING_ACTIVITY_PULL(0.22) × 活跃度`（活跃度 = 本句该音次数 ÷ 本句最高次数） | 每句的点分布成为一张不同的"密度云"：内圈 = 这句的骨干，外圈 = 在场但没用上的可能 |

- ⚠️ **A 必须限速**：直接把首音一次摆到正上方，环会一次转 0~154° —— 实测本素材的乐句首音是
  A: C3/C3、B: C4/C5/C4、C: C3/C4/E4、D: C5/E4（槽位 1/5/7/11），C4↔C5 差 6 个槽位，
  最远那颗点要跑约 **720px**，比原来的 19~39px 快一个量级。限速后每句位移 ≤ **≈90px**（实测最大 87.1–90.8px、平均 67px）。
  ★ 这与"箭头掉头要慢慢转"是同一条原则：**转向要有过程，不要一瞬间翻过去**。
- ⚠️ 两条都必须**确定性**：同一段音乐必然画出同一张图（实测同一形状重算两次，所有环位偏差 **0.000px**）。
  所以视觉侧**不再需要任何随机流**（`visualRng` 已删除）；若将来又要给视觉加随机，仍须从种子派生独立流。
- 环位槽点自身还留一点按 index 的固定抖动（`RING_SLOT_JITTER = 0.04`）让环不是机械正圆；
  ⚠️ 不要放大它（过去是 ±12%，会盖过"活跃度"这个真正的信号）。
- `layoutGraph()` 仍要重算所有环位**以及连线弹簧的静止长度**（不重算的话边弹簧会把位移拉回去，实测只剩 16% 偏移）。

## 9. 与音频的接口

- 音频事件由 `Tone.Transport` 预排；**视觉只在 `Tone.Draw.schedule(..., audioTime)` 到达实际发声时刻才更新**，
  否则 lookAhead 会让视觉提前于声音；
- 换句重组（`applyPhraseVisual`）安排在同一时刻**之前**的 `M` 秒开始，正好在首音收尾；
- 视觉侧现在**完全不用随机数**（环的朝向与半径都由本句的音乐算出，见 §6 的"跨度与形状"）；
  若将来又要给视觉加随机，必须来自**独立随机流**（由演出种子派生），
  ⚠️ 绝不能消耗钢琴 / texture 的那条 RNG，否则同一个种子的音符序列会因视觉改动而变化；
- 停止播放（`end()`）只收回"当前状态"（染色 / 行进），**图本身保留**，下次播放接着同一张图。

## 10. 明确禁止（都是被否掉过的做法）

| 禁止 | 原因 |
| --- | --- |
| 每句 `replaceChildren()` 重建 SVG | 过渡没有起始状态可补间，布局被重置，句界硬切 |
| 用"整环缩放"做弹力 | 看起来像充气外扩，而不是通过连线传导的活力 |
| 给边的弹簧设**绝对**理想长度（如 170–280px） | 会把环整个撑开、平衡点偏移 30px 以上 |
| 节点的透明度 / 半径交给 CSS 过渡 | DOM 搬动会重启动过渡；且 CSS 规则会覆盖 SVG 呈现属性 |
| 用 `setAttribute('opacity', …)` 去点亮元素 | 只要样式表里有同名 `opacity`，画面就永远不可见（实测踩过） |
| 把 `markerUnits="strokeWidth"` 的箭头挂到粗描边的行进层上 | 箭头会随 `stroke-width` 放大（实测 2.18 倍）；要挂就另建一支 `userSpaceOnUse` 的同款箭头 |
| 给**常规（灰）连线**挂箭头 | 用户 2026-09："去掉常规连线的箭头，显得很乱" —— 几十条边各带一个箭头时画面全是三角；方向改由渐变表达 |
| 用 `stroke-opacity` 表达连线明度 | 它传不到箭头（fill）上，于是线一个明度、箭头另一个明度 |
| 把渐变轴和路径**分开**算 | 两份几何会让渐变和线错开；`edgeGeometry()` 必须同时给出 `d` 与轴 |
| 给自环用"起点 → 终点"当渐变轴 | 两端重合 → `x1,y1 == x2,y2` → 按 SVG 规范**整条渐变不渲染**，那条线会直接消失 |
| 在几何收回**之前**把退场连线的明度清成 0 | 收回过程会整个看不见 —— 看起来就是"激活的连线被透明度抹掉" |
| 让彩色层保持满长、只靠退色消失 | 线已经缩回去了，彩色还停在原处，换句时像"被透明度擦掉"而不是"退回去" |
| 用 `opacity` 让**任何**连线元素（底边 / 高亮）出现或消失 | 连线的出现/消失一律走几何：生长 / 反向生长；透明度只用来表达"概率明度"这种静态量 |
| 用 `applyPhraseVisual` 顺手清零不属于本段落的 `edge.opacity` | 同上：那条线还要走一次反向生长 |
| 把箭头固定挂在路径末端（颜色还在走时就等在那儿） | 用户明确否掉："箭头一直在目的地等着曲线过来" |
| 给箭头用固定角度 / 结尾朝向定方向 | 曲线是带弯曲的，头部朝向必须算该点的**局部切线** |
| 让箭头"一帧翻过去" | 转向必须看得见：绕头部扫过去、时长跟这次高亮挂钩（实测 0.6s 高亮 → 0.36s 转完 180°） |
| 干脆不让箭头掉头（第一轮试过，被否） | 用户明确说过"回退箭头转向回退的方向是对的" |
| 骑行箭头的取样点顺序写反 | marker 朝向取自末端那一小段，写反会正好掉头 180°（实测 −1） |
| 彩色层用圆头描边 | 比算出来的端点再多伸 1.2；反向生长时那截会露在箭头外面 |
| 把"箭头只要挂在底边上"当规则 | 线是两层（底边 + 行进层）叠出来的，箭头只挂一层就会"线实心、箭头半透明" |
| 只看内部字段 / 单点像素就宣布"两条元素明度一致" | 采样点可能被**别的连线**压着（实测 2.9px 外那条把像素叠到 0.92） |
| 给"点到位"加硬性时间上限 | 会把飞行速度逼快 |
| 收起时原地淡出 / 瞬间消失 | 应"滑到宿主背后被挡住" |
| 速度倍率用哈希低位打散 | 音名相近时会撞值，等于没打散 |
| 视觉随机混进音乐 RNG | 同一种子的音符序列会变 |
| 用**没有音乐依据**的随机数决定布局（哪怕可复现） | 用户明确否掉："不要随机，完全的随机毫无意义"；每句的变化要用首音与活跃度这类本句的音乐量 |
| 把"首音摆到正上方"一次性摆过去 | 实测会一次转 0~154°、点跑 720px；必须像伺服一样限速（每句 ≤ 半个槽位） |

## 11. 验收清单（可量化，别只看"感觉应该对"）

1. **不重建**：切换段落后，节点的 `dataset` 标记仍在，`svg.childElementCount` 不变；
2. **时间基准**：给定音程 0.6 秒 → 行进时长 0.600 秒；给定时长基准 M = 0.35 / 0.8 / 1.4 秒 → 生长与收回时长**分别等于它们**；本句内部第一个音程 0.3 / 0.6 / 0.9 / 2.4 秒 → M = 0.32 / 0.60 / 0.90 / 1.60 秒（末项被钳到上限）；
3. **重组与首音同刻**：重组安排在"首音 − `MORPH_LEAD_S`"，变换期间有音乐在响（旧版约 73% 落在无音区间，属于 bug 级观感问题）；
4. **线与点同步**：某条朝新点生长的连线时长 == 它对应节点的飞行时长（逐帧核对完成时刻在同一帧）。注意判断"谁刚被激活"要用**前后在场集合之差**，不能用"有没有飞行"——保持不变的节点也有 glide 飞行；
5. **收起是被遮挡**：收起过程中"不透明度高 + 距离在缩短"，结束时离宿主 ≤ 6px、半径为 9、透明度 0；
6. **不是外扩**：换句后全环**平均半径**变化应远小于单点切向位移（实测切向 27.3px / 半径变化 4.8px）；
7. **线与箭头同明度**（只针对**激活线**，用像素量，不要只看内部字段）：同一状态里取"线中段的像素"与"箭头身体内部的像素"（底边往里 3px），两者的明度差应在抗锯齿噪声内（实测：最暗那条转移正在走彩色时 **`(139,92,246)` vs `(139,92,246)`**，差 0）。
   ⚠️ **量之前先查这个像素附近有没有别的连线**：48 条边都汇到少数几个节点，实测 `C4|G3` 从采样点旁 **2.9px** 处穿过（明度也是 0.72），于是像素被叠乘成 `1−(1−0.72)² = 0.92` 而不是 0.72，差点误判成"箭头更实"。做法：对每条在场连线采样 160 个点，算它到被采样点的最小距离，列表一起打出来。
8. **箭头几何**：路径末端距目标节点中心 = `R + ARROW_TIP_GAP + ARROW_LENGTH`（28.7px）、尖端 ≈ 20px；两支 marker 的 `refX` 都是 0（参考点在底边中点）；**常规连线的 `path.marker-end` 必须恒为 `null`**；行进层的箭头在颜色到达前必须是 `null`、到达后是 `url(#arrowhead-pulse)`；`getComputedStyle(path).strokeWidth === EDGE_STROKE_WIDTH + 'px'`（确认 CSS 没有覆盖）。
   标定页（独立于练习、只用 4 条路径）应能测出：同一个 `refX = 0` 几何的三种声明（`userSpaceOnUse` / `strokeWidth` 单位 / 换描边宽度）**线、线尾、箭头内部同为 0.502**，且两支箭头的 bbox / 尖端 / 末尾高度 / 像素面积一致。
9. **常规连线的方向渐变**：`path.style.stroke` 与 `getComputedStyle(path).stroke` 都应是 `url("#…-grad")`；每条边的渐变 **两端 `stop-color` = `PALETTE.edge`、`stop-opacity` = `edgeFadeFrom` / `edgeFadeTo`**；**轴的起点必须与路径 `d` 的第一个坐标一致**（可以用 `getPointAtLength(0)` 核对）；把某个点挪 40px 后轴的对应端必须跟着动；**48 条边的轴都不能退化**（`x1==x2 && y1==y2` → 那条线不渲染；02 实测自环 `C3|C3` 是唯一需要特殊处理的一条）。
10. **可见性一律读 `getComputedStyle`**，不能只读属性值；
11. **换句时"退场的连线"是收回、不是淡出**（用像素或逐帧快照量，别只看代码）：让一条**不属于下一段落**的转移先走到彩色到位，再执行一次 `applyPhraseVisual`，逐帧记 `presence / dashoffset / opacity`：
    - 退场线（灰底边）：`presence` 逐帧下降、`dashoffset` 同步增大，**`opacity` 全程保持它原来的概率明度**（02 实测 0.496，收回途中一帧都没变），`presence=0` 那一帧才变 0；
    - 它的彩色层（若它就是被走到的那条）：dash 区间**与灰线逐帧相同**（02 实测 offset `89.81487141927084` vs `89.81487141927083`）、**`opacity` 全程 1**、箭头在收回途中为 `null`，灰线收完时 `pulse.active=false`；
    - 对照（修复前）：收回途中灰线 `opacity` 已经是 **0**，而彩色层保持满长、`opacity` 1 直到 1.5 秒后才开始退色 —— 这正是"被透明度抹掉"的观感来源。
    - **高亮退场也是几何**（被下一条转移取代）：让一条**留在本段落**的转移先走到彩色到位，再对另一条边 `startEdgePulse`，逐帧记彩色层区间与 `opacity`：02 实测区间 `256 → 231.8 → 204.1 → 176.4 → 148.8 → 121.1 → 93.4 → 65.7 → 38 → 10.4`（0.576 秒内线性缩回 0，速率 ≈ L ÷ I）、**`opacity` 全程 1**、`marker-end` 在退场开始即为 `null`；退完 `active=false`。旧版这里是 `opacity` 从 1 降到 0（`EDGE_SWEEP_FADE_S = 1.2`，该常量已删除）。
    - **箭头跟着头部**（骑行箭头、`headPath`）：逐帧记「彩色区间正向端 `end`」与骑行箭头的 `d`，并**独立算一遍曲线在 `end` 处的切线**再和箭头方向求点积：
      02 实测行进时 `dotWithTangent = +1`、反向生长**转完之后**是 `−1`；转的过程中夹角要从 0° 爬到 180°
      （02 实测 8ms 一帧：`4 → 8 → … → 176 → 180`，0.36 秒转完，单调、没有一步跳到底）；
      箭头**底边到 `end` 的距离 0.00–0.01**、**尖端到 `end` 的距离 8.8**（= 一个箭头长度：底边压在线的端点上、尖端伸到前面）；
      同时 `path.marker-end` **恒为 `null`**（常规连线没有箭头）、`pulsePath.marker-end` 在行进中也是 `null`（一条边同时只有一支箭头）；
      颜色到位后骑行箭头收起、`pulsePath.marker-end = url(#arrowhead-pulse)`（这就是"激活线的箭头"）。
      反向生长退完后两者都回到 `null` —— 旧版这里是"底边箭头挂回来"，现在底边不再有箭头。
      ⚠️ 点积算出 ≈0 就说明方向算错了（垂直于曲线）；反向生长时**一帧就跳到 −1** 说明转向过程没了。
      ⚠️ **线头必须被箭头盖住**：在头部前后沿**法向**取一串点，量横向被上色的范围 —— 线是 2.4、箭头底边 8.8。
      02 实测（反向生长中）`k=-2 → 2.5`、`k=-1 → 2.5`、**`k=0 → 8.5`**、`k=+1 → 7.5`、`k=+2 → 6.5`、`k=+4 → 4.5`、`k=+8 → 0.5`：
      头部那一刀是箭头底边（8.5 ≈ 8.8）而不是裸线（2.5），说明线端被盖住、没有线头露在箭头旁边。
      （调头的那一版在这里是 `k=0 → 2.5`，线头直接暴露 —— 就是用户看到的现象。）
      ⚠️ **交接不能有跳变**：用 4ms 细步逐帧记录"箭头底边到静止位置的距离"，应当**线性单调减到 0**
      （02 实测 `12.11 → 10.39 → 8.66 → 6.94 → 5.22 → 3.49 → 1.77 → 到位`，每帧步长恒为 1.72）。
      若最后一帧的落差明显大于其它帧，就是"箭头往前弹一下"（早期把尖端放在头部上时，落差整整多出一个箭头长度）。
    ⚠️ 读 dash 区间时注意**两套约定**：`updateEdgePresence` 用 `"L L"` + 正 offset（区间 `[0, L−offset)`），`updateEdgePulse` 表示"中间一段"时用 `"段长 L"` + 负 offset（区间 `[−offset, −offset+段长)`）。只按其中一种解码会把另一种读成 0。
11. **响应式（见 §12）**：任意视口下环的**屏幕**跨度 ≈ **0.68W × 0.63H**（只统计在场节点，所以略小于理论的 0.72/0.64），
    节点**屏幕**半径 = `17 × scale`，两者的比值（间距 / 半径）稳定在 10–15；且 `scale === 1` 当且仅当视口 ≤ 1100×700（旧观感不变）。
    量的时候要用 `getScreenCTM()` 把设计单位换算成屏幕像素，不能直接读节点坐标。
12. **`f` 键全屏**：按下后 `documentElement.requestFullscreen()` 被调用（已全屏时调用 `exitFullscreen`），
    `defaultPrevented === true`；焦点在种子输入框里时**不触发**；`fullscreenchange` 后 `viewBox` 必须已按新视口重算。
    无头环境下进不了真全屏，做法是把 `requestFullscreen` / `exitFullscreen` 换成记录调用的假函数、
    并用 `Object.defineProperty(document, 'fullscreenElement', …)` 模拟"已全屏"（测完还原）。
13. **无头验证**：`rAF` 在无头环境被节流，需 `requestAnimationFrame = () => 0` 后手动逐帧调用 `animateGraph()`；
    CSS 过渡的动画时钟也不前进，要读目标值需先把 `style.transition` 置为 `none`；
    探针页用完删除。**Chrome 的 stdout 在无头下可能拿不到**：让探针页用 `fetch('/__report?line=…')` 把结果发给本地静态服务器，从服务器日志里读，比 `--dump-dom` 稳。
    页面内部的常量都是**顶层 `const`（不是 window 属性）**：必须用 `iframe.contentWindow.eval('…')` 在它自己的全局作用域里跑，直接在探针里写 `w.graphMotion` 会拿到 `undefined`；
    而且 eval 出去的代码在 **iframe 自己的作用域**里执行，探针页的局部变量（如视口尺寸）在那边不存在 —— 要么把数值写进字符串，要么在 iframe 里自己量。

## 12. 视口与响应式：内部坐标用"设计单位"，整张图等比缩放

**问题**（用户 2026-09 反馈："窄屏下很好，宽屏下四周的空白都太大了"）：环的半径曾经写了两条**绝对上限**
（`min(380, W*0.36)` / `min(330, H*0.32)`），窗口一大就再也不长 —— 实测 2560×1440 的窗口里只有
**760×660** 的一圈（横向只占 30%、纵向 46%），四周全是空的。

**规则**：

- 环的半径**只按视口比例**算：`radiusX = W × RING_FILL_X(0.36)`、`radiusY = H × RING_FILL_Y(0.32)`，
  于是横向占 **72%**、纵向占 **64%**，与窗口大小无关（只在极小窗口用 `RING_MIN_RADIUS` 止损）。
- 视觉内部的坐标**不是 CSS 像素，而是"设计单位"**：`viewBox` 写成设计尺寸（= 窗口尺寸 ÷ scale），
  由浏览器把整张 SVG 等比放大。`scale = clamp(sqrt(窗口面积 ÷ 参考面积), 1, GRAPH_SCALE_MAX)`，
  参考 1100×700、上限 2.5。
  - **下限 1** 是关键：参考尺寸以内的窗口 `scale = 1`、设计尺寸 = CSS 尺寸，**渲染结果与改造前逐像素一致**
    （用户认可的窄屏观感一点没变）；
  - 更大的窗口整体放大 —— 环、节点、音名、连线粗细、箭头尺寸、弹的幅度**全都按同一比例**，
    不会出现"环变大了但点还是 17px"的割裂。
  - ⚠️ **不要逐个常量乘系数**：那样必须有人记得同时改节点半径、隐藏半径、宿主偏移、音名字号、箭头长度、
    描边宽度、冲量……漏一个就割裂。用 viewBox 缩放是一次性的、不可能漏。
  - 由此，间距/半径（观感密度）与视口无关：实测 10.3 / 13.0 / 13.0 / 13.2 / 13.2 / 14.2 / 14.6。
- **HUD 是 HTML 覆盖层，故意不缩放**（CSS px，保证文字始终可读）；要让它也随窗口变，就在 CSS 里引入
  `--ui-scale`，不要把它塞进 SVG。

实测（每个视口单独跑一次探针，量的是**在场节点**的屏幕坐标）：

| --- | --- | --- | --- | --- | --- | --- | --- |
| 390×844 | 1.00 | 390×844 | 271×534 | 0.70 | 0.63 | 17.0px | 10.3 |
| 1100×700 | 1.00 | 1100×700 | 744×443 | 0.68 | 0.63 | 17.0px | 13.0 |
| 1440×900 | 1.30 | 1110×694 | 974×570 | 0.68 | 0.63 | 22.1px | 13.0 |

每点微扰，所以最外圈那两个位置不一定有点。这是正常的，不是 bug。）

**换视口时的连续性**：`updateGraphViewBox(true)`（`resize` 与 `fullscreenchange` 都会调用）先把每个点
按设计尺寸的变化等比挪一下，再由 `layoutGraph()` 重算环位，其余交给弹簧 —— 所以从窗口切到全屏是"整张图
平滑地放大并重新站位"，不是硬切。

**`f` 键全屏**：`keydown` 里判断 `f`/`F`，跳过带修饰键的情况，并且**焦点在输入框（`INPUT`/`TEXTAREA`/
`contenteditable`）里时不处理**（否则种子输入框里打不出 f）。全屏的是整个文档（HUD 与控制还在）；
想只看画面就再点一下画面隐藏界面（这两件事故意不合并，全屏 ≠ 隐藏界面）。浏览器要求全屏由**用户手势**
触发，键盘事件算手势，所以不需要额外按钮；`requestFullscreen()` 返回的 Promise 要 `catch` 掉
（被拒绝时别在控制台留未捕获错误）。

## 13. 复用到新练习时的最小改造清单

1. 定义你的**对象集合**（长期存在的节点/边）与**状态来源**（这里是段落 + 当前音）；
2. 找出你的**音乐时间量**，把它们代入 §3 的四个公式（若没有乐句概念，就用最近的两次事件间隔当 I）；
3. 抄 §2 的分层与 §4/§5 的状态机；
4. 力学按 §6 起步，先跑一次离散模拟确认峰值与稳定时间，再写进代码并在注释里留下"k / 阻尼 → 过冲 / 稳定"；
5. 视口按 §12：内部坐标用设计单位 + viewBox 缩放，半径只按比例算 —— **不要给半径设绝对上限**；
6. 配色按 §14：画面颜色集中在 JS 的 `PALETTE`、由 `applyTheme()` 推成 `<html>` 的内联 CSS 变量（CSS 里不再声明它们），浅色不是把色阶对调，而是**对齐对比度**；
7. 按 §10 逐条避免禁区，按 §11 逐条验证。

## 14. 配色与主题（深色 / 浅色）

深色是默认，也是这个练习的身份。HUD 控制面板右上角有一个 light/dark 按钮（`#themeToggle`），
图标与 `shared/exercise-controls.js` 那套一致（24×24 viewBox、`fill:none`、`stroke` 继承 `currentColor`、
`stroke-width: 2.4`），所以看起来是同一套图标。★ 图标表达的是**"点了会变成什么"**（深色时显示太阳），
不是"现在是什么"；`title` / `aria-label` 用动词（"切换到浅色"），`aria-pressed` 表示当前是不是浅色。

### 14.1 单一来源：画面颜色集中在 JS 的 `PALETTE`，页面 chrome 在 CSS 变量

用户 2026-09 要求把"非激活点 / 音符字 / 连线 / 背景色"这些变量和段落色**写到一块**（"我边看边调"），
所以**画面上的颜色**集中在 `0.3/index.html` 里那段带 `★★` 的 `PALETTE`（两套主题各一份）：

| PALETTE 的键 | 推成的 CSS 变量 | 控制什么 |
| --- | --- | --- |
| `stageBg` | `--stage-bg` | 画面底色（`.markov-stage`） |
| `edge` | （不推；写进每条边的渐变 stop） | 未激活的连线的墨色 |
| `edgeFadeFrom` / `edgeFadeTo` | （不推） | 连线渐变**两端**的浓度 = **方向**（起点端 / 终点端；对调就反过来，见 §5 第 9 条） |
| `nodeBase` | `--graph-node-base` | 乐句点**本来的颜色**（平时那些点，以及图例里那个灰点） |
| `labelInk` | （不推，JS 直接用） | 音名的字色；压在 `nodeBase` 上对比度低于 3:1 时退回白/深墨并报警（见 §4） |
| `sections[4]` | `--section-color`（取 `sections[0]` 垫底） | A/B/C/D 段落色 = **被激活时的颜色**（又当连线高亮、又当图例里那个彩点、又是日志文字色） |

点的颜色**没有**独立的变量（逐帧算，见 §4）。

流转方向是**单向**的：`applyTheme()` 把 `PALETTE[主题]` 的值用 `setProperty` 写到 `<html>` 的内联样式上，
CSS 规则照旧 `var(--stage-bg)` / `var(--graph-edge)` 取值；段落色另外由 `tweenSectionColor()` 逐帧插值写进
`.markov-stage` 的内联变量。节点颜色因为要**逐帧用 RGB 三元组插值**（`paintNode` 的 `mixRgb`），
由 `applyTheme()` 直接把 `PALETTE` 的值转成数组（`NODE_IDLE_FILL` / `NODE_PRESENT_FILL` / `NODE_PRESENT_STROKE` 因此是 `let`）。

两条必须遵守的规矩：

1. **CSS 里不要再声明这几个变量**（`--stage-bg` / `--graph-*` / `--section-color`）。
   内联样式优先级高于样式表，写在 CSS 里不但不生效，还会让人以为"改了没反应" —— 这在"边看边调"时最坑。
   页面 chrome（`--bg / --panel / --fg / --dim / --line / --hairline / --log-fg / --code-* / --control-*`）
   与画面无关，仍在 `<style>` 的两个变量块里，各写一份。
2. **颜色只有一个来源**：绝不能把同一个量在 `PALETTE` 和 CSS 各写一份（会半截切换：面板变白了、环上的点还是黑的）。
   这与"明度只能有一个来源"（§5 第 8 条）是同一类错误，本练习踩过两次。

另外，手改调色板时**打错色值不能让整张图坏掉**：`hexToRgb()` 只接受 `#RRGGBB`，
`applyTheme()` 与 `tweenSectionColor()` 对非法值一律**跳过并 `console.warn` 点名是哪个键**、保留上一个合法颜色
（否则一个字符的笔误就会让节点填充变成 `#NaNNaN`）。

### 14.2 首帧之前定主题

`<head>` 的第一段脚本读 `localStorage['gml-theme']` 并写 `document.documentElement.dataset.theme`：
主题必须在**首帧之前**应用，否则选了浅色的人每次打开都会先闪一帧深色。
写入（点击时）与读取都包在 `try` 里 —— `file://` 与隐私模式下 `localStorage` 会抛错，失败就按默认深色。
**默认深色、不跟随系统 `prefers-color-scheme`**；`color-scheme` 属性跟着主题一起切（影响滚动条与原生控件）。

### 14.3 浅色不是"把色阶对调"，而是"对齐对比度"

第一版按 zinc 色阶镜像取值（500→400、600→300……），结果整张图发虚：实测**节点几乎融进底色**
（浅色 1.34:1，而深色是 2.51:1），连线的墨色也从 4.02:1 掉到 2.33:1。原因是"反差"由纸和墨的**明度差**
决定，单纯把浅色主题的灰调浅、等于同时把墨也调浅了。现在的规则：

- **墨色不随主题变**：连线在两套主题里都是 `#71717a`（反差由纸提供，不由墨提供），
  于是连线对比度两边一致（4.02:1 / 4.40:1），最淡的概率线也一致（1.15:1 / 1.21:1）；
- **节点灰度按对比度取值**：浅色的收起/在场节点是 `#b3b3b8` / `#9a9a9e`，
  分别对齐深色的 1.86:1 与 2.51:1（实测 1.90:1 / 2.55:1）；
- **音名颜色要跟着节点走**：深色用白字（白压 `#52525b`），浅色的节点本身偏暗，所以用 `#18181b`；
- 纸（`--stage-bg`）与面板（`--panel`）的相对关系保持不变：面板永远比页面底色"亮一档"。

验收要**同时**量两套主题的这几组对比度（探针里 `getComputedStyle` 读变量再自己算 WCAG 比值），
只看"切过去了没有"会漏掉"切过去之后糊了没有"。

### 14.4 已知待办（属于"调整配色"的下一步，尚未定）

**日志文字用段落色当墨**，浅色主题下偏虚：`#00c896` 压在 `#f4f4f5` 上只有 **1.97:1**、
`#ff8a00` 2.15:1（对照深色主题：绿 14.19:1、粉 7.58:1、橙 6.94:1、紫 6.06:1，都够用）。
两条路：①给浅色主题一套压暗过的段落色；②日志正文改用 `--fg`、段落色只留作标记。
**这两条都是配色判断，等用户定**，不要自行选一条改掉。

### 14.5 段落色也分主题，对应关系按"同色系"

两套段落色分别在 `PALETTE.dark.sections` 与 `PALETTE.light.sections` 里（`sectionColors()` 按当前主题取一组）。
CSS 里的 `--section-color` 默认值也由 `applyTheme()` 从 `sections[0]` 推出来，**CSS 里不再写死**
（否则没播放时图例上那个点会是另一套的颜色）。

**换一整组色时的做法 = 同色系一一替换**（用户："当前如果有蓝色，就用这组色值中的蓝色，其它也是一个意思"）。
2026-09 那一次把浅色的紫 / 绿 / 橙 / 粉换到深色那组，按**色相最近**对应：

| 段落 | 原色（浅色主题仍用） | 深色主题新色 | 色相距离（次近的候选） |
| --- | --- | --- | --- |
| A 紫 | `#8b5cf6` 258° | `#CD62EC` 287° | 29°（次近是蓝，35°） |
| B 绿 | `#00c896` 165° | `#03FE5F` 142° | 23°（次近是蓝，58°） |
| C 橙 | `#ff8a00` 32° | `#F67602` 29° | 3°（次近是红，32°） |
| D 粉 | `#ff2876` 338° | `#ED8199` 347° | 9°（次近是红，22°） |

新色里的**蓝 `#0248FD` 与红 `#FE0000` 在这个练习里没有对应物**（原四色里既没有蓝、也没有纯红），
所以暂时没用上 —— 要用得先决定给谁，不要随手安到某个元素上。

**切主题时要把"当前段落的颜色"重新插值过去**（`tweenSectionColor(sectionColors()[currentVisualSection])`），
否则画面会停在旧主题的那个色上、直到下一次换段才纠正；插值时长沿用 `SECTION_COLOR_MORPH_S`，
因为"颜色永远不跳变"这条规则对主题切换同样成立。

★ 三处必须注意的细节：

1. **这段不能写进 `applyTheme()`**：它在脚本中段就会被调用一次，而 `tweenSectionColor` 那时还没声明（TDZ）。
2. **`currentVisualSection` 必须是顶层状态**（由 `applyPhraseVisual` 写、初始 0）。⚠️ 2026-09 的 bug 就是把这里
   写成了 `currentSection` —— 那个名字**在顶层根本不存在**（两处 `let currentSection` 分别在段落链工厂与
   `activateEngine` 内部），于是点击按钮时抛 `ReferenceError`。而它正好是 handler 的**最后一句**，
   所以症状不是"按钮坏了"，而是**半切换**：背景、面板、点、连线全换了，只有段落色（也就是刚发声的点、
   彩色连线、图例彩点、日志文字）停在旧主题上 —— 用户报的原话是"切换 light/dark 只有背景变，
   其它颜色没有跟着变化"。★ 教训：**主题切换这类"整组状态"的代码，最后一句不能裸奔** ——
   现在这段包了 `try` 并在失败时报警 + 退回 `sections[0]`，不会再变成静默的半切换。
   验收也要盯住"最不显眼的那一类颜色"（段落色只有在换段或发声时才明显，最容易漏测）。
3. **已经打印出来的日志行也要重新着色**（`repaintLog()`，用户 2026-09："打印的乐句颜色没跟上吧"）：
   日志每行按**它所属段落**的颜色着色，而这个色是分主题的 —— 只在打印那一刻取一次色的话，
   切主题后老行会一直留在旧主题的配色里。做法：`logLines` 里存**段落号 + 当前 RGB**（不是颜色字符串），
   切主题时**逐行**从自己的旧色插值到新主题里同一个段落的色，时长同样用 `SECTION_COLOR_MORPH_S`。
   ★ 注意不能复用 `tweenSectionColor`：它插的是"**当前**段落色"这一个值，而每一行有它自己的段落。
   实测：暗→亮时四行分别 `#624DFF/#8DFE03/#FF7904/#FA2251` → `#FFC228/#2558FF/#FF741E/#45C674`，
   切回去逐字复原；切完之后新打印的行直接用新主题的色。

**色值是手调的，所以只保证"机制"不变、不锁死数值**：上表那次换色只是当时的一次操作，
现在的值以 `PALETTE` 为准。校验方式是**手动驱动帧逐段走一遍**（无头环境 rAF 不可靠，见 §11），
读 `--section-color` 内联值与 `sectionColorRgb`；换色后至少要确认：每个段落落到本主题 `sections[i]` 的值、
切主题时当前段落跟着换、节点点亮染色与图例点跟着走（三处都读的是同一个 `--section-color`）。
手调时也可以顺手量一下"段落色直接压住底色"的对比度 —— 它同时是**日志文字的颜色**，
深色底上 5:1 以上才舒服，浅色底上要更小心（见 §14.4）。

### 14.6 环境层涟漪（birds 发声期间的一群"旋转游走的线"）

**性质**：这是 0.4 新增的一层，**不属于这张状态图**（不参与节点/连线的力学），
它是"某一层环境音开始发声"这件事在画面上的回声；一段鸟叫里会出现**好几次**。

**参考出处（这个效果的来源，0.4 版）**：

| --- | --- |
| 作者 | **okazz**（OpenProcessing user 128718） |
| 作品 | **「240809a」**，用 p5.js 1.10.0 写的，2025-04-07 |

**触发**：`createMoodistTextures` 的 `options.onStart(texture, time, duration)` —— 一个**纯通知**回调，
只在某层**真的开始发声**时触发一次；视觉侧 `onTextureStart()` 判断 `name === 'birds'`（用户："只给 birds"）。
★ 通知必须走 **`Tone.Draw.schedule(..., time)`**：那个回调是预排的（lookAhead 会提前执行），
只有 Draw 到达 `time` 那一刻才是真正听到声音的时刻（与 §9 同一条规矩）。

**一段鸟叫里来好几发，不是只开场一发**（用户 2026-09 的第二轮要求："不要只在开始的时候，
在 birds 发声的过程时不时出现"）：`onTextureStart` 不直接起爆，而是**按这一层的节奏排一串** ——

| | 依据 | birds 的取值 |
| --- | --- | --- |
| 第一发 | 层开始的**那一帧** | 立刻（鸟叫一响就有反应）；**它也可以成簇** |
| 击发间隔 | 该层 `fade × BURST_CADENCE_FADE_RATIO(0.9)`，钳到 3–6 秒，再叠 ±`BURST_CADENCE_JITTER(0.22)` 的种子抖动 | 4.5s ±22% |
| 排到什么时候 | 这一响**还能听到**的时间窗 = `duration + fade`；每发至少 `BURST_IN_WINDOW_RATIO(0.5)` 的扩张落在窗内 | 25s 的鸟叫（窗 30s）→ **7 次击发** |
| **一次击发是几发** | `BURST_CLUSTER_CHANCE(0.55)` 的概率**不是 1 发而是一簇 2–4 发**（`BURST_CLUSTER_EXTRA(1–3)`），成员在 `BURST_CLUSTER_SPREAD_S(1.1)` 秒内散开 | 25s → 2 次单发 + 5 次成簇 = **17 发** |

**几发同时在场**（用户 2026-09 第四轮："**允许同时发射几个，而不是明显一个接一个的出现**，
这也是为了贴近鸟鸣的随机感"）。三条要点：
① **簇的成员位置必须各不相同** —— `pan` 只当**锚点**（"这层的声音偏右，画面就偏右"这条关系保留），
在它附近再加 `BURST_X_JITTER(0.13)` 的横向抖动，否则几发会叠成一个点（实测 `fx = 0.486–0.728`，锚点 0.605）；
② **先把整段鸟叫的击发时刻算完再排**（`offsets` 数组），这样簇的成员和它所属那次击发一起确定，
不会出现"排到一半被打断"；③ 簇成员的寿命是 1–4 秒，而簇内间隔 ≤1.1 秒，所以它们**必然同时可见**。
实测：12 段鸟叫的"同时在场发数"峰值 **4,4,4,4,4,3,4,4,4,4,4,4**（均值 3.9）；相邻击发间隔 **0.04–4.64 秒、均值 1.69 秒**
（旧版是 4.5 秒等距）—— 不是队列。

**一发内部也不再"一个接一个地冒出来"**：参考是**一次性全部创建**（`addObjs()` 里 20+50+2+10 个对象同一帧出生，
差异全来自各自的随机寿命），所以这里把各元素起始时刻的抖动收到很小：
圈 `BURST_RING_STAGGER_MAX_S(0.25)`、线 `BURST_ORB_STAGGER_MAX_S(0.12)`、痕 `BURST_SPARKLE_STAGGER_MAX_S(0.18)` 秒 ——
实测一发里最后一个元素最晚 **0.244 秒**启动（旧版 0.5–0.8 秒），一发就是"一下炸开"。

后续几发同样用 `Tone.Draw.schedule(…, time + offset)` 排在**音频时刻**上，所以视觉与"听到鸟叫"始终同源；
停止播放时 `end()` 里的 `Tone.Draw.cancel(0)` 会把还没到的那些一起取消。

**形态：主体是"旋转 + 游走"的线（`Orb`），涟漪圈只是锚** —— 这一段记的是**返工**，因为它踩了一个很典型的坑。
第一版按"元素**数量**"把参考砍成 3 圈同心环 + 6 根等分放射线，用户 2026-09 直接否掉：

> "太大了，形态也不好，完全没抓住参考中好的地方，需要那种旋转游走的线，现在的特别呆，每一个都一摸一样"

复盘参考（一发 82 个对象）才看清它的构成比例：**20 根公转中游走的线**（`Orb`）+ 50 颗飞散星点（`Sparkle`）
+ **只有 2 圈**涟漪（`Ripple`）+ 10 个旋转小几何（`Shapes`）—— **主体是那些线，涟漪圈只是个锚**。
第一版恰好留了锚、把主角当噪声删了，还自己发明了 6 根 60° 等分的放射线（参考里根本没有），
于是既"呆"（同心圆不旋转、不游走、几何完全对称）又"一摸一样"（发内每个元素形状相同、每发只有色相微差）。
★ **教训：借鉴形态时要按"哪个动作制造了那个观感"来留，不能按"元素数量多不多"来砍。**

`Orb` 的动作就是参考里那三行，也是整个"活"的来源：

| 参考的写法 | 含义 | 这里的做法 |
| --- | --- | --- |
| `this.ang += this.angStep` | **自转**：绕自己的中心转，角速度大小与方向逐个随机 | `ang(τ) = ang0 + angSpeed·τ`，`angSpeed ∈ ±6–18 rad/s`（= 参考的 0.10–0.30 rad/帧 × 60fps），方向随机 |
| `this.x += this.xStep; this.y += this.yStep` | **游走**：中心朝一个随机方向慢慢漂走 | `centre(τ) = 爆点 + 方向 × 速度 × τ`，速度上限 `ringR × BURST_ORB_DRIFT_RATIO(1.6)`，方向每根随机 |
| `this.pos.push(…); if (len > 10) splice(0, 1)` | 只留最近 10 个采样点，`show()` 把它们画成折线 | `<polyline>` 保留 9 个采样点，采样间隔固定 `BURST_ORB_TRAIL_STEP_S = 1/60` 秒 → 拖尾永远覆盖最近约 **0.13 秒**的轨迹 |

★ **所以它画出来的是一小段"扫过的弧"，不是一个圆**（实测折线总转角约 65°，远小于 360°）。
★ **运动写成解析式，不逐帧累加**：参考那三项（自转、游走、半径线性展开）本来就是线性的，等价于
`pos(τ) = 爆点 + 漂移·τ + R·min(1, τ/T)·(cos, sin)(ang0 + ω·τ)`。两个好处：① **与帧率无关**
（参考按帧累加，120Hz 屏上同一条拖尾只有一半长）；② 不用保存逐帧状态，仍从 `startedAt` 一次算出来 ——
和这一版其它部分一样"同一个输入必然同一帧画面"。验证办法：探针里**独立重算一遍这个解析式**，
再和 DOM 上折线的最后一个点比（实测差 **0.040px**），并对比"1 大步"与"30 小步"的 `points`（逐位相同）。
★ **每个元素的参数都不一样**（自转半径 / 角速度 / 游走方向与速度 / 寿命 / 描边 / 色相逐个取种子流）——
这是"不呆"的关键；实测一发 12 根线的这五项**各 12/12 各不相同**。
★ 参考的 `Shapes`（旋转的小方块/圆/叉）**先不加**：免得一发里东西太杂，而且用户要的是"旋转游走的**线**"。
★ 参考的 `Sparkle` 是"飞出去并闪烁的点"（p5 里逐帧 50% 概率重画）；这里改成**外飞的短痕**（`<line>`）：
本项目的规则是出现/消失都走几何，闪烁要写 opacity，不合规矩。

**调试入口：在点击处起爆**（用户 2026-09："增加一个调试，鼠标点击的时候就在点击来一发，不然还得专门等着"）。
birds 每 55–115 秒才出现一次，要调涟漪的观感就得干等，所以在 `.markov-stage` 上挂**第二条 click 监听**
（开关 `DEBUG_CLICK_BURST`，默认开）：**点画面任意位置，就在点击处炸一发**。三条规矩 ——

| | 做法 | 为什么 |
| --- | --- | --- |
| **参数同参** | 取 `MOODIST_TEXTURES` 里 birds 那一份传给 `spawnBurst(texture, at)` | 另写一组"调试用的数"的话，调出来的东西不是真鸟叫看到的那一发，这个入口就白加了（调试入门必须与被调试对象同参） |
| **位置** | 点击处 → 视口比例，用 `getScreenCTM()` 的**逆变换**，不是 `getBoundingClientRect()` 的比例 | viewBox 与元素尺寸在极端窗口下会有细微差别（宽高被 `Math.max(320, …)` 钳过、viewBox 取整）；CTM 是浏览器自己算的那一份 |
| **每下都不同，但不扰动真鸟叫** | 点一下就 `debugBurstIndex += 1`，用 `makeRng(f(序号))` 派生一条**独立**流传给 `spawnBurst(texture, at, rng)` | 第一版把调试发做成**完全固定**（理由写的是"方便改一个常量再点一次做对比"），被用户否掉 —— **形态的丰富度本身就是被调的对象**，把它固定下来就没法调它了。现在每下形态都不同，而"第 N 下"仍可复现（要对比改动就点同样几下、看第同样的那一下），且**不消耗 `burstRng`** → 点与不点都不影响真鸟叫那几发（调试不改变被调试对象，与"视觉侧不消耗 `textureRng`"是同一条原则） |

★ 它**不是**新的声音映射：`onTextureStart` 那条"只认 birds"一个字没动，这只是调试注入口。
★ 监听为什么挂在 `.markov-stage` 上：播放 / 种子 / 主题按钮所在的 `.hud` 是这个 stage 的**兄弟节点**
（`.visual-head` 与 `.legend` 才是它的子节点，那两处都是纯文字），所以点控件不会冒泡过去 ——
不需要额外判断 `event.target` 就能保证"点播放不会一边炸涟漪"。

**颜色是一族配色、不是单色**（用户 2026-09："要配色，不要单色"）：`shiftHue()`（RGB→HSL→转色相→RGB）
把**本段落色**按色相旋转，给**每个元素各取一份**色相（`hueBase ± BURST_HUE_SPREAD(42)`），
每一发再整体偏 `±BURST_HUE_JITTER(18)` 度（种子流）。实测一发 12 根线的颜色**12/12 各不相同**，
两圈与 12 道短痕也各取一份；整组**永远跟着段落色与主题走**（颜色逐帧算，不缓存）。
⚠️ 不用固定色值：一换主题/换段，固定色就会和画面其它部分脱节（用户要的是**配色**，不是"另一组固定色"）。

**每发都不一样：数量、大小、快慢都逐个分配**（用户 2026-09 第三轮："中间两个固定的同心圆还是很呆，
不一定永远有……还是太大了，包括生命值也一摸一样，这个就是想从观感上和鸟叫适配，有大有小，有快有慢"）。
上一版虽然已经是"每个元素各取参数"，但**结构本身还是固定的**，于是看起来仍然是同一发：

| 固定在哪 | 上一版 | 现在 |
| --- | --- | --- |
| **圈的数量** | 永远 2 圈 | **0 / 1 / 2 圈按权重抽**（`BURST_RING_NONE_CHANCE(0.30)` / `_ONE_(0.40)` / 其余两圈）—— "不一定永远有" |
| **两圈的关系** | 半径比写死 1 : 0.62、圆心都是爆点 → 一对同心圆 | 每圈**自己的圆心**（从爆点偏出去 `BURST_RING_OFFSET_MAX(0.55) × 外圈半径`）、**自己的半径**（`spread(0.7, 1.6)`）、**自己的起始时刻**（0–0.7 秒）、**自己的寿命**；实测同一发里两圈的半径比在 `0.72 / 0.99 / 1.00 / 1.24` 之间（旧版恒为 1.62） |
| **每圈/每根/每道的寿命** | 都以同一个 `grow`（= 该层 fade × 0.5）为中心、只在 ±15%~±30% 内浮动 | 各自从**宽区间**抽：线 `0.35–1.8 ×`、圈 `0.45–1.7 ×`、痕 `0.3–1.6 ×`；实测线寿命 **0.88–4.29 秒**、圈 **1.14–3.70 秒**、痕 **0.75–3.79 秒** |
| **数量** | 固定 12 根线 + 12 道短痕 | `BURST_ORB_COUNT_RANGE(7–16)`、`BURST_SPARKLE_COUNT_RANGE(5–14)`；一发总元素 **12–32 个**（= 圈 0–2 + 线 7–16 + 痕 5–14；旧版恒 26） |

★ **"有大有小、有快有慢"用一个偏置分配实现**：`spread(min, max) = min + (max-min) × rng() × rng()` ——
`rng() × rng()` 的均值约 0.25，分布**压向小端**（小的多、大的少），这才是鸟叫那种"多数很小、偶尔一声大"的样子；
直接用 `rng()`（均匀分布）时每个元素的大小仍然"差不多"，看起来还是"一摸一样"。
★ **"有快有慢"不靠另给一个速度上限，而是"一生走多远 ÷ 寿命"**：`travel = 外圈半径 × spread(0.25, 2.8)`、
`driftSpeed = travel / life`。同样远的行程、寿命短的就走得快；而且**总伸展因此有上限**
（若直接给"速度上限"，长寿命 × 高速度会让一根线跑到 400px 以外 —— 实测旧写法最远 181px、
按速度上限算则会长到 400px+）。实测游走速度 **2.55–92.90 px/s（36× 差）**、一生走 **9–92px**。

**规模与时长都由这一层的声音决定**（用户："大小和 birds 的声音关联"）：

| 量 | 依据 | birds 的取值 |
| --- | --- | --- |
| 整体尺度（= 外圈半径的基准） | 该层 `targetGain ÷ BURST_GAIN_REFERENCE(0.3)` 映射到 `BURST_RING_RATIO_MIN..MAX`（**短边的 2.3%–7.2%**） | gain 0.1 → **0.043 × 短边 ≈ 28px** |
| 其余所有尺寸 | 都是"外圈半径"的倍数（自转半径 0.50×、短痕距离 0.5–2.0×、一生行程 0.25–2.8×…），**再各乘一个偏置随机** | — |
| 时间尺度 | 该层 `fade × 0.5`，钳制 `BURST_GROW_MIN_S..MAX_S`（0.9–2.6 秒）；各元素寿命是它的 0.3–1.8 倍 | fade 5 → **2.5 秒** |
| 落点 | **在整块"安全区"里均匀抽**（安全区 = 视口四周各留"短边的 `BURST_EDGE_MARGIN(0.12)`"≈70px）；`pan` 只当**偏置**（`BURST_PAN_BIAS(0.28)`：把整发的落点分布往声像那一侧推一点） | birds → `fx 0.150–0.923`、`fy 0.127–0.880`（`pan +0.3` 让左边少用一点） |

**⚠️ 尺寸一律以"短边"为单位**：`unit = min(视口宽, 视口高)`，逐帧现算，元素里存的都是**比例**
（而不是"设计单位常量"）。参考整篇都建立在 `minSide` 上；这样换视口 / 全屏时整发按同一比例缩放，
不会出现"圈跟着变了、线没跟着变"的割裂（与 §12"用设计单位整体缩放"是同一条经验，只是这里的单位取自短边）。
★ **"太大了"被提了三轮**，每一轮都只动这一个基准（其余全是它的倍数，所以游走的观感比例没变）：
`90–260 设计单位`（birds 147 ≈ 视口高的 21%）→ `0.045–0.140`（49 ≈ 7%）→ `0.030–0.095`（36 ≈ 5%）
→ **`0.023–0.072`（约 28px ≈ 4%）**。验收量的是**整发墨迹的峰值**（从 0 推到寿命结束、每 0.1 秒取一次最大值）：
现在 **43 / 58 / 78px**（最小 / 中位 / 最大，= 视口高的 6.1% / 8.3% / 11.1%），上一版是**恒定的 85px = 12%**。

**形式参数**：0–2 圈涟漪（各自圆心偏移、大小、寿命、起始时刻）、8–15 根旋转游走的线
（拖尾 9 点、自转半径 `0.50 × 外圈 × spread(0.3, 1.5)`、展开 `BURST_ORB_GROW_S(0.45s) × spread(0.5, 1.6)`）、
5–14 道外飞短痕（生命的前 `BURST_SPARKLE_GROW_RATIO(0.25)` 把长度从 0 长到满）；
起始描边按短边取：圈 `0.0034`、线 `0.0022`、痕 `0.0016`（再各乘 `spread(0.6, 1.3)`）。

**必须遵守的三条既有规则**：① **出现 = 几何**（半径从 0 长出来，`r=0` 的圆本来就画不出来）、
**消失 = 描边细到 0 + 移除元素**，全程不碰 `opacity`；② **只读、不改图** —— 涟漪不参与节点/连线力学，
所以"同一段音乐画出同一张图"不被破坏；③ 颜色**逐帧算**（本段落色 → 色相偏移），所以换段/切主题时
整套配色跟着变，不需要另配颜色。

  证明那一下确实点到了控件（否则"没起爆"可能只是因为事件压根没发出）；
- 点击当帧图上的 14 个点坐标**一个都没变**（同 tick 比较，中间没有推帧）；
- **对图零副作用**：同一确定性序列跑 300 帧，带涟漪与不带涟漪得到**完全相同的节点/边 hash**
  （`1223802882 → -1186372183`）—— 这条要**两次独立运行对照**才测得准，单次运行里图本来就在呼吸漂移；
- 开销：涟漪层每帧约 **37.0–61.6 条 DOM 改动**（按一发 14–29 个元素而定；实测 8 发
  `18个→43.5`、`20个→37.0`、`21个→41.3`、`22个→48.5`、`26个→51.0/51.8/60.7`、`29个→61.6`），
  整张图稳态 **378–380 条/帧** → 在场时约 +10%~16%；
  一发 ≤4.3 秒，birds 每 55–115 秒才出现一次（一段里 4–7 发，所以画面上"时不时"就有涟漪）；停止播放时 `clearBursts()` 清空。
- ⚠️ 量 DOM 改动条数**必须 `mo.takeRecords()`**：在同步循环里 MutationObserver 的回调不会派发，
  直接读计数会得到 **0**（这一轮就踩了，第一版读数 0.0 差点被当成"零开销"）。
- ⚠️ 无头环境里 `performance.now` 与 `Date.now` **都被虚拟时钟冻结**（`--virtual-time-budget`），
  所以"毫秒级帧耗时"在这里量不出来 —— 改量 **DOM 改动条数**（MutationObserver），它是确定性的客观量。
- ⚠️ 探针里把 `requestAnimationFrame` 换成手动队列时，**只排空队列、不要再手动调 `animateGraph()`**：
  页面自己的循环每帧会再排一次队，两边都调就会指数增长（实测把 Chrome 跑到 120 秒超时）。

## 15. 随机性的使用判据（什么时候允许用随机）

> 用户 2026-09 的原话：**"不要随机的原则保留，允许在明确需要使用随机的时候使用"**。

这条原则是 0.3 那一轮为**状态图**定的（原话："不要随机，完全的随机毫无意义"：环上的位置与半径必须由
**这一句的音乐**算出来，不能用随机数凑）。**它不是"全局禁随机"** —— 哪些地方禁、哪些地方要，按下面这张表判：

| 对象 | 允许 / 禁止 | 理由 |
| --- | --- | --- |
| **状态图**：节点位置、半径、连线的存在与明度、各种时长 | **禁止随机** | 每个量都要能说出"它对应哪一段音乐"（首音槽位、发声次数、音程、转移概率…）。历史上那版 ±0.1 弧度的随机微扰已经被否掉 |
| **环境层的回声**（§14.6 的涟漪） | **允许、而且需要随机** | 它要对应的是**鸟叫的质感**，而鸟叫本身就是忽大忽小、忽快忽慢、没有两次一样；这里用确定性的几何反而错了（用户："这个就是想从观感上和鸟叫适配，有大有小，有快有慢"） |

### 15.1 允许的三个条件（缺一个就不算"明确需要"）

1. **有一个非随机的外框 —— 随机只负责"在这个范围里怎么分配"，不替代音乐决定的关系。**
   涟漪的**整体尺度**仍由该层 `targetGain` 定（相对 `BURST_GAIN_REFERENCE` 映射到 `BURST_RING_RATIO_*`）、
   **时间尺度**仍由 `fade` 定（`burstGrowSeconds`）、**位置**仍由 `pan` 定（当锚点，见下条）。
   即：外框由声音给出，随机只在框内分派。
2. **必须是种子派生的独立流，结果可复现。**
   用 `burstRng`，**不能**用钢琴的 rng、也**不能**消耗 `textureRng`（那会改变音频调度 —— 0.2 踩过）。
   同一条种子必然画出同一场演出；调试点击更要用**按点击序号派生**的独立流，
   这样"第 N 下"可复现、又不扰动真鸟叫那几发。
3. **判据是"这个量本来就该各不相同吗"。**
   是 → 用随机（每个元素的半径 / 转速 / 走多远 / 寿命 / 描边 / 色相）；
   不是 → 别用（凡是"本该跟音乐挂钩"的量，用随机就是偷懒）。
   ★ 注意**位置**这一项是"锚点 + 抖动"：`pan` 决定锚点（声音偏右 → 画面偏右），
   抖动只是让先后几发不叠在同一个点上（`BURST_X_JITTER`）—— 关系还在，只是不再逐发重复。

### 15.2 三条容易漏的补充

- **"每个元素各取参数"并不等于"每发都不一样"**：只要**结构**是固定的（永远两圈、半径比写死 1 : 0.62、
  圆心都是爆点、扩张共用同一个 `grow`），看起来仍然是同一发。所以"数量""圈的有无""圆心位置""起始时刻"
  这些**结构性的量**也必须逐发各抽（见 §14.6 的"每发都不一样"）。
- **分布的形状和随机本身一样重要**：`rng()` 是均匀分布，看上去仍然"每个都差不多"；
  `rng() × rng()`（均值约 0.25）把小端拉长，才有"小的多、偶尔一声大"的层次。
  要"有大有小"，光有随机不够，还要**偏置**。
- **"有快有慢"用"一生走多远 ÷ 寿命"反推速度**，不要另给一个"速度上限"：
  前者天然给总伸展设了上限，而且"同样远的行程、寿命短的就走得快"正好就是有快有慢；
  后者在"长寿命 × 高速度"时会让一个元素跑到 400px 以外（整发失控地大）。
