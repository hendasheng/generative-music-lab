# Exercises

每个练习使用独立目录，避免后续实验互相覆盖。

## 命名规则

```text
编号-英文短名称
```

例如：

```text
01-ambient-pulse
02-markov-melody
03-granular-texture
```

## 每个练习至少包含

```text
练习目录/
├─ README.md    # 学习目标、音乐规则、运行方式和后续想法
└─ index.html   # 可直接运行的入口
```

需要额外代码时，可以在练习内部增加 `src/`、`styles/` 或 `assets/`。同一练习需要保留多个实验版本时，使用 `0.1/`、`0.2/` 这样的子目录。只有多个练习确实共用的内容，才提升到仓库根目录，避免过早抽象。

## 三种文档，各管一事

这个仓库是边学边创作的，**「现在是什么」和「怎么走到这里」必须分开写**，否则同一份文件会同时承担现状、决策依据、逐轮实测和历史编年四种内容，读者得穿过几十 KB 才能找到当前参数。（2026-09-28 定：此前规则写「版本变化集中记录在练习 README」，实际长出了各版本自己的 README，同一练习的知识被劈成四份、互相埋住，所以改成下面这样。）

| 文档 | 职责 | 读者 | 建议规模 |
| --- | --- | --- | --- |
| `README.md`（必有） | **现行状态**：这是什么、怎么跑、当前版本、现行设计与参数表、关键设计决策（只留「为什么这样定」的结论）、怎么验证、未解决项 | 要改这个练习的人（含 AI）与自己复看 | ≤ 15 KB |
| `历史记录.md`（可选） | **编年史**：逐轮演进、当时为什么这么改、实测数字、被否掉的方案。只追加、不整理 | 想回顾学习过程时 | 不限 |
| `接入说明.md`（可选） | **跨项目契约**：带哪些文件、接口与参数、所有权与卸载责任、验收清单 | 要把它搬进别的项目时 | 不限 |

规则：

- **新练习只建第一份**；第二次出现「这一轮的实测/踩坑记录」时再建 `历史记录.md`，第三次出现「要搬到别处」时再建 `接入说明.md`。
- **版本目录（`0.1/`、`0.2/` …）不放任何说明文档**。版本说明属于该练习的 `README.md`（现状）与 `历史记录.md`（编年），不要在每个版本里各写一份。
- **现状文档不写日期流水**：「2026-09-26 改成 X」属于历史；README 里只留「现在是 X，因为……」，日期与过程写进 `历史记录.md`。
- 三者之间互相只留一行指针，不要复制内容。同一段话只允许存在一处。

公共播放控件放在 `shared/exercise-controls.js`。新练习直接使用 `<exercise-controls id="transportControls"></exercise-controls>`，监听 `exercise-play`、`exercise-stop`、`exercise-regenerate` 事件，并通过 `seedValue`、`clearSeed()`、`setPlaying()`、`setBusy()` 同步状态。组件只负责 UI，各练习仍保留自己的音频引擎和调度逻辑；不要再复制旧的播放、停止、种子、换一版按钮代码。

新增练习后，同时更新根目录 `README.md` 和 `index.html` 的作品列表。
