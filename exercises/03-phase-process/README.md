# 03 · Phase Loops

第三份练习：一组固定音符分别运行在独立 loop 中。每个音符都有自己的声音长度、循环周期和初始相位偏移；系统开始后，各个 loop 因周期不同而不断错位，音符之间的先后顺序与重叠关系持续变化，自然形成旋律与和声。

版本：[`0.1`](0.1/)（初始卡片式页面）；[`0.2`](0.2/)（全屏圆环舞台 + HUD 页面结构，音乐逻辑暂与 0.1 相同）。新增 [`0.3`](0.3/)（Three.js 3D 分层环带，音乐沿用 0.2）。版本目录只保存实现文件，本 README 统一记录整个练习的设计与演进。

灵感来自 Tero Parviainen 的文章 [JavaScript Systems Music](https://teropa.info/blog/2016/07/28/javascript-systems-music)。这篇文章用 Web Audio / Tone.js 重做 Steve Reich 和 Brian Eno 的系统音乐思路：不是直接写一段固定旋律，而是设计一个会自己生成音乐的系统。

- 视觉：同轴分层 3D 环带、正面印字、固定播放头附近的局部提亮；测试 HUD **只有圆角和恢复默认**。
- 音乐：周期 / 相位由种子确定，力度跨多轮呼吸；钢琴用补偿后的采样衰减估算 duration，Drone 按包络与周期留白分配时长。总输出 +6 dB。
- 钢琴尾音：保留起音，对衰减段做最多 +12 dB 的补偿，接近噪声底时撤回；保留源采样率。当前只有补偿版 Sampler 发声，不再保留用于界面对比的原始 Sampler。
- Release：目标为周期的 25%，下限 3.5s，上限为 `max(0.05, period − duration − 0.5)`，上限优先。因此补偿后较长的 duration 可能压低某些音的有效 Release，不能再把“全部至少 3.5s”当作不变量。循环卡显示有效秒数。
- FM 回退：每个音高独立 FMSynth，sustain=0.18，duration=3s，防止不同音的 Release 相互覆盖；共享混响。
- 操作：输入种子按 Enter 应用；换一版随机生成。重播 / 重建保留当前圆角选择，刷新回到默认值。
- 协作：**效果和参数该调就调，必要验证正常做；不要自动把每次调整做成 HUD 参数。** 只有用户明确需要界面控制时再加。删除音频测试控件不表示撤回已经做好的声音调整。
- 验证：已做采样能量对比、FM 包络隔离、真实播放停止与语法检查；控件收敛后检查了删除引用和语法。没有实际试听，尾音自然度与力度仍待用户判断。

## 学习内容

- 固定音符集合如何通过不同 loop 周期产生长期变化
- 初始相位偏移：系统开始时，每条 loop 从自己的不同位置进入
- 每个音符独立设置声音长度、周期与力度
- 低音 drone 也遵守独立 loop 规则，用更长周期托住调性中心
- 复用 02 的 `vsco2-piano-mf` 采样钢琴，便于比较不同生成机制
- 引入 Moodist 的环境音效作为背景 texture events：按周期、概率和淡入淡出出现，不常驻播放
- 使用递归 `Tone.Transport.scheduleOnce` 管理多个长期循环：`scheduledFireAt` 提前交给 Tone 排音频，`visibleFireAt` 只在实际发声时刻推进，避免 lookAhead 造成音画错位
- 用同心圆环显示每条 loop 的旋转音段，并用 `requestAnimationFrame` 平滑刷新
- 0.2 将圆环视觉铺满窗口，标题、控制器、状态和循环参数改为悬浮 HUD；点击舞台可统一显示或隐藏 HUD
- 0.2 的 SVG 层级固定为：灰色轨道在底层，其上依次是播放头、彩色音符、音名与触发轮廓；播放头只作为参照，不遮挡正在经过的音符
- 用种子随机生成可复现的 loop 参数
- 停止、换一版时正确清理 Transport 事件和 Web Audio 节点

## 音乐规则

- 音符集合：F 小调色彩的七个钢琴音，外加三条低音 drone。
- 每个音符是一条独立 loop，不共享节拍网格。
- 每条 loop 有 7.5 到 23 秒之间的周期，彼此刻意错开。
- 每个音符有自己的声音长度，短音像点，长音像云。
- Drone 使用 F2、C3、Ab2，周期约 40 到 70 秒，attack/release 都很长，像慢慢浮现的低频地平线。
- Moodist texture pool 包含 `brown-noise.wav`、`wind-in-trees.mp3`、`birds.mp3`、`busy-street.mp3`、`crowd.mp3`。它们不会永远播放，而是作为环境事件按不同周期和概率淡入淡出；鸟类、街道和人群会在播放后较早尝试入场，当前目标增益分别为 `0.03`、`0.2`、`0.4`；同一时间最多允许四条 texture、其中最多两条 event，避免长期全部常驻。
- 初始相位不是“延迟开始”，而是“这条虚拟磁带已经转到某个位置”：页面启动时会计算它下一次触发还要等多久。
- 采用 02 同款钢琴采样；混响较长，但干声保留清楚，让重叠关系仍然可辨认。
- 0.2 页面中的每个同心圆代表一条 loop：彩色弧段是声音长度，白色音名沿圆环曲率附着在弧段前端并随之旋转；当前端顺时针滚动到右侧播放头时，该音响起。配色保持两类单一纯色：所有钢琴音符统一使用橙色，所有 Drone 统一使用绿色；轨道使用接近黑色的中性色并退到背景，播放头使用低对比中性白。触发时播放头始终保持固定，音段继续运动；音段内外边缘复制为两条同色细弧，短音约扩散一个环距，长音可扩散两到三个环距。最内层向中心的距离会在圆心前停止。轮廓从音段头部向尾部裁切、逐渐透明；线宽也随包络由细变粗、再逐渐变细。整个生命周期严格等于该音符的实际声音长度，音符结束、透明度实际绘制为 0 后，才在下一帧移除节点。

## 视觉参考

同心圆 loop 可视化参考 Tero Parviainen 的 [JavaScript Systems Music](https://teropa.info/blog/2016/07/28/javascript-systems-music) 一文中对 tape loop / phase loop 的展示方式：每条圆环代表一条独立循环，彩色弧段代表该 loop 中会发声的片段，固定播放头用于观察不同周期的音段如何逐渐错位。本练习没有直接复制原文代码或素材，而是按同一视觉语义重新实现。

## 0.3 · 3D 分层环带

- 将原来的十条同心圆改为同轴、等半径、等层距的十条水平圆柱侧面环带。每层独立，没有螺旋连接。自上而下沿用原来的七条钢琴、三条 Drone 顺序，配色仍为橙 / 绿。
- 环带角度 = `duration / period × 2π`，旋转角度直接由实际音频时间 `Tone.Transport.getSecondsAtTime(Tone.immediate())` 与 `visibleFireAt` 计算，不逐帧累加。几何从尾端 `−span` 到前端 `0`；世界坐标 `+Z` 处为固定播放头，前端经过竖线时发声。拖动只移动镜头，不改变触发位置。
- `Tone.Draw` 在实际发声时记录 `lastVisualFireAt`，仅用于 HUD 发声状态。环带提亮由片元到固定播放头（世界坐标 +Z）的角距离决定，半宽 0.22 弧度、smoothstep 柔边：靠近时渐亮，经过最亮，远离后恢复；持续照亮正在经过的带面，从前端扫到尾端，不再整段按触发包络闪亮。镜头转动不改变亮区位置；停止时关闭局部光照并保留静止环带。
- 正交相机默认略微俯视，柔光与深度测试表现带面的前后遮挡。灰色细轨道表达完整周期；低对比播放头略放在环带内侧，避免盖住彩色音段。白色音名直接绘入环带的 UV 贴图，贴合曲面并共用光照、提亮和深度遮挡；侧看自然压缩，音名仅印在外侧正面，内侧背面只显示底色，不使用始终朝向相机的 Sprite。
- 拖动改变视角，滚轮缩放，`R` 恢复默认镜头，`F` 切换全屏；点击空白舞台隐藏 / 显示 HUD。拖动超过 5px 后不会被误判成点击，种子输入框内不响应快捷键。
- 初始画面用固定基础参数预览，不加载音频、不消费演出 RNG；播放后替换为该种子的真实参数。预览本身静止。
- `stage.js` 仅负责 3D 与交互，音乐引擎仍在 `index.html`。固定使用 Three.js **0.169.0** ES module（jsDelivr CDN），无需 npm / 构建；推荐通过本地 HTTP 服务器运行，ES module 在 `file://` 下受浏览器限制。
- 环带几何、材质、音名纹理在换一版时释放；停止取消动画循环，页面离开释放 renderer 与监听器。画布像素比上限 2。
- 本版先确定空间布局和同步，不加入参考图的颗粒材质。旧版二维扩散轮廓由环带提亮替代，避免轮廓穿过相邻层。

### 音色时长与力度呼吸（2026-09-18）

本次开始修改 0.3 音乐，替代旧的 `baseDur × 随机倍率`；早先“音乐沿用 0.2”仅描述初版。周期 / 初相位 / 基础力度沿用原种子抽取顺序，旧时长随机槽仍消费一次以免改变后续参数；新时长不使用那个随机数。`baseDur` 仅保留作未加载采样前的静态预览，播放后以实际时长重建环带。

- **钢琴**：加载同一套采样一次，分析各声道的 50ms RMS 窗口。峰值之后连续 300ms 低于峰值 **−24 dB**，取低电平段的开始作为参考松键时刻；未达到阈值则取文件时长。按 Sampler 相同的最近采样规则匹配音高（等距离选较高采样），再除以变调播放速率得到目标音的参考时长，最终不超过周期的 72%。−24 dB 是可试听调整的初始阈值，不是“人耳刚好听不见”的结论。静音采样兜底 0.3s。
- **合成回退**：按 FM 包络 attack 0.005s + decay 1.2s，参考时长 1.205s，不假装测得了真实钢琴采样。采样加载失败 / 超时清理已加载缓冲，迟到的加载结果也释放。
- **Drone**：共享实际声音包络 attack=4s、decay=1s、release=8s。设含释放的发声窗口为周期的 65%，`duration = max(attack + decay, period × 0.65 − release)`；另外限制松键 + release 不超过周期的 80%，至少保留 20% 空隙。对当前周期实际约留 35% 空隙，duration 一场内固定。比例是创作参数，依据是包络预算，并非唯一正确值。
- **力度呼吸**：每个音以 5–8 次自身循环为一轮缓慢的轻—重—轻，轮数为 `5 + MIDI % 4`（用于有限地错开各音，不是声学定律）。余弦曲线，钢琴在基础力度的 65%–100% 间，Drone 在 80%–100% 间；离散触发不保证采到连续曲线的极值。初始呼吸位置来自 `seed:breath:note` 的独立种子流，不影响音乐原随机流。
- 呼吸用**音频调度次数**推进，不能用尚未执行的 Draw/视觉计数；Draw 只更新 HUD 的本次力度。后台视觉节流不会改变下一音的力度。
- 测试 HUD 新增「力度呼吸」开关，用于比较；切换从下一次尚未预排的发声起生效，重新开启保持原呼吸进度。恢复默认会启用呼吸。展开「机制与循环」可看实际 duration、本次力度与呼吸轮数。

环带仍表示触发至松键，不包含 release 和混响；长度一场内固定，周期与相位不随呼吸改变。这里的变化以试听为准，未把基于 RMS 的估算等同于听感验收。

本轮验证：Chrome 静音实际采样加载、播放 / 停止 / 重播、呼吸开关通过，页面异常为 0；主动拦截采样请求后，FM 回退时长 1.205s、播放停止正常。人工合成 RMS 数据验证阈值、100ms 短空隙不误判、静音兜底；90 组音区 / 声部组合各 100 次力度均在范围内且按轮数重复；Drone 当前周期区间满足释放与留白预算。样例种子 `breath-check`：钢琴时长 F3=2.20、C4=3.02、Ab4=1.11、Bb4=0.99、Eb5=1.40、G5=2.36、C5=1.64 秒；Drone 19.49 / 26.71 / 34.25 秒。以上为计算与链路验证，尚未实际试听。

### 种子应用（2026-09-18）

旧实现只在创建引擎时读取输入，打字不会更新正在播放的版本；“换一版”还会清空输入。现 03 0.3 显式启用公共控件 `apply-seed`：输入后按 Enter 应用并播放，已有演出先淡出、释放再按输入种子重建；未播放时也可 Enter 开始。换一版仍是清空输入、随机生成。重建期间锁定控件，防止连续 Enter 产生多个引擎。其他练习未启用该属性，保留原行为。更换种子改变周期 / 相位 / 力度呼吸，不保证钢琴时长变化，因为时长由同一采样衰减决定。

种子流程静音实测：Enter 首次播放和播放中切换通过；`seed-alpha → seed-beta → seed-alpha` 周期 / 相位参数先变化再精确复现；始终一个画布，停止正常，页面异常为 0。

### 钢琴逐音 Release（2026-09-18）

用户要求「钢琴的 release 按各环位置算」，而不是所有音共用一个采样器常数。此前 `new Tone.Sampler({ release: 3.5 })` 是**全局**的：七个音、七条周期完全不同的环共用同一个尾音长度。

- 现在 `release = period × 比例`，比例由测试 HUD 的「钢琴 Release」滑杆给（5%–60%，默认 **25%**）。环越长尾音越长：实测 F3 4.43s、C4 4.93s、Ab4 5.46s、G5 2.32s（周期 9.29s）。周期最大 60% ≈ 14s 仍短于最短周期，尾音不会盖住这个音的下一次触发。
- 实现要点：**`Tone.Sampler` 里 `release` 不是一个共享的总线参数，而是每次 `triggerAttack` 现场读取的**。14.7.58 的 `triggerAttack` 对每个音即时新建 `ToneBufferSource` 并传 `fadeOut: this.release`，所以「触发前写 `piano.release = x`」就是逐音控制，**不需要复制采样器、不需要额外的增益节点**（曾担心池化 voice 会变陈旧，读源码后确认 Sampler 没有 voice 池，这个担忧不成立）。
- `loop.release` 存成**函数**而不是冻结数值，于是滑杆在播放中调整会从下一个音立即生效；而周期、时值、相位这些演出参数完全不受影响（不消费任何 rng）。
- `duration` 仍是「按住多久」（采样衰减实测），release 是「松手后的尾巴」，两者不叠加计算。落点越长的环，尾巴越长，整条环的总发声占比因此随周期归一。HUD 循环卡新增 `release x.xxs · 周期 NN%` 一行；回退的 FM 合成路径也支持逐音 release（写 FMSynth 包络），采样加载失败时滑杆仍有效。

验证（headless Chrome）：七个音各自触发时读取到的 `piano.release` 为 2.32–5.46s，互不相同且等于 `period × 0.25`；滑杆改 50% 后下一次触发即变为 4.80–11.60s；页面异常 0。**未做听感评价**——4.43s 的尾音是否合适只能靠耳朵，不合适就调滑杆（改动只影响下一次触发，不需要重播）。

### 修复：构建中的引擎被停止后变成孤儿（2026-09-18）


用户报「有的时候钢琴没声音」并伴随控制台 `Synth was already disposed` 疯狂报错。根因**不是音乐参数**（时长、周期、力度、呼吸都已核对无问题，实测七个钢琴音全部有正常时值），而是**停止落在引擎构建途中**：

- 采样钢琴要加载 12 个 WAV（单个 4.6–10 MB）并生成 10 秒混响，构建实测约 6–8 秒。这期间 `engine` 仍是 `null`，于是 `stop` 处理函数**什么都不做**（它只判 `engine`），`按钮却已经切到停止态`；而构建完成后照样 `schedule()` + `Transport.start()` —— 产生一个界面再也够不着的**孤儿引擎**：它继续排音、播进已被 dispose 的节点。之后每一次播放都会再建一个引擎，孤儿与新引擎同时发声，报错以 **20 次/秒**持续不断（与钢琴触发速率一致），听起来就是「没声音 + 疯狂报错」。
- 修法：新增 `engineGeneration` 代次计数器（`stop` / `restart` 自增）与 `pendingBuild` 引用。停止不再只判 `engine`：构建中的引擎在 resolve 之后比对代次，不等就 `end()` + `deactivate()` 回收，**绝不进入 `schedule()`**。停止时把 `engine` 先取到本地再置 `null`，避免 900ms 计时期间新建的引擎被误清。
- 同时修掉本轮重构引入的一个自身缺陷：`settled()` 包装函数写成 `return { ok: true }`，**丢掉了 resolve 出来的引擎对象**，`engine = result.value` 赋成 `undefined`，表现为「播放失败：Cannot read properties of undefined (reading 'schedule')」。现改为 `{ ok: true, value: await promise }`。

另一处独立缺陷（同一轮修掉）：凡是时长超过 Tone `lookAhead` 的音符，其 voice 都会用 `context.setTimeout` 安排未来的 release，而 **`Synth.dispose()` 并不会取消这些回调**。它们在本引擎销毁之后才到点，撞上 Tone 的 `assert(!this.disposed)` 就抛 `Synth was already disposed` —— 积压会长达数十秒（实测停止后仍有 20 次/秒、最长 158 秒），是用户报的「疯狂报错」里剩余的那一半。修法：`deactivate()` 末尾调用 `dropPendingVoiceCallbacks()` 清空该 context 待执行的回调队列（访问 `Tone.getContext()._timeouts._timeline`）。这是 Tone 私有实现（与本仓库已在用的 `_ticker` 同类），函数上写了注释：升级 Tone.js 必须复查；若结构变了只告警、不抛错。这些异常本来就不影响发声，所以它只是让控制台干净。

验证（headless Chrome，`--headless=new --autoplay-policy=no-user-gesture-required`）：完整走「播放 → 构建中途停止 → 再次播放 → 停止 → Enter 换种子 → 换一版 ×2 → 停止」，**全程 exceptions = 0**（修复前同一序列在换一版后即爆 363 次、停止后再 198 次）。压力测试连做 4 轮播放 / 停止 + 2 次换一版，**exceptions 仍为 0**；每次播放都有实际发声（Sampler/PolySynth 触发次数递增到 39/5）。


### Release 修正（2026-09-19，取代上一节逐音实现中的旧说明）

- 采样钢琴仍在每次触发时设置 release；FM 回退改为每个音高独立的 FMSynth，共享混响但不共享包络，最多七个实例，停止时统一释放与销毁。旧 `PolySynth.set` 会改到其他尚在发声的 voice，不能作为逐音设置。
- 有效 Release = `min(max(3.5, period × 滑杆比例), period − duration − 0.5)`（剩余时间最低 0.05s）。默认 25% 不再让短周期的音比旧 3.5s 更短；上限同时考虑按住时长，给同音下次触发留 0.5s。当前参数下可满足 3.5s 下限，若将来时值过长则留白上限优先。低比例因下限出现平台是预期行为。
- 循环卡显示当前目标的有效秒数，拖动 / 恢复默认立即更新。正在响及已预排的音保留旧参数，下一次尚未预排的触发采用新值。
- 秒数表示包络设置，不保证采样仍有同样长的可听尾音。不会延长已经结束的采样，也不改变混响或环带 duration。

2026-09-19 静音浏览器验证：重叠 C4 / G4 分别设 4s / 7s 后两者包络仍各自为 4 / 7；真实钢琴播放中，七个卡片在默认值均不低于 3.5s，滑杆改为 50% 后有效秒数实时更新，恢复默认精确还原。停止正常，页面异常为 0；语法与 diff 检查通过。未做实际试听。

### 可闻尾音补偿（2026-09-19，当前钢琴时长规则）

用户需要的是经过播放头后，钢琴仍清楚可闻地延续。只增大 Release 不够：旧 duration 在干采样跌到峰值 −24 dB 时松键，此时尾音已经很弱，Release 只会继续衰减它。现在先处理采样的自然衰减，再计算松键时刻。

- 原始 PCM 保留，额外生成一份延音补偿 PCM；不循环采样、不叠加合成延音、不改变播放速率或音高。保持源采样率与声道数。
- 以 50ms RMS 窗口估计包络；峰值后前 200ms 保持原样，此后将衰减曲线往 1.8 倍时间尺度的方向托起，提升最多 +12 dB。实际是按当前 RMS 的相对 dB 计算目标增益，不承诺听感或阈值时长严格为 1.8 倍。相邻窗口增益平滑插值；峰值约束防止额外削顶；低于峰值 −48 dB 后逐步撤掉补偿，到 −60 dB 目标回到 1，避免长期抬起噪声底。
- duration 改由**补偿后的采样**计算 −24 dB 衰减参考，仍补偿变调速率，仍受周期 72% 上限约束。环带随新的 duration 变长；Release 独立负责此后的松键淡出，仍受同音下一次触发的预算约束。
- 初次验证曾用两套 Sampler 和 HUD 开关做 A/B（两者保持相同 duration）。随后按用户要求移除开关与原始 Sampler，当前固定使用补偿版。
- FM 回退无法补偿不存在的采样：使用独立 FMSynth，当前 sustain=0.18、参考按住时长 3s，为衰减后提供短暂保持段；释放仍由 Release 控制。它是回退近似，不宣称与采样音色一致。
- 当前停止 / 重建时释放补偿版 Sampler、原始与补偿缓冲、共享混响；不修改随机序列、力度呼吸、Drone 或总体 +6 dB 增益。

静音实测（干采样，不等于最终混音听感）：F3 阈值时刻 2.20→6.90s，C#4 2.85→9.40s，A4 1.05→4.10s，C#5 1.55→2.75s，F5 1.25→4.10s；对应文件长度仍为 10.04–17.55s，没有拉长或补造文件。原阈值之后两秒 RMS 提升约 9.49–11.54 dB，前 150ms 能量差 0 dB，五份补偿 PCM 峰值均未超过 1。真实播放、补偿开关和停止通过，页面异常为 0。尚未实际试听；这版应由用户听后再调整补偿力度。
