# 04 · Note Tile Collapse 0.5 —— rolling window + register drift + density drift

**入口：[`index.html`](index.html)**。基线是已验证完成的 [0.4](../0.4/)（最小 WFC：一维 16 格、A minor 7 个候选、只两条硬规则、边坍缩边发声）。

0.5 **只加三个机制**，不引入和弦、段落、motif：

| 机制 | 解决什么 | 一句话 |
| --- | --- | --- |
| **① rolling window** | 从"有限序列生成"变成**可以一直跑的时间系统** | 始终维护 16 格未来窗口：最左格播完退出、其余前移、右端补入一个全新未确定的 Cell，再从已确定的邻居传播约束 |
| **② register drift** | 几十个 Cell 尺度上的**音区移动** | 中心是连续数值，只给**合法音高候选**加权（越近越容易被选中，远的只是概率低、**不会被删**） |
| **③ density drift** | 同样时间尺度上的**疏密移动** | 全局疏密控制"当前窗口大约该有多少个 note"，决定每格是 note 还是 rest；**只有 note 格进入音高坍缩**，rest 只是时间上的空位 |

两个 drift 都不是段落、不是"高潮/回落"这类离散状态，只是一直缓慢变化的全局参数。于是系统有三个时间层级：WFC 管音与音之间的局部连续性，register drift 管音区，density drift 管疏密。

## ① 滚动窗口：怎么滚动

窗口按**时间**排序：`index 0 = 下一步要播的`，`index 15 = 最远的未来`。一拍做四件事：

1. **保证能播**：`window[0]` 若是"还没定音的 note 格"，就当场坍缩它（用 register drift 加权选音）并传播；
2. **发声**：note 格触发一个八分音符；rest 格**不发声**（时间空位）；
3. **滚动**：它退出窗口 → 其余前移一位 → 右端补入一个全新 Cell（mark 与候选集都在此刻定）→ 从左侧已确定的邻居 `settle()` 传播；
4. **超前坍缩**：这一拍若没有强制坍缩，就按**熵顺序**（候选最少且 > 1）在未来 note 格里坍缩一个 —— "一段已经部分确定的未来"就来自这里。

★ **每拍只坍缩一次。** 若一拍既强制坍缩最左格、又超前坍缩未来格，"未定音格数"会一路降到 0 —— 窗口变成"整段预先决定"，而且新补入的格子只能被左邻约束（约束退化成单向的马尔可夫链）。

### ★ 窗口左边界外已播完的音，必须参与"连续同音"判断

本轮探针抓到的**真 bug**：`max repeat` 只看窗口内部邻居，而格子播完就退出窗口 —— "上一个音"一旦退出，规则就看不见它了。实测 400 拍 × 30 种子出现 **21 次 3 连击、最长 4 连击**（规则是"最多 2 次"）。
修法：把最近播放过的音高记进**历史缓冲**（`HISTORY = maxRepeat + 1` 个 midi，最新在前，**rest 记 null**），窗口左边界的"更左边"就取历史。修后 **连击超限 0、最长连击 2**。休止记 `null` 也让"休止会打断音程链与连击"这件事在规则里如实生效。

## ② register drift：怎么漂、怎么影响选音

```js
权重 w(d) = 1 / (1 + (d / REGISTER_WIDTH)²)，d = |候选 midi − center|，REGISTER_WIDTH = 3
```

- **只影响"倾向"，不影响"合法性"**：候选集合完全由 `max interval` / `max repeat` 决定；权重只在**合法候选之间**分配概率，远处的音**永远不会被删掉**。关掉时全部权重 = 1（= 0.4 的等概率选音）。
- **中心怎么动**：有惯性的随机游走 —— `速度 = 速度 × 0.9 + 随机推力(±0.12)`，`中心 += 速度`，到头反射（速度反向）。所以是**缓慢来回**，不会单向跑掉、也不会跳。
- **范围按音阶自身音域定**：`REGISTER_MIN = 音阶最低音 − 1 = 68`，`REGISTER_MAX = 音阶最高音 + 1 = 80`。规格举的 60（C4）→ 67 是另一段音区；要让中心落在那里，把 `OCTAVE` 改成 3，范围会跟着音阶自动下移。

## ③ density drift：窗口级配额，不是每格独立概率

```js
每进入一格：noteCredit += 当前 density
            p = clamp(noteCredit, 0, 1)；以 p 判 note，否则 rest
            判成 note 就 noteCredit -= 1
```

- **长期比例精确跟着 density 走**：credit 有界 ⇒ 任意连续 16 格里音数都在 `density × 16` 的 **±1 格**以内；实测（疏密冻结 0.5）`|窗口音数 − 8|` 平均 **0.25**、最大 **1.0**。
- **短期不会连成大片空洞**：低疏密时间隔上界约 `1/density` 格，而不是几何分布的长尾。
- **仍然有随机性**：credit 落在中间时是概率判定，不是机械等分。
- **每个新格只读"那一刻"的 density**，读一次就定了（之后它的 mark 不再变）。
- **只有 note 格进入音高 WFC**；rest 格不参与音高坍缩，只作为时间空位，并且**会打断音程链与连续同音**（这正是判定口径）。

★ **被实测否掉的第一版做法**（留档）：按"窗口现有音数 vs 目标音数的缺口"决定 note/rest（缺口大就补 note，达标就随机）。它确实把**窗口音数**稳在目标附近，但**完全不控制间隔** —— note 会在窗口里聚成一堆，播放出来就是前面连着 **13 格休止（3.5 秒空洞）**，正是"过于随机的空洞感"。改成误差反馈后：**最长休止段 13 → 6，休止段均长 4.45 → 1.62**（疏密冻结时最长 2）。

- **决定性**：同一颗种子跑两次，整条音流（含休止）**30/30 逐位相同**。

## 问题 / 语义待确认 / 尚未加入的功能

★ 这三类要分清：**问题**是现在做错了、该修的；**语义待确认**是实现上说得通、但需要你拍板的选择；**尚未加入的功能**是范围之外、故意没做的。

### A. 已经修掉的问题（都留了实测数字）

1. **density 一开，"部分确定的未来"被抽干**（本轮最大的问题）。坍缩原来是"每拍固定一次"，而 note 格流入只有 `density` 个/拍（0.5 时约 0.5）⇒ 未定音格被抽干：实测 **98.3% 的拍上未定音格 = 0**，新格一进来就被定音、它周围只有一个已确定的左邻，"部分确定的未来"名存实亡（也就是我在设计里特意避免的那条退化成单向约束的路）。
   **修法**：坍缩的触发条件改成「**未定音格数 > 目标水位**」（目标 = 窗口音格数的一半，与播种一致）。修后：未定音格均值 **3.72**、最小 1、**0% 的拍为 0**；register drift 的效果也从 1.75 回到 **2.15** 个半音（约束上下文恢复了）。
2. **窗口左边界外已播完的音不参与"连续同音"判断**：实测出现 21 次 3 连击、最长 4 连击。修法：加历史缓冲（rest 记 null）。修后连击超限 0、最长 2。
3. **density 第一版按"窗口缺口"配平**：窗口音数对了，但**间隔完全不受控** —— 最长休止段 **13 格（3.5 秒空洞）**。改成误差反馈后降到 6（疏密冻结时 2）。
4. **死代码清理**：`report.notes` / `report.rests`（只加不读）与 `lastSeed`（只写不读）已删。

### B. 语义待确认（不是 bug，但需要你点头）

1. **休止会打断 `max interval` 与 `max repeat`**：现在 rest 被当作"时间空位"，所以 `C – 休止 – A`（相隔 7 个半音以上）是允许的，`C – 休止 – C – C` 也不算 3 连击。另一种读法是"规则作用于**连续发声**的音，休止不打断链"。**两种都合理**，现在的实现是前一种（因为规格里写"rest 不参与音高坍缩"）。要换我改 `valueMidiAt` 一处。
2. **每个音固定一个八分音符**：density 只决定"哪里出现音"，不改变音长。所以低疏密时是"短音 + 空隙"，不是"长音铺满"。这也意味着**休止不会掐断上一个音**（上一个音本来就是 0.27 秒后自己结束）。

### C. 尚未加入的功能（范围之外，故意没做）

- **时值 / 长音**（note 延续到下一个事件）—— 要让稀疏时更连贯，这是最直接的下一步
- **力度**（含力度漂移）、**音色切换**、**效果器**
- **和声 / 和弦进行 / 调式切换**（`KEY_ROOT` / `KEY_MODE` / `OCTAVE` 已经是一等概念，但没有界面开关）
- **超过一个八度**（现在 A4–G5）、**多声部 / 复音**
- **段落 / motif / tension-release**（规格明确不做）
- **可视化映射**（现在只有候选格与两个漂移读数）
- **BPM / 网格可调**、**保存 / 导出**

## 可调旋钮与取舍

- **旋钮**：`WINDOW`（默认 16）、播种与坍缩水位比例（现在都是"音格数的一半"）、`REGISTER_WIDTH` / `DRIFT_ACCEL` / `DRIFT_DAMPING`、`DENSITY_ACCEL` / `DENSITY_DAMPING` / 范围、`maxInterval` / `maxRepeat`。
- **已知取舍**：坍缩按"目标水位"触发而不是固定每拍一次 —— 固定每拍会抽干未定音格（见 A.1）；水位比例调小会让窗口更"预先决定"、调大则坍缩更超前。
- `0.4` 保留为基线（有限 16 格）；`0.1`–`0.3` 是更早的二维版本；[`../算法规则.md`](../算法规则.md) 描述的是 **0.3**，不适用于 0.4 / 0.5。
