# 04 · Note Tile Collapse 0.5

入口：[index.html](index.html)。基线为 [0.4](../0.4/README.md) 的最小 WFC；0.5 增加滚动窗口、音区漂移和疏密漂移。当前机制更新于 2026-09-21：**休止与音高一起参与坍缩**。旧机制与迭代记录保存在 [早期机制记录.md](早期机制记录.md)，其中的旧统计不代表当前实现。上级 `算法规则.md` 只适用于 0.3。

## Cell 与候选

每个新 Cell 都是未确定状态，候选为 `A B C D E F G + 休止`。A 小调音高范围 A4–G5；关闭 density 的离线对照只有七个音高候选。

- `mark = pending`：尚未确定，音符与休止都可能出现。
- 坍缩为音高后才设 `mark = note`；坍缩为休止后才设 `mark = rest`。
- 休止使用独立候选对象 `REST`（midi 为 null），未确定值为 undefined，两者不能混用。
- 候选最少且大于一个的格子优先坍缩，并列用种子随机选择；唯一候选直接确定并继续传播。

## 三条硬规则

1. 相邻发声格的音程不超过 5 个半音。
2. 同音最多连续两格。
3. 休止最多连续四格（与最低疏密 0.2 对应：至少每五格出现一个音）。

休止仍打断音程与同音重复链。连续休止上限检查左右已确定格和窗口外播放历史，因此跨窗口边界也生效。音符和休止确定后都会传播；如果候选真的被删空，显式报错，不再跳过削减而静默放宽规则。

## 滚动与疏密

窗口保持 16 格，左端为下一个要播放的格子。初始化约一半格子已确定；播放时最左格若仍未确定则立即坍缩。播完退出，右侧补新格；本步未强制坍缩且未确定格超过 8 个时，在未来格里主动坍缩一个。每步最多一次主动坍缩，传播推出唯一结果不计入主动次数。

**不再在新格进入时提前选择 note/rest，也不使用旧的 noteCredit。** 坍缩时计算：

```text
发声总权重 p = clamp((density × 16 − 窗口已确定音符数) / 未确定格数, 0, 1)
休止总权重 = 1 − p
```

先在合法的发声/休止两类之间按上述权重选择；选择发声后，再在合法音高之间按音区权重选择。这与把发声总权重归一化分配给七个音高等价，避免七个音高对一个休止造成数量偏置。某类候选被硬规则排除后只能选另一类；已确定结果不随 density 改写。

这是**疏密倾向与窗口反馈**，不再保证旧机制“固定目标下任意 16 格误差 ±1”。未来窗口只有一半已确定，不能把其中已确定音数当作完整窗口的最终密度；离线疏密统计改为最近 16 个实际输出。漂移到输出有提前确定和滚动带来的滞后。

音区中心仍在 68–80 之间作有惯性的随机游走，合法音高权重为 `1 / (1 + (距离 / 3)²)`。疏密在 0.2–0.8 之间漂移。选格/音高、音区漂移、疏密漂移、发声/休止抽样使用四条种子派生随机流。同一种子可复现新机制，但不再复现旧版本的音流。

## BPM 演出参数（2026-09-22）

右上控制面板加了 `BPM` 数字输入框（**40–240，默认 112**）+ 一行提示（1 格 = 多少秒）。按 Enter 或失焦生效；非法输入（空、非数字、越界）回到上一个合法值并在状态栏点名 —— 与 0.2 / 0.3 的输入框行为一致。做法抄自它们的口径：**BPM 只缩放绝对速度，不改音乐结构**（模型整体在拍域，同一颗种子的音符序列在任何 BPM 下逐位相同）。

和 0.2 / 0.3 不同的一点是**这里用 Transport 自己排 repeat**（0.2 / 0.3 按绝对秒数 `scheduleOnce`），所以：

```text
Tone.Transport.bpm.value = bpm                 // 与"一个 Cell 的秒数"同源
scheduleRepeat(tick, 60 / bpm / 2, startAt)    // 秒数 → tick：192 PPQ 下**永远正好 96 tick**（八分音符）
triggerAttackRelease(note, 60 / bpm / 2, ...)  // 时值每步现算
```

- **`60 / bpm / 2` 秒在同一个 bpm 下恒等于 96 tick**（换算里 bpm 约掉了），所以既不会被量化（0.4 记过一条：不设 bpm 时 0.2679s 会被 120 BPM 的网格量化成 0.2682s），也不存在"某个 BPM 下网格不整"的情况。
- **播放中改 BPM 不用重排、不用重播**：repeat 的间隔是**按 tick 存的**，改 Transport 的速度，96 tick 还是八分音符，只是变快变慢；音的时值与画面位移时长在各自那一步 `cellSeconds()` 现算。因此**没有任何"建引擎时算死"的秒数**（这正是 0.3 记下的教训：延迟/时值按建引擎时的 BPM 算死，播放中改速度就会漂到错误的拍位上）。
- 停止期间改过的 BPM 由 `schedule()` 在重排时补写（它同时决定秒数 → tick 的换算，必须与 `cellSeconds()` 同源）。

验证分两半（按根 `AGENTS.md` 的验证口径）：

```powershell
node exercises/04-wfc-loom/tools/offline-tempo.mjs      # 调度时序，离线
node exercises/04-wfc-loom/tools/browser-check.mjs --url http://127.0.0.1:8765/exercises/04-wfc-loom/0.5/
```

| 量 | 离线（假 Transport，走真实 `playCurrent` 路径） | 真机（种子 12345，播放中 112 → 180） |
| --- | --- | --- |
| 112 / 56 / 224 BPM 的格长 | 0.267857 / 0.535714 / 0.133929s，与 `60/BPM/2` 逐位相同 | 间隔 0.2679 / 0.5357 / 0.8036s（格长的整数倍，休止格不出声） |
| 音的时值 | 三个 BPM 下都严格等于格长 | — |
| 步与步的时刻 | 第 k 步 = 起点 + k × 格长（整数倍检查，无累加漂移） | — |
| 同种子的音符序列 | 三个 BPM 下**逐位相同**（各 61 个音） | — |
| 播放中改 BPM | `Transport.bpm` 立刻跟随、之后触发的音全部用新格长；越界输入回退到上一个合法值 | 提示行 0.268 → 0.167s，间隔全部落在新八分音符网格上（÷期望 = 4 / 3 / 3），**步数 19 → 35 继续涨 = 没有重播** |

★ 离线桩量不到、只能在真机量的一件事：**"改 BPM 后网格自己跟着走"是 Tone 把秒数换算成 tick 的内部行为**（桩里的 repeat 间隔就是页面传进来的秒数），所以那一条由 `browser-check.mjs` 的 ①c 段负责。

**不跟着 BPM 缩放的东西**（都写死成秒）：`PIANO_RELEASE_S = 1.5`、混响 `decay 3.6`、`START_LEAD_S = 0.25`。所以改速度会顺带改变"干湿感"—— 极快时尾巴糊成一片、极慢时颗粒分明。这是 0.2 / 0.3 已经量过的同一件事（约 90 BPM 以下颗粒分明、180 BPM 以上洗成一片），本轮不处理；要让"快慢只改速度、不改干湿"，就得把 release / decay 改成按拍长算。

## 最小 motif memory（2026-09-22）

本轮直接加入 0.5，不新增版本。当前磁盘代码尚未包含 interval activity drift，本次没有补做它；现有音区、疏密和硬约束继续使用。

- **存储**：只从已经输出的音符顺序收集，连续四个发声音符存为一段，随后重新收集；休止清空未满四音的片段。最多六段，FIFO 淘汰，不检测相似度、不去重，也可以记住实际播放出的引用结果。
- **触发**：没有引用正在等待/播放且池非空时，每步以固定 0.15 概率尝试引用。不绑定小节。选最近一段连续四格尚未确定的未来区域；找不到就本次不调用，不改写已确定的 Cell。引用可以提前绑定，直到末格播放完才结束，因此实际调用率小于每步 0.15。
- **模式**：从池中等概率取一段；一半概率原样参考，一半概率选择四个位置中的一个做局部变异。参考绑定稳定 Cell 身份，不能根据熵坍缩次序推进 motif。
- **选择顺序**：硬约束筛选 → 原有 density 决定是否休止 → 若发声，非变异位置的历史音仍合法就优先采用；变异位置从不同于原音的合法音高中按原有音区权重选择。历史音不合法时回落到普通合法选音；没有不同合法音时允许保留原音。
- **传播优先**：唯一候选被传播确定时直接接受，包括休止。记忆既不复活被删除的候选，也不强制消除休止。“原样”指引用意图，不保证在当前上下文逐音复刻。
- **资源与重播**：记忆池六段、收集缓存最多三音、最多一个活动引用；用独立种子 RNG，`createStream` 重建时清空。没有增加 HUD 参数。`options.motif=false` 或 `motifRecallProbability=0` 可供代码级对照，零引用保持原生成随机流。

首版曾将参考直接绑定最近四格，离线发现大量格子早已确定，完整四音返回仅 22 次；因此改成最近连续未定区域，避免引用只是名义触发。

```powershell
node exercises/04-wfc-loom/tools/offline-motif.mjs
```

30 种子 × 3000 步检查：原有硬约束、记忆来源与 FIFO 容量、同种子重播、零引用与关闭记忆一致、已定格不被改写、引用不重叠均通过。共发起 4382 次引用（原样 2204 / 单位置变异 2178），实际输出中 212 段完整四音与来源相同；参考位置命中原音 7692 次、变异位置输出不同音 1164 次、休止 8308 次。后两项包含当前位置的约束影响，不是完整变异片段成功数。

这些数据证明最小链路实际作用于输出，不代表听感验收。仍需试听判断熟悉感是否明显；休止和硬约束会使很多引用只保留部分材料。第一版没有移调、倒影、逆行、相似度检测、和弦适配或多轨共享。

## 钢琴采样（2026-09-22）

0.5 音源换成仓库已有的 `vsco2-piano-mf`，从 jsDelivr 的 samples-alex-bainter 镜像加载 A4、C#5、F5 三个采样，由 Sampler 覆盖 A4–G5。首次播放显示加载状态；单项网络加载超时 20 秒，失败显示错误并允许重试，不静默换回合成器。解码后的 AudioBuffer 在页面内缓存，换种子不重复下载。

采样增益沿用 04 0.3 的 +14 dB 标定；Release 1.5 秒，总增益 +6 dB、末级 Limiter(-1)。时值仍为一个八分音符，力度 90/127，所有生成规则不变。Release 是松键后的释放时间，不等于延长音符的节奏时值。

加载完成后才创建音频节点；停止或离开页面会使待建引擎代次失效，迟到完成的引擎销毁而不启动。停止使用 Sampler.releaseAll 收尾，换种子时销毁旧采样器。

静音浏览器检查：采样加载并实际调用 Sampler 播放，19 次 Draw 更新音画不匹配 0；停止后触发数 13→13，重播 13→18，控制台与未捕获异常均为 0。motif 的 30×3000 步离线统计与换音色前一致。本轮未实际试听响度与尾音。

### 第二轮：音头「敲桌子」（2026-09-22，改为带混响）

用户报「音头有明显敲桌子的声音」。做法是**先把能量量出来再动手**：`tools/browser-check.mjs` 现在会在真机上解码 A4.wav，打印起始采样、直流、音头包络与频谱（种子 12345）：

| 量 | 实测 | 读法 |
| --- | --- | --- |
| 采样 | 2 声道 · 48 kHz · 12.12 s | 峰值 **0.0939**（−20.5 dBFS） |
| 首采样 | `[0, 0, 0, 0]` | 起点就在零点 |
| 起始 5 ms | **−36.3 dB**（rel 最强窗口） | 采样开头是静音 ⇒ **不存在起点爆音** |
| 音头 40 ms 频谱 | 440:0 · 880:−17 · 1320:−22 · 600:−21 · 150:−21 · 200:−27 · 300:−31 | 能量在基频与前几个分音，低中频只有 −21 dB 的机械成分 |
| 直流 | 音头 0.0009 · 整段 −0.000006 | 没有直流偏移 |

由此**否掉了两个看起来很对的改法**（都写出来、都已回退，不留在代码里）：

1. **250 Hz 二阶高通「砍掉敲击闷响」**：150 Hz 本来就在基频之下 21 dB，整段只动 1.7 dB 能量，而低切对 A4 的基频也只压低 0.43 dB —— 既没解决问题，也没伤到音符，属于纯粹的多余机制。
2. **3 ms 音头淡入「消掉起点爆音」**：起点本来就在零点，前 5 ms 是 −36 dB 的静音，淡入无事可做。

★ 量法上的坑（下次别再踩）：`raw − HPF(raw)` **不是**「低频能量」—— 滤波器相位会让基频成规模地进入这个差值（这里算出 −1.7 dB，看着像"低频占了一大半"，实际 150 Hz 在 −21 dB）。要量某个频段有多少能量，用单频 DFT 或配对带通，别用互补差。

真正的差别在链路：02 / 0.2 / 0.3 用的都是这套采样 **+ Reverb**，而 `PIANO_VOLUME_DB = 14` 正是在 0.3 那条**带混响**的链路末端标定的 —— `Tone.Effect` 的干路会被 `×(1−wet)` 缩放，0.3 当年实测的钢琴峰值 **0.52** 与这里的算式吻合：

```text
0.0939 × 7.09（+14 dB 采样 · velocity 90/127 · +6 dB 母带）= 0.665
0.665 × 0.74（Reverb 干路 1−0.26）= 0.492      ← 0.3 实测 0.52
```

也就是说，**0.5 之前少的不只是房间，还比标定语境整体响约 2.6 dB**（峰值 0.665，Limiter 天花板 0.891）。近距干声 + 又短又密的格子，听到的主要就是每个音自己的起音 —— 这就是「敲桌子」。

现在链路是 `Sampler(+14 dB, release 1.5s) → Reverb(decay 3.6, wet 0.26) → masterGain(淡入 +6 dB) → Limiter(-1) → Destination`。混响参数取 0.3 的原值（同一套采样、已被试听接受过），`createEngine` 等 `reverb.generate()` 完成再建 Sampler（否则开头几拍是干的），`deactivate` 一并销毁；嫌糊可收到 `decay 2.2 / wet 0.15`。**采样本身没有改动**，也没有加低切、EQ 或压缩。

同一次真机运行（种子 12345）：19 次 Draw 更新、音画不匹配 0；停止后触发数 13→13、重播 13→18；控制台与未捕获异常 0；motif 的 30×3000 步离线统计与改音色前逐位一致。**本轮仍未实际试听**：上面证明的是链路、电平与生命周期，「现在还像不像敲桌子」只能由耳朵判。若仍觉得是敲击，下一批可选手段是：在采样域压掉音头 40 ms 里 150–600 Hz 的机械成分（比基频低 21–31 dB）、换一套钢琴采样（这份镜像只有 `vsco2-piano-mf` 一层力度）、或调整混响量与整体增益。

## HUD 布局（2026-09-22）

参照 03 的悬浮面板：左上标题与短介绍，右上公共播放/种子控件、状态及现有漂移读数，左下默认折叠的机制说明。Cell 居中置于全屏画面；窄屏控制面板限高可滚动，画面留在面板下方。点击画面隐藏/显示 HUD，F 切换全屏；通过 composedPath 排除种子输入框键盘事件。没有新增测试参数。此次只改布局与 HUD 交互，钢琴敲击声问题在上一节处理。静态语法与必需 DOM ID 检查通过。
