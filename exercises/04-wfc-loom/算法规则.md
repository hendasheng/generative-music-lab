# 04 · Note Tile Collapse —— 当前算法规则（0.3）

> **这份规格描述 `0.3/index.html`（当前入口）。`0.2/` 是上一版，差异全部集中在"时间"这一层**（其余条款都照下面执行）：
>
> | 项 | 0.2 | 0.3 |
> | --- | --- | --- |
> | 时值 | 每格一个基本时值（0.25 / 0.5 / 1 / 1.5 拍，由 `row/col` 派生）+ 级进 2.4 拍 + 终止列 4 拍 | **恒为 1 拍**（`NOTE_BEATS = 1`）—— 时值系统整套删除 |
> | 时值线 | 格底 5 拍标尺 + `.time-mark`（起点 = 延迟、长度 = 实际时长、逐帧生长） | **整套去掉**（CSS、DOM、`growing` / `growMark` / `freezeMarks` / `stopMarks` 全删） |
> | 拍内延迟 | 0 或 0.5 拍（由 `(row*2+col*3) % 4` 派生） | **恒为 0** —— 音头就在拍点上 |
> | 步长 | `max(1, ceil((延迟 + 时长) × 0.6))` 拍，只能是 1 / 2 / 3 拍；还要被句尾留白钳制 | **恒为 1 拍** —— 第 k 次坍缩正好在第 k 拍（是"第几步"，不是"哪一格"） |
> | 整曲 | 79–92 拍（随种子变） | **恒为 64 拍** = 16 小节 = 4 句（120 BPM 约 32 秒） |
> | 连带 | 时长在运行期决定 → 时值线要按实际时长重画；状态栏显示"延迟 +X 拍 · 时值 X 拍" | 时值 / 延迟都是常量 → 这套显示与重画逻辑一并删除；`HARSH_INTERVALS`（协和兜底）与 `tieOver`（同音退场）在 0.3 里**恒不触发**（没有叠置），保留待时长加回来 |
> | 其余 | — | 与 0.2 逐字相同（候选 / 传播 / 和声 / 权重 / 留白 / 音色 / 母带链 / BPM） |

这份文档描述**现行**算法（截至 2026-09-20，0.3 第二步）。[README](README.md) 记各轮演进与当时的实测数字，这里只记**现在到底怎么算**：每一处规则都能在 [`0.3/index.html`](0.3/index.html) 里按同名常量或函数搜到。

> ⚠️ **`0.4/` 与 `0.5/` 是独立的实验，下面任何一条都不适用于它们**：0.4 按用户规格 [`0.4/实验说明.md`](0.4/实验说明.md) 从最小功能重建（一维 16 格时间序列、A 小调 7 个候选、只两条硬规则 `max interval` / `max repeat`、边坍缩边发声）；0.5 在 0.4 上加了 rolling window、register drift、density drift 三个机制。协议（**一次只加一条规则、加之前和加之后各量一次、每条规则都能单独关掉**）与实测数字见 [`0.4/README.md`](0.4/README.md) 与 [`0.5/README.md`](0.5/README.md)。**下面这份规格继续描述 0.3。**

## 1 一句话

一片 8×8 的候选格：每一步按**熵**挑一格 → 按**权重**给它定一个音高或休止 → 立刻发声、并沿上下左右**传播**消掉邻居里不兼容的候选；**每 1 拍走一步**，拍长由 BPM 决定。音高同时受三层约束：**时间轴上的和弦进行**（骨架）、**最近发过的音**（不粘连）、**仍在响的音**（不刺耳，0.3 里暂时不生效）。

## 2 数据模型

| 量 | 值 |
| --- | --- |
| 网格 | `GRID = 8` → `CELL_COUNT = 64`，index = `row * 8 + col`（DOM 顺序） |
| 候选 tile | `NOTES` 9 个：`rest` + F 小调 8 个音高 `F4 G4 Ab4 Bb4 C5 Db5 Eb5 F5`（一个八度内的音阶音） |
| tile 基础权重 | rest 1.2 / F4 1.35 / G4 0.92 / Ab4 1.1 / Bb4 0.88 / C5 1.3 / Db5 0.72 / Eb5 0.95 / F5 1.0 |
| 每格自带的时间 | **无** —— 0.3 里 cell 上不再有任何时间量（时长是全局常量 `NOTE_BEATS`，音头就在拍点） |
| 运行时状态 | `cell.candidates`（候选集合）、`cell.value`（坍缩结果）、`noteState`（见 §9） |
| 界面 | 未坍缩：9 个小方块 = 候选集合；坍缩：整格被该 tile 填满 + 音名；**格底没有标尺** |

> ★ **0.3 删掉了 0.2 的 `cellTime(index)`**：0.2 用它由格子自己的 row/col 派生 `offset`（拍内延迟）+ `dur`（基本时值），型表如下（**只在 0.2 里存在**）：
>
> | 型 | `offset`（秒） | `dur`（秒） | 换成拍（120 BPM） |
> | --- | --- | --- | --- |
> | 型 0「正拍·1 拍」 | 0 | 0.5 | 延迟 0 · 时值 1 拍 |
> | 型 1「正拍·半拍」 | 0 | 0.25 | 延迟 0 · 时值 0.5 拍 |
> | 型 2「正拍·半拍」 | 0 | 0.25 | 延迟 0 · 时值 0.5 拍（与型 1 等价，保留两格只是为了不动 pattern 公式） |
> | 型 3「推后·16 分」 | 0.25 | 0.125 | **延迟 0.5 拍** · 时值 0.25 拍 |
> | 型 4「正拍·1.5 拍」 | 0 | 0.75 | 延迟 0 · 时值 1.5 拍 |
>
> 这整套被删掉的理由，是它踩了本练习最反复的一条坑：**"tile 自带的属性"如果被拿来当音乐时间用，就必须只允许影响拍内**，而只要它进耳朵（音头落点、听觉间隔），**由 `row/col` 派生就等于在随机时刻撒** —— 坍缩顺序是熵顺序，与行/列无关。
>
> ★ **第十二轮（0.2）：拍内延迟只剩两档（0 与 0.5 拍）**。原来是四档 0 / 0.125 / 0.25 / 0.375 秒（= 0 / 0.25 / 0.5 / 0.75 拍），实测 **24% 的音头落在十六分位**、听觉上的起音间隔**只有 38% 是整拍**（其余是 1.25 / 1.5 / 1.75 / 2.5 拍这类半拍错位）、最小间隔 0.25 拍 —— 听感就是"很多音根本不在拍子上"。这是"拿空间坐标当音乐时间用"的**第四例**（前三例：重音不能来自 `col`、和声不挂 `row/col`、同音降权不能只看左邻格）。**0.3 直接把延迟归零，把这条例底抽掉。**
>
> 注意：听觉上的间隔不是步长本身，而是 `等待拍数 + (下一格的延迟 − 这一格的延迟)` —— 所以哪怕步长永远是整拍，延迟差也能把它压成 0.25 拍。

## 3 一步（tick）的完整顺序

每一步都在 `Tone.Transport` 的回调里同步跑完（`collapseLine` 的 `tick`）：

1. **挑格** —— `chooseCell(rng)`，按候选最少（+ 首尾偏置 + 抖动）选一格；没格子了就结算（返回 64 个值）。
2. **取和弦与位置** —— 和弦挂在**拍**上（`chordPlan[⌊stepBeat / 8⌋]`）、强拍 = `stepBeat % 4 === 0`、倾向解决目标（仅当上一个音是当时的非和弦音）。
3. **选值** —— `chooseValue(...)`：句尾留白硬规则 → 逐候选乘权重 → 按权重抽样（§6）。
4. **定音长** —— **恒为 `NOTE_BEATS = 1` 拍**（0.2 这里是 `noteDuration(...)`：终止列 4 拍 / 级进 2.4 拍 / 否则用这一格的基本时值）。
5. **同音退场** —— 若这个音高仍在响，记下 `tieOver`，让旧音在**新音起音处**退场（§9）。★ 0.3 里"仍在响"的列表恒为空，所以这一步不发生。
6. **传播** —— `propagate(cell.index)`：按横向 ≤7 半音 / 纵向 ≤5 半音清掉邻居的候选，BFS 直到稳定（§5）。
7. **力度** —— `stepVelocity(stepBeat)`（§8）。
8. **步长** —— **恒为 1 拍**（0.2 这里是 `max(1, ceil((延迟 + 实际时长) × 0.6))`，再被句尾留白窗口钳制）。
9. **排画面** —— `Tone.Draw.schedule(..., 音头时刻)`：填色、音名、候选消除、传播高亮。0.3 里音头 = 步时刻，所以画与声**同刻**。
10. **发声** —— `onCollapse` 里 `voice.trigger(...)`。（0.2 还要在这里让时值线从 `startAt` 起逐帧生长；0.3 没有时值线。）
11. **推进** —— `step += 1`、`stepBeat += 1`、`stepAt += 1 × secPerBeat`，然后 `Transport.scheduleOnce(tick, stepAt)` 排下一步。于是**第 k 次坍缩正好在第 k 拍**（`stepBeat ≡ step`）。★ 这是"第几步"等于"第几拍"，**不是"哪一格"** —— 哪一格坍缩仍由熵决定（§4），格子编号与时间无关。

## 4 挑格：按熵，不按位置

```js
score = cell.candidates.size + edgeBias + rng() * 0.06     // edgeBias: 首格/末格 −0.2
```

取 score 最小者（并列时随机挑一个）。所以**坍缩顺序是信息论顺序**：候选最少的格子先塌。

> ★ 这条决定了整个练习的性格，也决定了一条铁律：**声部顺序与网格的行/列顺序不是同一个序列**。凡是"音乐上的相邻"（重音、和声变换、同音重复）都必须挂**时钟**，不能挂 `row`/`col`（§13）。

## 5 传播：横向 ≤7 半音、纵向 ≤5 半音

- `compatible(left, right)`：横向相邻 —— 音程 ≤ 7 半音；任一侧是 `rest` 直接放行。
- `verticalCompatible(a, b)`：纵向相邻 —— 音程 ≤ 5 半音；任一侧是 `rest` 直接放行。
- `propagate(start)`：BFS，用**已坍缩格**的候选集合去筛未坍缩邻格；筛完为空则兜底成 `{rest}`（保证总有解）；候选数有变化就继续传播。返回被改动的格子（给画面做"传播"高亮）。
- `applyPhraseConstraints()`（每场开始时调一次）：首格只允许 `rest / F4 / C5 / F5`，末格只允许 `rest / F4 / Ab4 / C5 / F5`。

实测**每一步在选值之前**的候选数落在 **5–9** 个（初始 9 个），平均约 **7**：传播确实会收窄，但几乎不会只剩一两个（第十轮实测 13.4 次重复**全部**发生在候选 ≥3 时）。这就是选音空间的实际大小。

## 6 选值：完整权重表

`chooseValue(cell, rng, ringing, phraseRest, harmony, recent)`，**按顺序**相乘；最后按权重归一化抽样。

| # | 条件 | 乘数 | 属于 |
| --- | --- | --- | --- |
| 0 | `phraseRest && 候选含 rest` | **直接返回 `rest`**（硬规则，不走权重） | 时间 |
| 1 | 基础 | `tile.weight`（§2） | — |
| 2 | **左邻格**已坍缩且同 tile | ×0.48 | 空间语法 |
| 3 | **左邻格**是音：音程 ≤2 / ≤5 / 其它 | ×1.6 / ×1.05 / ×0.44 | 空间语法 |
| 4 | 右邻格已坍缩且 `compatible` 不成立 | ×0.05 | 空间语法 |
| 5 | 上邻格已坍缩且 `verticalCompatible` 不成立 | ×0.05 | 空间语法 |
| 6 | 下邻格同上 | ×0.05 | 空间语法 |
| 7 | `index === 0` 且 F4 | ×1.7 | 起句 |
| 8 | `index === 63` 且 F4 / F5 | ×1.8 | 收句 |
| 9 | `row < 2` 且 midi < 70 | ×0.72 | 音区 |
| 10 | `row > 5` 且 midi > 72 | ×0.72 | 音区 |
| 11 | 和声：强拍和弦音 / 强拍非和弦音 / 弱拍和弦音 / 弱拍非和弦音 | **×8 / ×0.4 / ×4 / ×1** | 时间（和声） |
| 12 | 和声：是倾向解决目标且在和弦音内 | ×2.5 | 时间（和声） |
| 13 | 与**仍在响**的音撞上小 2 度 / 三全音 / 大 7 度（`HARSH_INTERVALS = {1,6,11}`） | ×0.03 | 时间（协和）★ **0.3 里恒不触发**（时值 = 步长 = 1 拍 ⇒ 没有叠置） |
| 14 | **时间上的重复**：与最近第 1 / 2 / 3 个**发声**的音高相同 | ×0.2 / ×0.5 / ×0.75 | 时间（不粘连） |

三条要记住的读法：

- **第 2–6 条是 WFC 的 tile 语法，作用在"网格"上**：`previous = cellAt(row, col-1)` 是**左邻格**，不是上一个发声的音。实测它整首只命中 7.6 对 —— 对听感几乎无影响（第十轮）。**别把它当成旋律规则来调。**
- **第 11–14 条才是"你听到的音乐"**：和弦骨架、倾向解决、协和兜底、时间上不粘连。★ 0.3 里第 13 条不生效（没有叠置），第 14 条是唯一的"反重复"机制。
- 权重是**按候选求和**的：把某个候选压下去，会把它那一类的**整池**概率抬上来。所以降权重时要连类一起想（第十轮踩过：只压"相邻同音"太轻时重音骨架反而更稳，太重时会让位给整池经过音）。

**倾向解决**（第 12 条）只在"**上一个音是当时的非和弦音**"时才生效（是和弦音的倾向音不需要解决，硬要求会和骨架打架）：`Db→C`、`Eb→F`、`G→Ab`、`Bb→Ab/C`。

## 7 和声层：六个 F 小调三和弦，每 8 拍换一次

```js
Fm{5,8,0} → Db{1,5,8} / Ab{8,0,3} / Bbm{10,1,5} / Cm{0,3,7}
Db → Ab / Eb / Fm        Ab → Eb / Fm / Db        Eb → Fm / Ab / Db
Bbm → Db / Eb / Fm       Cm → Fm / Ab
```

- 进行用**种子派生的独立 rng** 走 `next` 图：`makeRng(seed ^ 0x9e3779b9)`，长度 `CHORD_SLOTS = 24`（24 × 8 拍 = 192 拍，够整曲不绕回）。**绝不能和 WFC 共用随机流**。
- 换和弦的周期挂在**拍**上：`chordPlan[⌊stepBeat / CHORD_BEATS⌋]`，`CHORD_BEATS = 8`。
- 强拍 = `stepBeat % BAR_BEATS === 0`（小节第 1 拍）锁和弦音（×8）；弱拍放开经过音（×4 : ×1）。

## 8 时间模型：全部在"拍"域

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `STEP_S` | 0.5 | 120 BPM 下一拍的秒数（全文件**唯一**的"拍 ↔ 秒"基准） |
| `timeScale()` | `120 / bpm` | 唯一的缩放因子（`bpm ∈ [40, 240]`，默认 120） |
| `NOTE_BEATS` | **1** | 每个音的时值，也是每一步的步长（0.3 新增；0.2 没有这个名字） |
| `BAR_BEATS` / `PHRASE_BEATS` / `PHRASE_REST_BEATS` | 4 / 16 / 2 | 小节 / 乐句 / 句尾留白（都以**拍**为单位） |
| `START_LEAD_S` | 0.25 | 第一次坍缩的提前量（传输时间轴上） |
| `BEAT_ACCENT` | `[0.22, 0, 0.10, 0]` | 小节内第 1/2/3/4 拍的重音加成 |
| `BREATH_DEPTH` | 0.14 | 一句（16 拍）内的呼吸弧幅度 |
| `PIECE_BEATS` | `CELL_COUNT`（= 64） | 只用于输入框提示 —— 0.3 里整曲长度是常量，不再随种子变 |

**坍缩步长**（0.3）：

```js
const waitBeats = NOTE_BEATS;   // 恒为 1 拍
```

- 0.2 的公式是 `waitBeats = max(1, ceil((延迟 + 实际时长) × WAIT_SCALE 0.6))`，只能是 1 / 2 / 3 拍，还要被 `toRest = PHRASE_BEATS − PHRASE_REST_BEATS − stepBeat % PHRASE_BEATS` 钳制，"长音不许跨过句尾留白"。
- ★ 0.3 里这条公式**恒等于 1**（时值恒 1 拍 ⇒ `max(1, ceil(0.6)) = 1`），而每个 1 拍的步都不可能跨过 2 拍的留白窗口，所以公式与钳制**双双失去意义**，一并删掉。删掉之后 `stepBeat ≡ step`，但结构判断仍然写成"拍"（`stepBeat % 16`），不写"第几个格子" —— 将来步长一变，两者就又不等价了（第九轮的教训）。
- **小节 / 乐句 / 和弦周期只数拍**，不能数"第几个格子"：0.2 里步长 1–3 拍不等，`step % n` 与"每 n 拍"是两件事；0.3 里两者恰好等价，但代码仍按拍写（`stepBeat`）。
- **`ceil` 不能去掉**（0.2 的教训，留在这里给将来恢复步长时用）：不取整会让步长出现 1.44 / 1.59 拍这类值，而 `stepBeat` 是累加的 —— 一个长音之后每一次坍缩都永久偏离拍点（实测 90% 的步偏离、中位 0.23 拍）。

**力度**：`min(0.8, 0.4 + BEAT_ACCENT[beat % 4] + sin(π · (beat % 16) / 16) × 0.14)` —— 小节第 1 拍最重、第 3 拍次之，再叠一层 4 小节的呼吸弧。

**句尾留白**：`beat % 16 >= 14` 的两拍强制 `rest`（若候选集里有 `rest`）。它是**"这两拍不再有新起音"**，而不是"把还在响的音掐掉"：横跨乐句末尾的长音按自己的时值走完、用自己的 release（钢琴 1.5s / 合成器 1.15s）自然衰减进留白。

> ★ 第十一轮改的就是这里：原先在留白处 `releaseNotes(plan.ringing)` 把所有还在响的音一起放掉（为了"让留白听得见"），代价是把**还在满音量持续**的长音按 1.5s 线性淡出掐断 —— 那些音本来还要再响最多 2 拍。实测（浏览器，同一颗种子）：修复前每个留白窗口有 1–4 个音被提前放掉（最多提前 **2 拍**），修复后 **0 个**。

**拍 → 秒只在两处换算**：排下一步（`stepAt += waitBeats × STEP_S × timeScale()`）与排声音/画面（`plan.startAt`、`plan.duration`）。音乐判断一律用拍。

### 8.1 BPM 到底改什么（0.3）

```js
const timeScale  = () => DEFAULT_BPM / bpm;   // 120 / BPM
const secPerBeat = STEP_S * timeScale();      // 0.5 × 120/BPM = 60/BPM 秒（每步现算，不进模型）
stepAt += waitBeats * secPerBeat;             // waitBeats 恒为 1 拍
```

- **每次坍缩的间隔 = 1 拍 = `60 / BPM` 秒**（与格子、种子、音高、休止都无关）。第 k 次坍缩的绝对时刻 = `START_LEAD_S + k × 60/BPM`。
- **整曲 = 64 次坍缩 = 64 拍 = `3840 / BPM` 秒**（`PIECE_BEATS = CELL_COUNT` 只用于输入框提示）。

| BPM | 两次坍缩的间隔（= 1 拍） | 整曲（64 拍） |
| --- | --- | --- |
| 40 | 1.500 s | 96 s |
| 60 | 1.000 s | 64 s |
| 90 | 0.667 s | 42.7 s |
| **120（默认）** | **0.500 s** | **32 s** |
| 180 | 0.333 s | 21.3 s |
| 240 | 0.250 s | 16 s |

**跟着 BPM 变的**：坍缩间隔、每个音的时值（时值也是 1 拍 ⇒ 音长 ≡ 间隔，永远是"一拍一个音"）、整曲长度。**不改的**：小节（4 拍）/ 乐句（16 拍）/ 和弦周期（8 拍）的**拍数**，以及同一颗种子的音符序列（40–240 BPM 下逐位相同，判断全在拍域）。

**不跟着 BPM 缩放的东西（都写死成秒）**，调 BPM 时要意识到它们会改变"干湿感"：

| 量 | 值 | 240 BPM 时等于 | 40 BPM 时等于 |
| --- | --- | --- | --- |
| 钢琴 `release` | 1.5 s | **6 拍**（整片糊在一起） | 1 拍（刚好分开） |
| 合成器 `release` | 1.15 s | 4.6 拍 | 0.77 拍 |
| 混响 `decay 3.6 / wet 0.26` | 3.6 s | 14.4 拍 | 2.4 拍 |
| `START_LEAD_S` | 0.25 s | 1 拍 | 0.17 拍 |

> 实测口径：一拍 1.5s（40 BPM）时音与音是分开的、听得见空隙；一拍 0.25s（240 BPM）时余韵跨 6 拍，颗粒被尾巴盖住。**约 90 BPM 以下"颗粒分明"、180 BPM 以上"洗成一片"** —— 这是 BPM 除了速度之外唯一的听感副作用。若要让快慢只改速度、不改干湿，下一步就是让 `release` / `decay` 跟着拍长走（现在没做，属于 §15 的候选杠杆）。

**播放中改 BPM**：`applyBpm()` 只改 `bpm` 变量，**不重启播放**；`secPerBeat` 每步现算，所以**从下一次坍缩开始按新速度走**，已经排进 Transport 的那一步保持旧间隔。`stepAt` 是**累加**的，所以中途改速度是"从这一刻起换速度"，不会把已播过的部分重新量化到新网格上 —— 想完整听一个速度就重新播放。

## 9 时值与演奏状态

**0.3：`durationBeats = value === 'rest' ? 0 : NOTE_BEATS`（= 1 拍）**。0.2 的 `noteDuration()` 三个分支（**只在 0.2 里存在**）：

```js
noteDuration(cell, midi, prevMidi) =
  cell.col === 7 ?                      4.0 拍（CADENCE_S = 2.0s）     // 终止列收句
  |midi − prevMidi| ≤ 2 ?               2.4 拍（LEGATO_S  = 1.2s）     // 级进/同音 → 连成线
  :                                     基本时值（0.25 – 1.5 拍）       // 跳进 → 断开
```

> ★ **时值恒 1 拍 ⇒ 坍缩步长也是 1 拍 ⇒ 每个音在下一步就被 `pruneRinging` 剔除 ⇒ 任何两个音都不叠置。** 这一条连带决定了三件事，改时值之前必须先想清楚：① 协和兜底（§6 第 13 条）恒不触发；② 同音退场（`tieOver`）恒不发生；③ 钢琴的 `release = 1.5s` 意味着每个音都在前一个音的余韵上起音 —— "有没有叠置"由**时值与步长**决定，`HARSH_INTERVALS` 与 `tieOver` 都只是兜底，不要把它们当成本版还在生效的规则。

`noteState`（每个引擎一份，跨场不残留）：

| 字段 | 用途 |
| --- | --- |
| `ringing[{name, midi, endsBeat}]` | 仍在响的音 → 协和约束（§6 第 13 条）、同音退场（§9 末段）。★ 0.3 里每步都被清空，所以恒为空 |
| `prevMidi` / `prevNonChord` | 0.2 里用于级进时长；0.3 里只剩倾向解决的触发条件（`prevNonChord`） |
| `recent[3]` | 最近 3 个**发声**的音高（midi）→ 时间重复降权（§6 第 14 条）；休止不入列 |
| `chordPlan[24]` | 这一场的和弦进行 |

**同音退场（`tieOver`，0.3 里不发生，逻辑保留）**：新音与仍在响的音同音高时，先把旧音在**新音的起音处** `triggerRelease`，并把它的 `endsBeat` 收到此刻。原因在 `Tone.Sampler` 的实现：`triggerRelease(note, t)` 会停掉该音高**全部**活动 source，后一个同音自己的释放点会把前一个还在响的长音一起停掉（实测该组衰减比对照组快 4 倍）。钢琴上这就是"重新按下同一个键"。

## 10 声部与音色

- **单声部**：每一步只坍缩一个 cell、发一个音。0.3 里时值 = 步长，所以**模型里完全没有叠置**（听感上钢琴 1.5s 的余韵会叠 3 拍）；0.2 靠长音叠置最多同时 2 个音。
- 演奏接口统一为 `trigger / releaseNotes / releaseAll / dispose`，引擎构建时按 `instrument` 选一套：

| 音色 | 实现 | 关键参数 |
| --- | --- | --- |
| 钢琴采样（默认） | 一个 `Tone.Sampler`（本身就是复音的，无 voice 池），4 个采样点 `F4 A4 C#5 F5`（vsco2-piano-mf，约 13MB，失败/超时 20s 自动回退合成器） | `volume +14 dB`、`release 1.5s` |
| 合成器 | 两个 `Tone.PolySynth(Tone.MonoSynth)` 池（midi ≤70 / >70），`maxPolyphony = 8`（**实例属性**，写在构造参数里不生效） | triangle + lowpass 1600Hz、`release 1.15s` |

母带链（跨练习约定）：`voice → Gain(1) → Reverb(decay 3.6, wet 0.26) → masterGain(淡入到 +6 dB) → Limiter(−1) → Destination`。

> 这条链上**原来还有一个 `Tone.FeedbackDelay`**（`delayTime` = 半拍、`feedback 0.12`、`wet 0.1`，0.2 首次提交就有），第十二轮之后删掉了：它给每个音在**正拍之间**加一份很轻的副本 —— 那正是"回响"，而且与"音头落在拍点上"直接冲突（拍间刚清干净，那一下回声成了拍间唯一的能量）。★ 教训：**拍点类改动要连效果链一起检查**；要加任何延迟，先想清它落在拍网格的哪一格上（原来那个 `delayTime` 还是建引擎时按当时的 bpm 算死的，播放中改 BPM 会漂到一整拍/八分之一拍）。

## 11 视觉：激活落在**发声时刻**

- **0.3**：没有拍内延迟，所以**这一个 cell 的全部激活画面**（填色、音名、候选消除、传播高亮）与发声**同刻**排在 `audioTime` 上。休止不发声，但它的坍缩画面照样画在它自己那一拍上。实测（浏览器整曲）：64 个 cell 的激活时刻相对自己那一拍的最大偏差 **0.0027 拍（约 1.4ms）**，与发声时刻的差恒为 **+10ms**（一个动画帧；`Tone.now()` 里还含 Tone 自己的 `lookAhead = 0.1s`）。
- **0.2**（历史）：那时要排在 `步时刻 + 拍内延迟`，否则"先亮后响"；时值线（格底 5 拍标尺）起点 = 拍内延迟、宽度 = 实际时长，音一响就从 0 逐帧长（`requestAnimationFrame` + 音频时钟 `Tone.getContext().currentTime`），被同音退场放掉的音把线冻结在截断处。
- ★ **0.3 把这一整套时值线连同它的运行期机制一起删掉了**（`growing` 队列 / 逐帧写 `--time-w` / `growMark` / `freezeMarks` / `stopMarks`）。教训：**删掉一个视觉量要连同它的运行期机制一起删干净**，否则会留下"每帧还在写一个没人用的 CSS 变量"这种暗债。做法是先把所有引用 grep 出来（`time-mark|time-lane|growing|growMark|--time-w|laneBeats|offsetBeats`）再逐个处理，比"看着删"可靠。
- **时值现在没有画出来**（用户明确要求先不加回时值线）。将来要用别的形式表示（tile 色深 / 候选区小竖线等），**不要把 `.time-mark` 加回来**。

## 12 生命周期

```
play  → Tone.start() → activateEngine(seed) → schedule() → Transport.start() → 淡入
stop  → 淡出 0.38s → end()（取消事件、取消 Draw、releaseAll、Transport.stop/cancel）
        → dispose 全部节点 → dropPendingVoiceCallbacks()
换一版 / 应用种子 → 淡出 → deactivate → （换一版时清空种子）→ play
```

- `schedule()` **必须幂等**：先 `eventIds.forEach(Transport.clear)` 再重置数组，否则重复 play 会留下一条 `end()` 清不掉的旧坍缩链（音符数翻倍）。
- **同一个引擎的第二次调度要把演奏状态清干净**：整曲结束后 `engine` **不销毁**（只 `Transport.stop/cancel`，这样重放不必重建引擎、也不必重载采样），所以「放完再按播放」会在同一个引擎上再调一次 `schedule()`。除了 `ringing` / `prevMidi` / `prevNonChord` / `chordPlan`，**`recent`（时间上的重复降权）也必须清** —— 漏掉它时新一轮开头 1–3 个音会带着上一轮末尾那 3 个音高的降权（×0.2 / 0.5 / 0.75）。用离线桩 [`tools/offline.mjs`](tools/offline.mjs) 实测 30 颗种子：修前 **12 颗**的第 2 场与「全新引擎」不同（分歧都出现在第 1–3 个音），修后 **30/30 逐位相同**（上一版 0.2 是同一个漏清，修前 11/30，同一天一起修了）。★ 通用规矩：重置状态时，凡是"跨场会残留"的派生量都要一起清。
- `deactivate()` 末尾清 `Tone.getContext()._timeouts._timeline`（私有 API，与 `_ticker` 同类，升级 Tone.js 要复查）：Tone 对超过 lookAhead 的音用 `context.setTimeout` 排 release，而 `dispose()` 不取消这些回调，否则停止后控制台会刷 `Synth was already disposed`。
- **两套时间轴不能混用**：`scheduleOnce(fn, time)` 的 `time` 是**传输时间**，回调收到的 `time` 是**音频上下文时间**。下一步永远用自己维护的 `stepAt` 排，回调的 `audioTime` 只用于排声音与 `Tone.Draw`。

## 13 复现与"演出参数"

- 种子：输入框里的文本经 `hashSeed`（djb2）变成 32 位种子；不填则随机。**"输入框填 2024" ≠ "数字 2024"**，两者是两首不同的曲子。
- 同一颗种子 + 同一音色 + 同一 BPM = 逐位相同的音符、时值、顺序。**包括「放完再按播放」这条路径** —— 那个引擎不重建（只 `Transport.stop/cancel`），所以 `schedule()` 必须把跨场状态清干净（见 §12 的 `recent`）。
- **音色与 BPM 是演出参数**：只换音色或改 BPM 不改任何音符（`lastSeed` / `pendingSeed` 保住同一首，方便 A/B）。BPM 只缩放绝对速度，模型在拍域，所以 40–240 BPM 下**拍域序列 md5 完全相同**。
- 不要用 `Tone.Transport.bpm` 代替 `timeScale()`：本练习按绝对秒数排事件，改 Transport 的 BPM 会让已经排好的事件被重新解释。

## 14 现行实测指标

**0.3**（离线 16 种子 × 64 步 = 1024 步 + 真实浏览器整曲 1 颗种子）：

| 项 | 实测 |
| --- | --- |
| 坍缩步长 | **恒为 1 拍**（1024/1024）；步时刻偏离拍点 **0** |
| 音头 | 全部落在**正拍点**（残差 0.000000）；因为 0.3 没有拍内延迟，音头 = 步时刻 |
| 时值 | **恒为 0.5s = 1 拍**（808 个音全部；休止 216 步） |
| 画面的激活时刻 | 与**自己那一拍**的最大偏差 **0.0027 拍（≈1.4ms）**；与发声时刻差恒为 **+10ms**（一个动画帧；`Tone.now()` 含 `lookAhead 0.1s`） |
| 叠置 | **0**（每个音都在下一步之前结束 ⇒ 模型里没有同时发声的两个音） |
| 句尾留白 | 留白拍（`beat % 16 ≥ 14`）上的音符 **0** |
| 音高 | 8 个音高全部用到；调外音 **0**（全在 F 自然小调内） |
| 和弦周期 | 每 8 拍换一次，逐拍对齐（如种子 12345：Fm×8 Bbm×8 Eb×8 Ab×8 Fm×8 Cm×8 Fm×8 Bbm×8） |
| 力度 | 落在 **0.40–0.80**（小节第 1 拍最重） |
| 整曲长度 | **恒为 64 拍 = 16 小节 = 4 句**（120 BPM 约 32 秒；与种子无关） |
| DOM | `.time-lane` / `.time-mark` **0 / 0**（播放中也是 0） |
| 重放复现 | 同一个引擎跑第二场 vs 全新引擎：**30/30 颗种子逐位相同**（修 `schedule()` 漏清 `recent` 之前是 18/30）；离线桩 [`tools/offline.mjs`](tools/offline.mjs) |
| 稳定性 | 页面 error / unhandledrejection **0**、未捕获异常 **0**；控制台只有 Tone.js 自己的一条 `ScriptProcessorNode` 弃用警告 |

**0.2**（上一版，留作对照）：坍缩步长只有 {1,2,3} 拍、偏离拍点 0；音头 **87%** 在正拍点 / 13% 推后半拍；听觉起音间隔 **75%** 是整拍（最小 0.5 拍）；重音与小节逐一对上（18/18、19/19、17/17、18/18）；力度 ≈ 0.69 / 0.53；同时最多 **2** 个音、平均时值 **1.74–2.04 拍**；和弦音：强拍 **94.3%** / 全体 **76.5%**；相邻同音 **7.5%**、2 音内重复 24.7%；整曲 **79–92 拍**（均 86，120 BPM 约 40–46 秒）。

## 15 已知边界（下一个杠杆）

1. **"哪一格坍缩"仍由熵决定**：坍缩踩在拍上了，但**落点没有音乐理由**。要让横向真的成为时间轴（按时间前沿选格、边坍缩边读谱），会动到选格逻辑本身。
2. **时值被压成常量之后，"呼吸"没有了**：0.3 的 64 拍是等距脉冲。要恢复长短只有两条路 —— 把 `NOTE_BEATS` 变成"按乐理决定"的常量表（例如和弦变换处给 2 拍），或者恢复 0.2 的 `max(1, ceil(时值 × 0.6))` 步长公式（那时记得连协和兜底与同音退场一起恢复，它们本来就是为叠置写的）。
3. **时值现在没有画出来**（用户明确要求先不加回时值线）：候选形式是 tile 色深 / 候选区小竖线；**不要把 `.time-mark` 加回来**。
4. **`release` / 混响没有跟着 BPM 缩放**（§8.1）：极慢时音符太干、极快时又糊成一片。要让"快慢只改速度、不改干湿"，就把 `PIANO_RELEASE_S`、`SYNTH_RELEASE_S`、混响 `decay` 改成按拍长算（例如"release = 2 拍"）；那会同时改掉留白的手感（见 §8 的留白口径），改之前先想清楚。
5. **不是多声部**：每一步只发一个音；"低音 + 旋律 + 伴奏"那种分声部的做法（每步同时坍缩 2–3 个音区）留给后续版本。
6. **音域只有一个八度**（F4–F5；02 是 C3–C6、03 是 A2–F6）。补它要么扩钢琴采样集（每个 wav ≈ 3MB）、要么按行移八度，两者都会动到加载体积或视觉，需要先确认。
7. **音高集中度**：前 3 个音高（当前和弦的三个音）约占 **60%**，因为和弦音权重 ×8 / ×4、而候选只有一个八度的 8 个音。要更散就得改和弦权重档位，或扩音域（同第 6 条）。
8. **候选集合被传播收窄到 5–9 个**：不是所有权重在所有时候都有效 —— 调试权重时要分清"权重写错了"还是"候选早被收窄了"（单元级 vs 全曲两个层次都要量）。
