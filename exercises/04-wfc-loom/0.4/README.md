# 04 · Note Tile Collapse 0.4 —— 最小 WFC（只生成 Pitch Sequence）

**入口：[`index.html`](index.html)｜规格原文：[`实验说明.md`](实验说明.md)**（用户给的说明，逐字保存，未改动）。

0.4 **不继承** 0.1–0.3 的任何规则。它只验证一件事（规格 §10）：

> 候选集合被相邻结果不断削减之后，生成结果是否比纯随机**更具有局部连续性**，同时仍然保留变化。

原因是前面几版"很难单独验证其中的规则"：0.3 光 `chooseValue` 就一次乘 15 条权重、时间层四处耦合、文件 1000 行，任何一次改动都说不清是谁造成的。所以 0.4 从最小功能开始，并且**一次只加一条规则、加之前和加之后各量一次**。

## 这一版是什么

- **Cell = 时间轴上的一个位置**（一维 16 格 = 2 小节），不是 0.2/0.3 的二维网格。所以"相邻"同时是空间相邻与时间相邻，不存在「空间坐标被当成音乐时间用」那个坑。
- **调与音阶是一等概念**：候选音**只**由 `KEY_ROOT` / `KEY_MODE` / `OCTAVE` + 音阶结构（`minor = 0 2 3 5 7 8 10`）派生（现在是 A minor 的 `A4 B4 C5 D5 E5 F5 G5`，midi 69/71/72/74/76/77/79）。所以**"调外音"在结构上不可能出现**，换调 / 换调式只动三个常量；探针把它当不变量断言（实测 0/480）。
- **两条规则**：
  - **max interval = 5 半音**：相邻音的音程 ≤ 5（规格 §5：`Cell4 = E` 之后，`Cell5` 里 A 因为 7 个半音被排除）。
  - **max repeat = 2**：同一个音最多连续 2 次（规格 §6：`C→C→C` 禁止，`C→C→D` 允许）。
- **坍缩顺序 = 熵顺序**：第一版把"候选数量"当熵，每次挑**候选最少且大于 1**的格子，从它的候选里等概率选一个音；并列时（开局 16 格都是 7 个候选）用种子随机挑起点。**只剩一个候选的格子不算一次坍缩** —— 它已经被约束推出来了：当场确定，并立刻继续向外约束邻居。
- **边坍缩边发声**（用户明确要求）：`createModel(...).stepOnce()` 每走一步就是"坍缩一格 + 传播"，页面在**每一个八分音符**调一次，**这一步确定下来的音就在这一拍响**。所以：
  - **第 1 圈 = 生成过程**：听到的顺序是**熵顺序**（与时间顺序无关），同时看到候选被一格格划掉、有些格子被"推"成唯一解；16 步（默认参数下正好 16 次主动坍缩）走完。
  - **第 2 圈起 = 成品旋律**：按**时间顺序**循环演奏，正在发声的格子高亮。
  - 状态栏在两个阶段分别显示进度（坍缩第 k/16 步、Cell 号、传播改动几格）与体检数字（最大音程 / 最长连击 / 主动坍缩次数 / 传播推出格数 / 削减处数 / 放宽次数）+ 坍缩顺序。
- **固定参数**（规格 §7）：BPM 112 · 每格一个八分音符（0.268s）· Velocity 90/127 · 只有音高，没有时值、力度、和声、音色、段落。

## 规格没写、由我决定的几件事（要改先看这里）

| 决定 | 取法 | 理由 / 另一条路 |
| --- | --- | --- |
| 坍缩顺序 | **候选最少且 > 1** 的先塌（熵），并列随机；单候选格直接确定并继续传播 | 规格写明"候选数量最少且大于 1"。熵顺序是 WFC 的定义性做法，也正好让"传播"先于"演奏"发生。另一条路是**左到右**顺序坍缩（更接近马尔可夫链，没有"传播"可言）—— 改 `chooseCell` 一处即可 |
| 坍缩完之后的去向 | **转入成品旋律、按时间顺序循环** | 这样两种听法都能得到：第 1 圈听生成过程（熵顺序），之后听成品（时间顺序）。另一条路是坍缩完就停，或直接开始下一次坍缩 —— 改 `tick` 里的 `phase` 分支即可 |
| 停止 | **暂停语义**：保留引擎与种子，再按播放会从坍缩起点重放同一首；只有"换一版 / 应用种子"才重新生成 | 反复听同一首才能判断；0.3 是停止即销毁引擎 |
| 音色 | 一个 `Tone.Synth`（triangle + 短包络）+ 母带链只留 `Limiter(-1)` | 规格把音色排除在外，所以故意只留最小；**没有加混响/延迟**（没人要求的效果器不加） |

## 一条规则一验：探针与实测

两条规则都是**可单独关掉**的常量（关 = `Infinity`）：`MAX_INTERVAL = 5` / `MAX_REPEAT = 2`，并且 `createModel(seed, { maxInterval, maxRepeat })` 接受覆盖 —— 探针就用这两个参数做"只关一条"的对照，而且**逐步驱动 `stepOnce()`**，与页面跑的是同一条代码路径。

```powershell
node exercises/04-wfc-loom/tools/offline-minimal.mjs --seeds 30
```

实测（30 颗种子 × 16 格，离线、不开浏览器）。**主动坍缩** = 真按熵顺序做过选择的次数；**传播推出** = 被约束削到只剩一个候选而直接确定的格数：

| 配置 | 最大相邻音程 | 超过 5 半音的相邻对 | 最长同音连击 | 3 连击段 | 主动坍缩（均） | 传播推出（均） | 削减（均） | 放宽 | 调外音 | 长度异常 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ① 默认（5 / 2） | **5** | **0** | **2** | **0** | 16.0 | 0.0 | 25.5 | **0** | **0/480** | 0 |
| ② 只关规则①（∞ / 2） | 10 | **121**（占 27%） | 2 | 0 | 16.0 | 0.0 | 2.1 | 0 | 0/480 | 0 |
| ③ 只关规则②（5 / ∞） | 5 | 0 | **3** | **5** | 16.0 | 0.0 | 23.1 | 0 | 0/480 | 0 |
| ④ 机制检查（2 / 2） | 2 | 0 | 2 | 0 | 15.2 | **0.8** | 66.7 | 0 | 0/480 | 0 |

- **规则①确实在管音程**：关掉后最大音程 5 → 10，超限相邻对 0 → 121。
- **规则②确实在管重复**：关掉后最长连击 2 → 3，出现 5 段 3 连击。
- **削减量几乎全来自规则①**：只有它时平均削 2.1 处，两条都在时 25.5 处（规则②只在连击处动手）。
- **默认参数下"传播推出"是 0**：max interval = 5 时，削减只把格子从 7 个候选压到 5–6 个，**从来不会压到只剩 1 个** —— 所以这一版里 16 格全部要主动坍缩。
- **④ 是机制检查行**（不是音乐方案）：把音程收紧到 2 半音，传播才会真的把格子削到唯一解，于是走到"推出 → 直接确定 → 继续向外约束"这条分支（15.2 + 0.8 = 16）。★ 这条分支不能省：若把单候选格晾着不传播，`max repeat` 会漏判（A 格 = C、B 格被推成 C 却不继续约束，后面那格还能选 C ⇒ 三个连续同音）；默认参数下它一次都不触发，所以专门留了这一行压它。
- **放宽 0 次**：两条规则从没把某一格的候选清空过。`settle` 里有兜底（清空就跳过这次削减并记一次"放宽"），计数会显示在状态栏 —— 不静默塞一个音进去。
- 同一颗种子生成两次 **30/30 逐位相同**。

★ **不做"WFC vs 纯随机"的听感 A/B**（用户明确说不需要，纯随机的问题他能想象）。要数字参照，把两条规则同时关掉跑探针即可；页面上不提供这个版本。

## 真机检查（**一轮只开一次**，2026-09-21）

按根 `AGENTS.md` 的「验证口径」，只有"声音真的响了没有 / 生命周期 / 报错"这一类才需要开浏览器。批量探针把要查的全写在一起：

```powershell
python -m http.server 8765
node exercises/04-wfc-loom/tools/browser-check.mjs --url http://127.0.0.1:8765/exercises/04-wfc-loom/0.4/
```

实测（种子文本 `12345`，headless Chrome + `--autoplay-policy=no-user-gesture-required --mute-audio`）：

| 检查 | 结果 |
| --- | --- |
| **第 1 圈边坍缩边发声** | 2.4 秒处：已发声 **8** 个音，界面同时有 **8 / 16** 格被确定（状态栏："坍缩中 · 第 8 / 16 步 · Cell 15 = G5 · 传播改动 2 格"）—— 声音与坍缩同步推进，不是先解完再播 |
| 第 1 圈 vs 成品 | 第 1 圈的 16 个音 `G E E B B D D G D F E F F A C D` 与成品 `C A D D B B E G E D F E F D G F` **是同一批音的排列**（差的就是"熵顺序"与"时间顺序"） |
| 发声间隔 | **0.2679s**（= 112 BPM 的八分音符），逐拍精确 |
| 第 2 圈起 | 状态栏转为「成品循环（时间顺序）」；DOM 16 格全部 `.done`，播放中正好 1 格 `.hit` |
| 停止（过 380ms 淡出再等 900ms） | 计数**冻结**（20 → 20） |
| 停止后再按播放 | **重新出声**（20 → 28）—— 暂停语义成立，且从坍缩起点重放同一首 |
| 报错 | 控制台 error **0**、未捕获异常 **0**、页面 error 监听 **0** |

★ **这一轮真机检查抓到两个离线全绿、只有真机才暴露的问题**（都留下了）：

1. **`Tone.Synth`（单音）没有 `releaseAll`** —— 那是 `PolySynth` / `Sampler` 的接口。停止时先调它 → 抛错 → 后面的 `Transport.stop()` / `cancel()` 全被跳过，表现就是**按了停止还在响**（实测 11 → 13 还在涨）。两处修法：`end()` 改成**先停传输再收声音**（顺序本身就能防这类连带），单音用 `triggerRelease`。
2. **`Tone.Transport.bpm` 是只读 getter**：严格模式下 `= 112` 直接抛 `Cannot assign to read only property 'bpm'`，必须写 `.value`。顺带量到一个细节：不设它时 `scheduleRepeat` 按默认 120 BPM 的 tick 网格把 0.2679s 量化成 **0.2682s**（每步差 0.3ms）；设成 112 之后八分音符正好 96 tick，实测间隔精确到 0.2679。

## 已知边界 / 下一步

- **只有 pitch**：时值、力度、和声、音色、段落一律没有（规格 §12 明确不做）。
- **候选里等概率**：这一版**没有任何权重** —— "哪个 Cell 先塌"和"候选里挑哪个"都是均匀随机。所以如果听感平淡，第一个该试的是"选音偏好"，而不是急着加新规则。
- **音域只有一个八度**（A4–G5），边界音（A4 / G5）在 max interval = 5 下天然更容易被排除。
- 规格 §11 的下一条规则是 **Return / 回归**（乐句末提高回到主音 / 属音的概率）。加它之前，先按"一条规则一验"量一遍基线。
- `0.1`–`0.3` 原样保留作对照；现行算法规格 [`../算法规则.md`](../算法规则.md) 描述的是 **0.3**，不适用于 0.4。
