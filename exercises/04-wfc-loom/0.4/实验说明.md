# 最小版 WFC 生成式音乐实验说明

## 目标

这一版不追求“生成一首完整的音乐”，只验证一个最底层的问题：

> **把 WFC 的“候选集合 + 坍缩 + 约束传播”机制放到音乐时间序列里，是否能产生比普通随机更有连续性的结果。**

因此第一版只生成 **Pitch Sequence**，不处理和弦、节奏变化、力度、音色、段落结构等内容。

## 1. Cell 是什么

这里的 `Cell` 可以直接理解成：

> **时间轴上的一个位置。**

例如做 8 个 Cell：

```text
时间 →
[ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ][ 7 ][ 8 ]
```

如果每个 Cell 对应一个八分音符，那么这 8 个 Cell 就组成一段 8 个八分音符长度的旋律。

第一版里，每个 Cell 只负责一件事：

> **这个时间位置允许出现哪些音。**

## 2. Cell 里到底有什么

假设使用 A minor：

```text
A B C D E F G
```

那么在系统刚开始时，每个 Cell 都拥有完整候选集合：

```text
Cell 1 = {A,B,C,D,E,F,G}
Cell 2 = {A,B,C,D,E,F,G}
Cell 3 = {A,B,C,D,E,F,G}
Cell 4 = {A,B,C,D,E,F,G}
Cell 5 = {A,B,C,D,E,F,G}
Cell 6 = {A,B,C,D,E,F,G}
Cell 7 = {A,B,C,D,E,F,G}
Cell 8 = {A,B,C,D,E,F,G}
```

也就是：

```text
[ ? ][ ? ][ ? ][ ? ][ ? ][ ? ][ ? ][ ? ]
```

每个 `?` 并不是完全未知，而是：

```text
? = {A,B,C,D,E,F,G}
```

## 3. Collapse 是什么

`Collapse` 就是：

> 从当前 Cell 的候选集合中，最终确定一个音。

例如：

```text
Cell 4
{A,B,C,D,E,F,G}
```

坍缩为：

```text
Cell 4 = E
```

于是：

```text
[ ? ][ ? ][ ? ][ E ][ ? ][ ? ][ ? ][ ? ]
```

这个 Cell 从“多个可能状态”变成了“一个确定状态”。

## 4. Propagation 是什么

一个 Cell 确定之后，它会影响和它有关的其他 Cell。

例如：

```text
Cell 4 = E
```

这时候 Cell 3 和 Cell 5 不能再完全自由选择。

它们需要根据音乐规则重新计算自己的候选集合。

也就是：

```text
Collapse
= 我决定自己是谁

Propagation
= 我决定以后，把这个信息传给周围 Cell
```

WFC 的关键不在于“随机选了 E”，而在于：

> **E 出现以后，其他位置有哪些可能性因此被排除了。**

## 5. 第一条规则：max interval

`max interval` 用来限制相邻音之间的最大音程。

例如：

```text
max interval = 5 semitones
```

假设：

```text
Cell 4 = E
```

Cell 5 原本是：

```text
{A,B,C,D,E,F,G}
```

计算这些音与 E 的距离：

```text
A = 7 semitones
B = 5
C = 4
D = 2
E = 0
F = 1
G = 3
```

因为：

```text
A > 5
```

所以 A 被排除。

Cell 5 变成：

```text
{B,C,D,E,F,G}
```

也就是：

```text
Cell 4 = E
        ↓
Cell 5
{A,B,C,D,E,F,G}
        ↓
{B,C,D,E,F,G}
```

Cell 3 同样会受到影响。

这条规则解决的是最基本的：

> **不要让旋律连续出现过多毫无关系的大跳。**

## 6. 第二条规则：max repeat

`max repeat` 用来限制同一个音连续出现的次数。

例如：

```text
max repeat = 2
```

如果已经出现：

```text
Cell 3 = C
Cell 4 = C
```

那么 Cell 5 就不能继续选择 C。

原本：

```text
Cell 5
{A,B,C,D,E,F,G}
```

传播之后：

```text
{A,B,D,E,F,G}
```

于是：

```text
C → C → C
```

这种连续三次重复会被禁止。

但：

```text
C → C → D
```

仍然允许。

这条规则不是为了完全消除重复，而是为了：

> **允许短暂重复，但避免机械地卡在同一个音上。**

## 7. 第一版固定参数

为了降低验证成本，除了 Pitch 之外全部固定。

例如：

```text
BPM = 112
Scale = A minor
Cells = 8 或 16
Cell Duration = 1/8 note
Octave = 4
Velocity = 90
```

也就是说第一版不处理：

```text
duration
velocity
rhythm variation
chord
bass
texture
section
instrument change
```

只生成：

```text
Pitch Sequence
```

例如最终结果：

```text
A → C → D → E → D → C → B → A
```

## 8. 最小数据结构

实现时，一个 Cell 可以简单到只包含：

```js
{
  possibleNotes: ["A", "B", "C", "D", "E", "F", "G"]
}
```

整个序列：

```js
[
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"],
  ["A","B","C","D","E","F","G"]
]
```

随着约束传播，某些 Cell 会变成：

```js
["C", "D", "E"]
```

最后：

```js
["D"]
```

当候选集合只剩一个音时，这个 Cell 就已经完全确定。

## 9. 一个完整例子

初始：

```text
1          2          3          4
{ABCDEFG} {ABCDEFG} {ABCDEFG} {ABCDEFG}
```

假设 Cell 2 坍缩：

```text
Cell 2 = E
```

变成：

```text
1          2     3          4
{ABCDEFG} {E}   {ABCDEFG} {ABCDEFG}
```

应用：

```text
max interval = 5
```

于是 Cell 1 和 Cell 3 删除 A：

```text
1         2     3         4
{BCDEFG} {E}   {BCDEFG} {ABCDEFG}
```

之后假设 Cell 3 坍缩成：

```text
C
```

现在：

```text
E → C
```

如果后面又出现：

```text
Cell 4 = C
```

并且：

```text
max repeat = 2
```

那么 Cell 5 的候选集合中必须删除 C。

约束就是这样不断传播。

## 10. 第一版真正要验证什么

不是验证：

> WFC 能不能自动写出好听的旋律。

而是验证：

> **候选集合被相邻结果不断削减之后，生成结果是否比纯随机更具有局部连续性，同时仍然保留变化。**

因此第一版最好直接做 A/B 对比。

### Version A：纯随机

```text
从 A minor 中直接随机选音
```

### Version B：WFC-style

```text
A minor
+
max interval
+
max repeat
+
constraint propagation
```

然后只比较：

```text
纯随机
vs
受约束传播
```

如果听感没有明显改善，就没有必要继续增加系统复杂度。

## 11. 下一步

如果这一版有效，再加入第三条规则：

```text
Return / 回归
```

例如：

```text
每 8 个 Cell
提高 A / E / C 的权重
```

或者：

```text
每个乐句末
提高回到 tonal center 的概率
```

这样可以进一步测试：

```text
局部连续性
+
重复控制
+
结构回归
```

但第一版不需要加入。

## 12. 这一版暂时不要做的东西

暂时不要加入：

```text
稳定 / 发展 / 高潮 / 回归
Chord Track
Bass Track
Rhythm WFC
Motif Detection
Tension / Release
Velocity Generation
Multi-octave
Visual Mapping
```

这些都会显著提高验证成本。

现在最重要的是先确认：

> **WFC 的约束传播机制本身，在音乐序列里是否值得继续研究。**

## 13. 一句话总结

第一版可以理解成：

```text
每个 Cell 一开始都有 7 个候选音
        ↓
某个 Cell 坍缩
        ↓
max interval / max repeat
删除周围 Cell 中不合适的音
        ↓
继续坍缩
        ↓
最终得到一条完整旋律
```

也就是：

> **不是每一步直接随机生成一个音，而是让每个时间位置保留多个可能，然后通过音乐规则逐渐排除不可能的结果。**
