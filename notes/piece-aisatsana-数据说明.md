# piece-aisatsana 素材数据说明（instructions.json）

> 对应源码：`packages/piece-aisatsana/src/instructions.json`
> 本地克隆可看全量数据：`generative-pieces/packages/piece-aisatsana/src/instructions.json`

## 为什么代码里看不到素材

`piece.js` 只有一行 `import instructions from './instructions.json'`——
**音符数据在独立的 JSON 文件里**，由 MIDI 导出生成。这是"记忆 + 重排"里"记忆"的来源。

## 数据结构

```json
{
  "tracks": [
    { "id": 0, "name": "Aphex Twin - aisatsana", "notes": {} },
    { "id": 1, "notes": [ { "name": "E3", "time": 0 }, { "name": "G3", "time": 0.588 }, ... ] }
  ]
}
```

- `tracks[1].notes`：音符数组，每项 `{ name: 音名, time: 秒 }`
- 用到的正是 `tracks[1].notes`（源码第 20 行）

## 素材示例（前 20 个音符，完整数据见本地克隆）

```json
E3 @ 0          G3 @ 0.588      C3 @ 1.176      C4 @ 1.765
E3 @ 9.412      G3 @ 10.000     C3 @ 10.588     C4 @ 11.176
B3 @ 11.765     E4 @ 14.118     E3 @ 18.824     G3 @ 19.412
C3 @ 20.000     C4 @ 20.588     B3 @ 21.176     E3 @ 28.235
G3 @ 28.824     C3 @ 29.412     C4 @ 30.000     B3 @ 30.588
```

**观察**：
- 音高集合集中在 **C 大调**（C D E G B——含大七度 B，C 大调/Am 色彩）
- 结构是**琶音分解四音组**：`E-G-C-C`（及其变体，如结尾的 `E-G-C-C-B`）反复出现
- **组内间隔固定 2 格**（0.588s ≈ 2 × 0.294s），**组间有大休止**（约 9.4s = 32 格）
- 注意：`time` 值都能被 0.294（网格宽）整除——**原曲音符恰好落在八分网格上**（MIDI 导出已按八分音符对齐），所以量化几乎不改变时值，主要做"分组 + 切乐句"

## 量化过程演示（源码第 23–31 行）

网格宽 = 60 / (2 × 102 BPM) ≈ **0.294 秒/格**。把音符按格子分组：

```
格子 0（0~0.294s）: E3
格子 1（0.294~0.588s）: （空）
格子 2（0.588~0.882s）: G3
格子 3（0.882~1.176s）: （空）
格子 4（1.176~1.470s）: C3
格子 5（1.470~1.764s）: （空）
格子 6（1.764~2.058s）: C4
...
```

量化后每格是一个"音符集合字符串"：`["E3", "", "G3", "", "C3", "", "C4", ...]`
——多个音同格就 join：`"E3,G3"`。

## 乐句切分（源码第 33–45 行）

每 32 格 = 一个乐句（≈ 9.4 秒）。301 秒素材 ≈ **32 个乐句**——
这就是马尔可夫链的状态数（32 个"和弦/旋律块"各有性格差异：安静的、主题的、发展的、收束的），
也是原版"段落感"的素材基础（对比 02 练习手写的 10 个乐句 4 段）。
